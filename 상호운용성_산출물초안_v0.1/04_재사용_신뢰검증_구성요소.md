# D04 재사용 가능한 신뢰검증 구성요소 설계서

버전: v0.1 · 작성일: 2026-09-27 · 상태: 기관 협의용 초안

본 문서는 KR-AdES·KR-TL·KR-DSS 연구를 위한 설계 제안이다. 실제 기관의 참여·책임 수락, 제품의 구현 지원, 국제 적합성 인증을 의미하지 않는다. ‘한다’는 문구는 초안에서 제안하는 규칙이며 승인 전 운영 의무로 적용하지 않는다.

## 1. 목적과 설계 경계

공통 구성요소가 형식 처리, 암호 검증, 신뢰정보·권한·상태 평가, 결과 기록을 수행하고, 수신기관이 업무 수용정책을 소유하도록 설계한다. KR-AdES·KR-TL·KR-DSS의 모듈 이름은 적용 후보를 설명하는 것으로 실제 클래스·API 구현이나 지원 범위를 조사·확정한 결과가 아니다.

v0.1은 SVC-01·02·03, D03의 P-SIG·P-ATTR·P-EMP 및 현재 시점 평가를 대상으로 한다. 정책과 신뢰 앵커가 준비되지 않은 형식을 자동 수용하지 않는다. 국제 서비스의 인증·법적 상호인정, 과거 장기검증, 실제 지갑 발급 UI는 후속 범위다.

## 2. 구성요소와 계약

| ID | 구성요소 | 입력 → 출력 | 제안 배치 |
| --- | --- | --- | --- |
| C01 | 요청·접근 통제 | 호출자·서비스·증거 참조 → 검증 컨텍스트 | SDK/API 경계 |
| C02 | 형식·프로토콜 어댑터 | 증거 바이트·프로파일 → 정규화된 검증 대상 | KR-AdES 및 별도 VC 어댑터 |
| C03 | 암호 검증 | 서명된 원문·키·허용 알고리즘 → integrity | 공통 crypto/core |
| C04 | 신뢰정보 해석 | 서명키·서비스·시점·목록 → trust와 근거 | KR-TL client + 평가기 |
| C05 | 권한 평가 | 발급자·속성·업무·위임·시점 → authority | 별도 권한 정책 구성요소 |
| C06 | 상태·시간 평가 | 상태 증거·유효기간·시계 → status·freshness | 상태 어댑터 + 정책 평가기 |
| C07 | 보유자·거래 결합 | holder proof·nonce·audience → holderBinding | VC 제시 검증 구성요소 |
| C08 | 정책·결과 집계 | 필수 검사·서비스 수용 규칙 → 기술 결과·업무 결정 | SDK core/API |
| C09 | 증거·감사 보고 | 결과·정책·엔진·근거 → 보고서·증거 참조 | report + 제한된 증거 저장소 |

VC 형식을 기존 서명 어댑터에 무조건 편입하지 않고 데이터·증명 모델의 차이를 확인한다. C05의 권한 판단은 키가 유효하다는 사실만으로 대체할 수 없다. C08의 업무정책은 수신기관 소유이며 공통 엔진은 승인된 정책의 실행과 기록을 지원한다.

## 3. 처리 흐름과 실패 처리

C01이 호출자의 서비스·증거 접근권한을 확인하고 서버가 승인 프로파일·정책을 선택한다. C02는 크기·깊이·참조 수 제한 안에서 형식을 분석한다. C03의 무결성 확인 후 C04~C07을 적용한다. C08이 D03 규칙대로 집계하고 C09가 접근통제된 보고서를 만든다.

증거에서 읽은 발급자 ID·URL·키 정보는 검증 전까지 신뢰하지 않는다. 앞 단계 실패로 뒤 검사를 수행할 수 없으면 NOT_EVALUATED와 원인을 남긴다. 신뢰정보 공급 실패를 trust=FAIL로 바꾸거나 status 미확인을 PASS로 바꾸지 않는다. 필수 FAIL이 확인되면 최종 INVALID를 유지한다.

상태 조회의 정상 응답도 서명·출처·유효 시각을 확인한다. 인증서 또는 상태 응답에 포함된 URL은 내부망·로컬 파일 등에 접근하는 수단이 되지 않도록 허용 대상, DNS/IP 재확인, 리다이렉트와 응답 크기를 제한한다. XML 외부 엔티티, 과도한 중첩, 압축 폭탄과 원격 이미지 요청을 기본 차단 대상으로 둔다.

## 4. 제안 인터페이스

제안 HTTP 경로: POST /v1/verification-requests. 이는 신규 설계안이며 실행 중인 API 주소가 아니다. 요청에는 requestId, serviceId, evidenceRef, presentationContext를 포함한다. profileId·policyId는 서버의 서비스 설정으로 선택하며, 허용된 경우에만 호출자의 버전 요청을 검증한다.

P-ATTR·P-EMP의 presentationContext에는 서버가 발행·저장한 nonce, 예상 audience, 세션의 보유자 결합 자료를 연결한다. P-SIG에서는 해당 필드를 생략할 수 있다. evidenceRef는 승인 저장소의 접근 가능한 식별자이며 호출자가 임의 외부 URL을 전달하는 인터페이스로 만들지 않는다.

동기 완료 응답은 D03의 COMPLETED 보고서를 반환한다. 구문 오류는 HTTP 400/REQ_MALFORMED, 권한 부족은 403/REQ_UNAUTHORIZED, 승인 정책 미확보는 503/SYS_POLICY_UNAVAILABLE, 예기치 않은 오류는 500/SYS_INTERNAL로 제안한다. 상태조회 장애로 완결된 INDETERMINATE 보고서는 HTTP 200일 수 있다. HTTP 코드와 technicalResult의 의미를 분리한다.

동일한 requestId·동일한 요청 내용의 재시도는 이미 생성된 결과를 돌려주는 멱등성을 제공한다. 같은 ID에 다른 내용이 오면 REQ_MALFORMED로 거절한다. 새로운 상태 평가가 필요하면 새 requestId를 발급한다. 동일 응답의 재조회와 VC 제시 nonce의 신규 거래 재사용은 다르며 후자는 C07에서 차단한다.

## 5. 정책 패키지와 신뢰정보

정책 패키지는 policyId·버전, 적용 서비스·프로파일, 필수 검사, 허용 형식·알고리즘, 신뢰 앵커, 권한 규칙, 상태 최신성·캐시 한도, 시계 오차, 최소 속성, 수용 규칙, 배포 승인자를 포함한다. 무결성·출처를 확인한 불변 버전으로 배포하고 실행 중 조합이 섞이지 않게 한다.

목록·상태 증거의 ‘공급자가 선언한 유효기간’과 ‘국내 수용정책의 최대 허용 나이’를 모두 충족해야 캐시를 사용할 수 있다. 갱신 실패 시 무기한 연장하지 않는다. 목록 서명키 교체는 승인된 신뢰 연결과 버전으로 처리하며 새 키를 받은 사실만으로 신뢰 앵커에 추가하지 않는다.

재시도 횟수·기한, 캐시 한도, 허용 시계 오차, 파일·응답 크기, 동시 처리 수와 성능 목표는 O03·O06에서 정한다. D05의 시험 수치는 합성 환경 값이며 운영 SLA가 아니다.

## 6. 결과·증거·보안

보고서는 D03 필드를 사용하고 결정에 사용한 증거와 정책·엔진 버전을 연결한다. 정책 변경이나 상태 변경 뒤 재검증하면 새 reportId를 만들고 기존 보고서와의 관계를 남긴다. 과거 보고서를 현재 결과로 덮어쓰지 않는다.

API 인증·기관별 권한, 기관 간 저장소 분리, 전송·저장 보호, 키·비밀 관리, 의존성 취약점 관리와 감사 접근통제를 적용한다. 비밀키는 검증 보고서·운영 로그·시험 결과에 포함하지 않는다. 필요 이상으로 속성 내용을 복제하거나 상태조회 로그를 이용자 행동 추적에 재사용하지 않는다.

운영 지표는 처리량·지연 외에 코드별 실패율, 조회 실패·캐시 사용률, 기관 간 결과 불일치, 정정 소요시간을 포함한다. 민감한 속성이나 전역 사용자 ID를 지표 레이블로 사용하지 않는다. 장애가 난 기관을 식별하되 불필요한 이용자 식별은 피한다.

## 7. 도입·교체와 완료 조건

1단계는 합성 증거로 C01~C09의 계약·코드를 검증한다. 2단계는 서명문서와 신뢰목록을 연결한다. 3단계는 권한·VC 제시·상태관리를 서비스별 승인 범위에서 추가한다. 각 단계의 통과 기준은 D05이며 구현 지원 여부를 실측해 기록한다.

인터페이스 버전 변경 시 이전·신규 어댑터를 같은 fixture로 비교한다. 불일치 원인을 분석하고 이전 버전으로의 복귀 경로를 마련한다. 보안 사고로 폐기한 키·정책을 단순 롤백으로 다시 신뢰하지 않는다.

완료 조건은 공개된 입력·출력 계약, R03~R11의 추적표, 필수 시험 통과, 미지원 범위 공개와 운영 담당 지정이다. 본 초안에는 실행 코드·실데이터·배포된 엔드포인트가 포함되지 않는다.
