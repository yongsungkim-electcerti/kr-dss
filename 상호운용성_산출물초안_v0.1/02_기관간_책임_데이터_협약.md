# D02 기관 간 책임·데이터 협약

버전: v0.1 · 작성일: 2026-09-27 · 상태: 기관 협의용 초안

본 문서는 KR-AdES·KR-TL·KR-DSS 연구를 위한 설계 제안이다. 실제 기관의 참여·책임 수락, 제품의 구현 지원, 국제 적합성 인증을 의미하지 않는다. ‘한다’는 문구는 초안에서 제안하는 규칙이며 승인 전 운영 의무로 적용하지 않는다.

## 1. 협약 당사자와 적용 범위

협약명: 디지털 신뢰체계 상호연동 실증을 위한 책임·데이터 협약(안).

당사자는 발급기관 [기관명], 수신기관 [기관명], 신뢰목록 운영기관 [기관명], 지갑 제공기관 [기관명/해당 없음], 검증서비스 운영기관 [기관명]으로 한다. 기관명·법적 지위·주소·대표자·연락처는 부속서 A에 기재한다. 한 기관이 여러 역할을 맡아도 역할별 의무를 구분한다.

적용 서비스는 부속서 A에서 선택한 SVC-01·02·03으로 제한한다. 실증 데이터는 합성 자료를 기본으로 하며 실제 개인정보를 사용하려면 처리 근거와 보호조치를 먼저 확정한다. 본 초안은 서명 전 협의문이며 그 자체로 제3자 제공, 업무위탁 또는 법적 상호인정을 성립시키지 않는다.

## 2. 역할과 책임 배분

| 활동 | 실행 책임 | 최종 책임 | 협의·지원 |
| --- | --- | --- | --- |
| 원천 사실·발급권한 확인, 발급·정정·폐기 | 발급기관 담당자 | 발급기관 책임자 | 수신기관·위탁업체 |
| 서비스·기관 등록과 신뢰정보 갱신 | 신뢰목록 운영 담당 | 신뢰목록 운영기관 책임자 | 발급기관·등록 심사 주체 |
| 이용자에게 요청·제출 범위 표시 | 지갑 제공 담당 | 지갑 제공기관 책임자 | 수신기관·발급기관 |
| 검증엔진·정책 배포와 실행 기록 | 검증서비스 담당 | 검증서비스 운영기관 책임자 | 신뢰목록 운영기관 |
| 목적·최소 속성·업무 수용 결정 | 수신기관 업무 담당 | 수신기관 책임자 | 발급기관·개인정보 담당 |
| 자기 기관의 접근통제·보존·파기 | 각 기관 담당자 | 각 기관 데이터 책임자 | 정보보호·감사 담당 |
| 공동 시험 계획·결과 조정 | 공동 시험 담당 | 지정 시험 주관기관 책임자 | 각 구현기관 |
| 이용자 이의 접수와 처리 안내 | 수신기관 민원 담당 | 수신기관 책임자 | 오류 원인 기관 |

각 활동의 최종 책임자는 한 명으로 지정하되, 법령상 각 기관의 고유 의무나 이용자의 권리를 이 표로 이전하거나 제한하지 않는다. 발급 사실의 정확성, 엔진 계산의 정확성, 최종 업무 수용은 서로 다른 책임이다.

## 3. 목적·범위와 데이터 처리

당사자는 승인된 서비스 목적 범위에서만 자료를 처리한다. 제공·위탁 여부는 기관 명칭이 아니라 실제 처리 목적과 지시·통제 관계를 검토하여 부속서 B에 기록한다. 동의가 필요하면 별도로 적법하게 확보하며, 이 협약을 동의의 대체물로 사용하지 않는다.

| 데이터 묶음 | 기본 포함 항목 | 제공·생성 주체 → 수신 주체 | 제한 |
| --- | --- | --- | --- |
| DT01 업무 증거 | 문서 또는 최소 속성, 발급 시점·유효기간 | 발급기관/이용자 → 수신기관 | 서비스에서 승인한 항목만 |
| DT02 신뢰·권한 정보 | 기관·서비스 ID, 키·인증서, 인정 범위·상태·이력 | 신뢰목록/발급기관 → 검증서비스 | 공개 범위와 재배포 조건 명시 |
| DT03 제출 증명 | nonce, audience, 보유자 증명 | 지갑 → 검증서비스 | 단일 거래 용도, 재사용 방지 |
| DT04 검증 결과 | 판단·사유 코드, 정책·엔진 버전, 증거 참조 | 검증서비스 → 수신기관 | 원본 속성을 불필요하게 반복 저장하지 않음 |
| DT05 운영·감사 기록 | 가명 거래 ID, 접근·변경·오류 기록 | 각 기관 → 승인 감사 담당 | 접근권한·보존기간 별도 지정 |

부속서 B의 각 행에는 처리 목적, 항목·민감도, 처리 근거, 제공/위탁 구분, 저장 위치, 수신자, 재제공 여부, 보존 기산점·기간, 파기 방법·예외, 국외 이전 여부를 채운다. 빈 항목은 승인된 것으로 간주하지 않는다. 원문 해시도 연계 가능성이 있으므로 자동으로 익명정보라고 분류하지 않는다.

## 4. 최소수집·보존·권리 행사

원본 증거는 업무상 필요한 기관만 보관하고 검증서비스에는 처리에 필요한 범위만 전달한다. 기본 운영 로그에는 원문, 비밀키, 접근 토큰, 제출된 속성 전체를 기록하지 않는다. 재현이 필요한 경우 접근통제된 증거 저장소의 참조와 무결성 값을 기록한다.

원본, 검증 보고서, nonce 재사용 방지 기록, 운영 로그의 보존기간은 목적별로 다르게 정한다. 종료 시 파기·반환과 증명 방법을 합의하고, 법령상 보존 또는 분쟁 보존이 필요한 범위는 별도로 기록한다. 보존기간을 본 초안에서 임의의 공통 숫자로 확정하지 않는다.

열람·정정·삭제·처리정지 요청은 수신기관 접점에서 접수하고 담당 기관에 이관한다. 발급 사실 오류는 발급기관이 확인·정정하며 수신기관은 이미 수행한 업무 판단의 재검토 필요성을 결정한다. 처리 상태와 이관 이력을 이용자에게 안내한다.

## 5. 신뢰정보와 검증 품질

발급기관은 키 침해, 오발급, 권한 종료와 상태 변경을 신뢰목록 운영기관 및 영향을 받는 기관에 통지한다. 신뢰목록 운영기관은 확인 근거·효력 시점·게시 시점을 분리하여 기록한다. 검증서비스는 신뢰정보의 서명·출처·최신성을 검증하고 미확인을 유효로 대체하지 않는다.

수신기관은 D03의 기술 결과와 업무 결정을 별도로 관리한다. 기술 INVALID·INDETERMINATE인 요청을 이 협약의 자동 수용 경로에서 ACCEPT하지 않는다. 사람이 별도 증거를 받아 업무를 처리할 때는 원래 검증 결과를 덮어쓰지 않고 새로운 증거·판단 이력을 남긴다.

## 6. 장애·사고·분쟁 대응

신뢰목록·상태조회 장애에는 승인된 유효 캐시만 사용할 수 있다. 캐시도 기준을 충족하지 못하면 DEFER하고 이용자에게 재시도·대체 제출 경로를 제공한다. 무제한 재시도와 장애 중 검증 생략을 허용하지 않는다.

사고를 인지한 기관은 영향 확산을 막고 증거를 보존한 뒤 공동 연락망에 사실·발생/인지 시점·영향 범위·임시조치를 통지한다. 기관 간 최초 통지·상황 갱신·복구 목표는 부속서 C에서 정한다. 법정 신고·통지 의무와 기한은 각 기관이 별도로 확인하고 이행하며 계약상 통지로 대체하지 않는다.

책임 판단은 발급·운영·수용 단계의 실제 행위와 증거를 바탕으로 한다. 손해배상, 보험, 면책 예외, 책임 한도와 분쟁 해결 관할은 법무 검토 후 부속서 D에서 합의한다. 초안은 포괄적 면책이나 자동 연대책임을 설정하지 않는다. 실무 협의 → 기관 책임자 협의 → 합의된 분쟁 절차 순으로 처리하되 법령상 권리 행사를 제한하지 않는다.

## 7. 위탁·변경·감사·종료

재위탁·외부 클라우드·국외 처리가 있으면 업무·수탁자·위치·접근 범위와 필요한 승인 절차를 사전에 명시한다. 법령상 요구되는 위탁 문서·공개·감독 사항은 별도 부속서로 구체화한다.

형식, 코드, 신뢰정책, 알고리즘 또는 참여기관 범위의 변경은 영향 분석과 D05 회귀시험 후 공동 변경 기록에 남긴다. 긴급 키 폐기 등 즉시 조치가 필요한 경우 우선 보호 조치 후 사유·영향과 사후 승인을 기록한다. 기존 결과의 정책 버전은 변경하지 않는다.

감사는 목적·범위·주기·접근자를 정해 수행하며 필요한 증거만 제공한다. 협약 종료 또는 기관 탈퇴 시 신규 거래 중지, 진행 거래 이관, 신뢰정보 갱신, 데이터 반환·파기, 보존 예외와 이용자 통지를 정한다. 서비스 종료가 과거 감사기록의 임의 삭제를 허용하지 않는다.
