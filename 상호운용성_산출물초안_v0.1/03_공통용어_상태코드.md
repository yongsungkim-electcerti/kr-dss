# D03 공통 용어와 상태 코드

버전: v0.1 · 작성일: 2026-09-27 · 상태: 기관 협의용 초안

본 문서는 KR-AdES·KR-TL·KR-DSS 연구를 위한 설계 제안이다. 실제 기관의 참여·책임 수락, 제품의 구현 지원, 국제 적합성 인증을 의미하지 않는다. ‘한다’는 문구는 초안에서 제안하는 규칙이며 승인 전 운영 의무로 적용하지 않는다.

## 1. 적용 범위와 명명

이 문서의 코드명은 국내 공동 실증용 제안이며 ETSI·OpenID·NIST의 공식 코드가 아니다. 외부 라이브러리의 결과는 원본 코드와 근거를 보존한 채 매핑한다. 국제 규격의 INDETERMINATE·TOTAL_PASSED 등의 이름이 유사하다는 이유로 의미를 자동 대응시키지 않는다. 코드 사전의 식별자는 TV-CODESET, 버전은 0.1이다.

| 선택적 공개 | 필요한 속성만 드러내는 기능 | 거래 사이의 연결을 막는 비연계성 |

## 3. 처리 상태와 검사 상태

processingStatus는 COMPLETED·REJECTED·ERROR 중 하나다. COMPLETED는 검증 흐름을 완료했다는 뜻이며 성공이나 유효를 뜻하지 않는다. REJECTED는 요청 오류·권한 오류로 접수하지 않은 경우다. ERROR는 승인 정책 미확보나 내부 오류로 완료 보고서를 만들지 못한 경우다.

완료 결과의 검사항목은 integrity(서명·허용 알고리즘), trust(신뢰 경로·목록), authority(발급·서명 권한), status(폐기·정지 상태), freshness(증거 유효기간·판단 시점), holderBinding(보유자·수신자·거래 결합)이다.

각 검사는 PASS·FAIL·INDETERMINATE·NOT_APPLICABLE·NOT_EVALUATED 중 하나다. PASS는 충족 증거, FAIL은 위반 증거, INDETERMINATE는 판단 증거 부족을 뜻한다. NOT_APPLICABLE은 승인 프로파일에서 제외한 경우에만 사용한다. NOT_EVALUATED는 의존 검사 실패 등으로 실행하지 않은 경우로, PASS와 동일하게 처리하지 않는다.

P-SIG의 필수 검사는 integrity·trust·authority·status·freshness이며 holderBinding은 NOT_APPLICABLE이다. P-ATTR·P-EMP는 여섯 검사 모두 필수다. status 검사의 세부 대상은 서명 인증서 상태 또는 자격증명 상태 등 프로파일에서 정한다. 사실관계의 최신성은 업무정책에서도 추가 판단한다.

## 4. 기술 결과와 업무 결정의 집계

필수 검사 중 FAIL이 하나라도 있으면 technicalResult=INVALID다. FAIL이 없고 모든 필수 검사가 PASS이면 VALID다. 나머지는 INDETERMINATE다. 필수 검사에 NOT_APPLICABLE이 들어오거나 허용하지 않은 상태를 엔진이 내면 스키마·프로파일 검증 오류로 처리하고 정상 완료 결과를 발행하지 않는다.

INVALID는 REJECT로 처리한다. INDETERMINATE는 DEFER로 처리한다. VALID에 한해 수용정책을 적용하여 ACCEPT·REJECT·REVIEW 중 하나를 결정한다. REVIEW는 기술 증거는 충족했으나 사실관계·업무 재량의 사람 심사가 필요한 경우다. DEFER는 기술 판단에 필요한 증거가 부족해 재시도·추가 자료를 기다리는 경우다.

REJECTED·ERROR 응답에는 technicalResult·businessDecision·완료 checks를 넣지 않는다. 실패한 실행의 부분 진단은 접근통제된 내부 감사자료로만 관리한다. HTTP 성공 응답과 기술 VALID는 구분한다. COMPLETED 안의 INVALID·INDETERMINATE도 정상적인 업무 결과다.

## 5. 사유 코드 사전

아래 결과 열은 단일 원인 시험의 기준이다. 여러 원인이 동시에 존재하면 4절의 집계가 우선한다. 예를 들어 서명 실패와 상태조회 장애가 함께 있으면 INVALID이며 두 사유를 모두 보존한다.

| 코드 | 의미 | 검사 영향 | 단일 원인 기술 결과 | 업무 방향 |
| --- | --- | --- | --- | --- |
| TV_OK | 필수 검사 모두 통과 | 해당 없음 | VALID | 업무정책 적용 |
| TV_SIGNATURE_INVALID | 서명값·서명된 내용 불일치 | integrity=FAIL | INVALID | REJECT |
| TV_ALGORITHM_DISALLOWED | 프로파일이 금지한 알고리즘 | integrity=FAIL | INVALID | REJECT |
| TV_PROFILE_UNSUPPORTED | 형식 또는 하위 프로파일 미지원 | integrity=INDETERMINATE | INDETERMINATE | DEFER |
| TV_CHAIN_UNTRUSTED | 정상 확보한 신뢰정보로 경로 불신 확인 | trust=FAIL | INVALID | REJECT |
| TV_TRUST_UNAVAILABLE | 신뢰정보 미확보·무효 서명·연결 장애 | trust=INDETERMINATE | INDETERMINATE | DEFER |
| TV_TRUST_STALE | 신뢰정보의 허용 최신성 초과 | trust=INDETERMINATE | INDETERMINATE | DEFER |
| TV_AUTHORITY_MISMATCH | 업무·속성·시점에 대한 권한 부재 확인 | authority=FAIL | INVALID | REJECT |
| TV_AUTHORITY_UNKNOWN | 권한 증거가 부족함 | authority=INDETERMINATE | INDETERMINATE | DEFER |
| TV_REVOKED | 해당 판단 시점의 폐기 확인 | status=FAIL | INVALID | REJECT |
| TV_STATUS_UNAVAILABLE | 상태 증거 미확보·검증 불가 | status=INDETERMINATE | INDETERMINATE | DEFER |
| TV_STATUS_STALE | 상태 증거의 허용 최신성 초과 | status=INDETERMINATE | INDETERMINATE | DEFER |
| TV_TIME_INVALID | 유효기간 밖 또는 허용 오차 초과 확인 | freshness=FAIL | INVALID | REJECT |
| TV_TIME_UNPROVEN | 검증에 필요한 시점 근거 부족 | freshness=INDETERMINATE | INDETERMINATE | DEFER |
| TV_HOLDER_MISMATCH | 보유자·수신자 결합 실패 | holderBinding=FAIL | INVALID | REJECT |
| TV_REPLAY | nonce·제시 증명의 재사용 확인 | holderBinding=FAIL | INVALID | REJECT |
| BUS_POLICY_REJECT | 유효 증거이나 업무 수용 조건 미충족 | 검사 변경 없음 | VALID | REJECT |
| BUS_REVIEW_REQUIRED | 유효 증거의 업무상 추가 심사 필요 | 검사 변경 없음 | VALID | REVIEW |
| BUS_EVIDENCE_PENDING | 필수 증거 부족으로 처리 보류 | 검사 변경 없음 | INDETERMINATE | DEFER |
| REQ_MALFORMED | 요청 구문·필수 필드 오류 | 검사 미실행 | 없음 | 없음 |
| REQ_UNAUTHORIZED | 호출자·서비스·증거 접근권한 부족 | 검사 미실행 | 없음 | 없음 |
| SYS_INTERNAL | 예상하지 못한 엔진 실행 오류 | 완료 결과 없음 | 없음 | 없음 |
| SYS_POLICY_UNAVAILABLE | 승인 정책·버전을 확보하지 못함 | 검사 미실행 | 없음 | 없음 |

TV_OK는 필수 검사 전부 PASS일 때만 쓴다. VALID·REJECT에는 TV_OK와 BUS_POLICY_REJECT를, VALID·REVIEW에는 TV_OK와 BUS_REVIEW_REQUIRED를 함께 기록할 수 있다. INDETERMINATE·DEFER에는 구체적 TV 원인과 BUS_EVIDENCE_PENDING을 기록한다. TV_OK와 TV 실패·미확인 코드는 혼용하지 않는다. 외부 응답에 상세 인증서·개인정보가 노출되지 않도록 공개용 메시지와 내부 상세를 분리한다.

## 6. 결과 필드와 시간 해석

완료 응답의 필수 필드는 schemaVersion, codeSetVersion, requestId, reportId, serviceId, profileId, profileVersion, policyId, policyVersion, engineVersion, evaluatedAt, validationTime, processingStatus, checks, technicalResult, businessDecision, reasonCodes, evidenceRefs다. 각 check에는 status와 evidenceRefs를 두고 NOT_APPLICABLE 사유를 남긴다. 검증 결과 자체에 개인정보 속성 전체를 반복해서 싣지 않는다.

evidenceRefs에는 접근통제된 증거 ID·해시, 신뢰목록 식별자·버전·취득 시각, 상태 증거·발급/유효 시점, 권한 자료, 신뢰 앵커 버전을 연결한다. 원문 해시만 남기고 원본·필요 증거를 모두 파기하면 재현이 어려울 수 있으므로 D02 보존정책과 함께 정한다.

현재 실증 프로파일에서는 validationTime=evaluatedAt를 기본으로 한다. 임의의 과거 시점을 API 호출자가 지정해 만료·폐기를 회피할 수 없게 한다. 과거 시점 검증은 신뢰할 수 있는 시간 증거·당시 상태·정책을 포함한 별도 승인 프로파일에서만 추가한다. 현재 만료가 모든 과거 서명을 자동 무효화한다는 일반 규칙으로 확장하지 않는다.

## 7. 버전·확장과 사용자 안내

코드 의미를 바꾸거나 삭제할 때는 주요 버전을 변경하고 대응표·회귀시험을 제공한다. 새 코드 수신 시 유효로 간주하지 않는다. 수신기관이 해석하지 못하는 버전은 처리를 보류하고 운영자에게 알린다. 이전 보고서는 생성 당시 코드·정책 버전 그대로 보존한다.

이용자 메시지는 ‘위조됨’과 ‘확인하지 못함’을 구분한다. 예: TV_STATUS_UNAVAILABLE은 ‘현재 상태를 확인하지 못했습니다. 잠시 후 재시도하거나 안내된 대체 자료를 제출해 주세요.’ TV_SIGNATURE_INVALID의 일반 메시지는 ‘제출 문서의 서명을 확인하는 데 실패했습니다. 원본을 다시 확인해 주세요.’ 형사적 위조 판정을 코드에서 단정하지 않는다.
