# D01 서비스별 상호운용성 검토서

버전: v0.1 · 작성일: 2026-09-27 · 상태: 기관 협의용 초안

본 문서는 KR-AdES·KR-TL·KR-DSS 연구를 위한 설계 제안이다. 실제 기관의 참여·책임 수락, 제품의 구현 지원, 국제 적합성 인증을 의미하지 않는다. ‘한다’는 문구는 초안에서 제안하는 규칙이며 승인 전 운영 의무로 적용하지 않는다.

## 1. 검토 목적과 공통 범위

다른 기관이 발급하거나 서명한 전자적 증거를 수신기관이 일관되게 검증하고 업무에 수용할 수 있는지 검토한다. 문서별 참조는 D02 책임·데이터 협약, D03 공통 용어·상태 코드, D04 신뢰검증 구성요소, D05 공동 적합성 시험세트다.

공통 흐름은 신청 → 증거 발급·서명 → 보유·제출 → 기술 검증 → 업무 수용 판단 → 기록·정정이다. 검증엔진이 법적 효력이나 민원 승인 여부를 단독으로 결정하지 않는다. 실제 기관명·업무 근거·데이터 처리 근거는 협약 부속서에서 확정한다.

## 2. 서비스 목록과 실증 가정

| 서비스 ID | 대상 사례 | 제출·수신 관계 | 실증 프로파일 |
| --- | --- | --- | --- |
| SVC-01 | 기관 간 서명문서 제출 | 기관 A의 서명문서 → 기관 B 업무 담당 | P-SIG: 서명 PDF를 최초 후보로 검토 |
| SVC-02 | 공공 속성증명 제출 | 공공 발급기관 → 이용자 지갑 → 민간 수신기관 | P-ATTR: 거주지역 적격 여부 증명 |
| SVC-03 | 민간 재직증명 제출 | 기업 발급기관 → 이용자 지갑 → 행정 수신기관 | P-EMP: 재직 여부와 발급 시점 증명 |

A·B 및 공공·민간 기관은 역할 예시다. SVC-02·03은 SD-JWT VC와 OpenID4VCI/VP를 첫 후보로 하되 정책 프로파일에서 정확한 버전을 승인한 뒤 사용한다. 후보 지정은 기존 SDK가 해당 형식을 지원한다는 의미가 아니다. 주민번호·실제 재직정보를 실증 기본 데이터로 사용하지 않는다.

## 3. 공통 검토 기준

| 요구 ID | 검토 기준 | 승인에 필요한 증거 |
| --- | --- | --- |
| R01 | 발급·제출·수용의 업무 목적과 처리 근거를 특정한다 | 서비스 범위와 법무·개인정보 검토 기록 |
| R02 | 발급자와 대행자의 권한을 구분한다 | 역할 등록, 위임 범위·기간·철회 자료 |
| R03 | 형식·프로토콜·알고리즘·스키마 버전을 고정한다 | 승인 프로파일과 호환성 표 |
| R04 | 서명과 신뢰정보를 판정 시점에 맞춰 검증한다 | 신뢰목록·키·경로·상태 이력 |
| R05 | 만료·폐기·미확인 상태와 조회 실패를 구분한다 | 상태조회 및 시간 검증 시험 결과 |
| R06 | 제출자 결합과 재사용 공격 방지를 적용한다 | nonce·대상 수신자·보유자 증명 시험 |
| R07 | 공통 의미·코드와 업무 수용정책을 적용한다 | D03 매핑·수용정책·오류 안내 |
| R08 | 최소수집·보존·접근·정정 책임을 정한다 | D02 데이터 명세와 권한표 |
| R09 | 장애·변경·종료 때 서비스 연속성을 확보한다 | 재시도·대체 경로·사고 대응 기록 |
| R10 | 판단 근거를 재현하고 변경 이력을 보존한다 | 정책·엔진·증거 버전과 무결성 기록 |
| R11 | 공동 시험에서 기관별 결과를 비교한다 | D05 기대 결과 대비 차이와 조치 |
| R12 | 이용자에게 보류·거절 사유와 이의 경로를 제공한다 | 화면·통지·민원 처리 시나리오 |

## 4. SVC-01 검토 초안

업무 가정: 기관 B가 기관 A의 서명된 제출문서를 검증한 뒤 접수한다. P-SIG는 현재 시점의 수용 가능성을 기본 범위로 하며, 과거 시점의 장기 유효성 판단은 별도 프로파일 승인 전 제외한다.

법률·조직: 어떤 문서에 누구의 서명이 필요한지, 대행 서명과 재제출을 허용하는지, 원본 보존 주체가 누구인지 정해야 한다. 기관 A는 서명자 권한과 제출문서의 업무 내용을 관리하고 기관 B는 최종 접수를 결정한다.

의미·기술: 문서 유형, 업무 식별자, 발급기관 식별자와 문서 해시를 연결한다. 검증 결과는 서명 무결성, 신뢰 경로, 서명 권한, 자격 상태, 시간 조건으로 나눈다. 파일 내 서명 인증서의 존재만으로 발급자 신뢰를 인정하지 않는다. 문서 내 다중서명·사후 변경의 허용 범위는 R03 승인 항목이다.

판정 예시: 유효한 서명과 신뢰정보가 있어도 제출 기한을 넘긴 문서는 기술 VALID·업무 REJECT가 될 수 있다. 신뢰목록을 가져오지 못했고 유효한 캐시도 없으면 INDETERMINATE·DEFER다. P-SIG의 holderBinding은 적용하지 않으며 권한 검증을 생략한다는 뜻은 아니다.

실증 진입 조건: 승인된 서명 형식, 서명자 권한 자료, 갱신 정책, 문서별 수용 규칙을 확보한다. R01~R05·R07~R12 및 D05의 공통·서명 관련 시험을 통과해야 한다.

## 5. SVC-02 검토 초안

업무 가정: 민간 서비스가 이용자의 특정 지역 거주 적격 여부만 확인한다. 실제 주소 전체의 제출 필요성이 확인되기 전에는 거주 적격 여부와 기준 시점만 요청한다. 발급자는 해당 속성을 발급할 권한과 원천자료 갱신 절차를 제시한다.

법률·조직: 공공 발급자료의 민간 수용 목적, 제공·위탁 관계, 이용자의 선택과 대체 제출 방법을 정한다. 지갑 제공자와 속성 발급자는 같은 기관이라고 가정하지 않는다.

의미·기술: ‘거주 적격’의 지역 기준과 기준일을 속성 스키마에 정의한다. 지갑은 요청 목적·수신자를 제시하고 승인된 범위만 제출한다. 검증자는 nonce, audience, 보유자 결합, 속성 유효기간과 상태를 검증한다. 신뢰서비스 목록과 지갑·발급기관 역할 목록은 필요에 따라 분리한다.

판정 예시: 서명은 유효하나 해당 지역 속성을 발급할 권한이 없으면 authority=FAIL이다. 알려지지 않은 발급자의 권한 자료가 부족한 경우는 authority=INDETERMINATE다. 선택적 공개를 지원하더라도 상태조회·식별자에 의한 추적 가능성은 별도 점검한다.

실증 진입 조건: 최소 속성, 보유자 결합 방식, 상태조회 및 오프라인 허용 여부를 승인한다. 기본안에서는 오프라인 상태 미확인 증명의 자동 수용을 허용하지 않는다. R01~R12 전부를 검토한다.

## 6. SVC-03 검토 초안

업무 가정: 행정 수신기관이 신청자의 민간 재직증명을 접수한다. 기업은 재직 사실의 발급 근거와 갱신 책임을 지며, 발급 대행이 있으면 기업·대행자의 권한 관계를 별도로 증명한다.

법률·조직: 민간 증명의 해당 행정업무 수용 근거를 확인한다. 전자적으로 검증된다는 이유만으로 행정 증명요건 충족을 선언하지 않는다. 퇴사·오발급의 정정과 이미 내려진 결정의 재검토 담당을 정한다.

의미·기술: ‘재직’은 발급 시점 사실인지 제출 시점 사실인지 구분한다. 초안은 발급 기준 시점과 유효기간을 함께 제공하고, 제출 시점의 상태를 추가 확인한다. 근무기간·급여·부서 등 불필요한 속성은 기본 제출에서 제외한다.

판정 예시: 권한 있는 기업이 발급했어도 폐기 확인 시 INVALID·REJECT다. 발급 이후 실제 사실관계에 이의가 제기되었지만 기술 증거가 유효하면 VALID·REVIEW로 구분하고, 담당자가 근거를 남겨 처리한다. 상태 만료를 현재 재직 사실의 증거로 취급하지 않는다.

실증 진입 조건: 발급권한 등록, 오발급·퇴사 처리, 최소 속성과 수용 근거를 합의한다. R01~R12 전부를 검토한다.

## 7. 쟁점·결정 및 검토 완료 기준

O01 실제 참여기관·업무 근거는 각 서비스 소유기관이 정한다. O02 형식·프로토콜·알고리즘 버전은 기술협의체가 정한다. O03 상태 갱신주기·캐시 한도·시계 오차는 운영기관과 수신기관이 함께 정한다. O04 보존기간·제공/위탁 구분·국외 이전 여부는 데이터 책임자와 법무가 정한다. O05 SLA·사고 연락망·비용·책임 한도는 기관 대표가 합의한다. O06 성능 목표·시험 구현 조합은 공동 시험 담당이 정한다.

각 서비스의 결론은 승인·조건부 승인·보완 후 재검토 중 하나로 기록한다. 초안 현재 결론은 모두 ‘보완 후 재검토’다. R01~R12별 증거, O01~O06의 담당·기한, 중대 실패의 조치가 갖춰진 뒤 승인권자가 결정한다. 기술 구현이나 실증 성공을 선행 가정하지 않는다.
