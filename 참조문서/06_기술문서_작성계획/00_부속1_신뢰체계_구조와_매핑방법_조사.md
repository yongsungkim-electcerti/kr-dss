# 00 부속1 — 신뢰체계의 구성요소 배치 구조와 EU 기준 매핑 방법 조사

조사일: 2026-09-29. [0번 문서](../../기술문서/00_신뢰프레임워크_분석_EIF중심.md)의 정의(E1~E8)와 결정 사항을 전제로 두 가지를 조사했다. 결정 사항은 신뢰서비스(전자서명)를 범위에 포함하고, 상호연동을 "신뢰체계 요소 간 매핑"으로 보는 것이다.

1. 각 국가는 E1~E8을 어떻게 배치하는가. EIF처럼 메인 문서 아래 세부 문서가 연계된 **허브형**인가, 한국처럼 요소가 따로 존재하는 **분산형**인가.
2. 유럽을 기준으로 서로 다른 신뢰체계의 법적·기술·검증·조직·의미 요소를 **어떻게 매핑하는가**. 통합 체계(신뢰 프레임워크)가 없는 나라는 요소를 각각 어떻게 매핑해야 하는가.

법적 매핑, 기술·검증 매핑, 조직·의미·평가 매핑과 구조 분석으로 나눠 조사한 3건의 결과를 합쳤다. 조사 중 웹 검색 한도가 소진돼 로컬 원문, EU 원본 XML, DSS 6.1 jar·공식문서로 대신했다. 확인하지 못한 항목은 7장에 모았다.

## 1. 요약

- **허브형과 분산형**
  - 영국·뉴질랜드·호주·EU eIDAS·캐나다 PCTF는 **허브형**이다. 법률 또는 개요 문서가 메인이고, 규칙·보증수준·인정·공시가 위임 조항이나 명시적 참조로 연결된다.
  - EIF도 허브형이지만 보증수준(E5)과 인정(E6)이 없는 **메타 프레임워크**다.
  - 한국은 **분산형**이다. 전자서명 영역만 시행령 → 고시 → 평가기관으로 이어지는 소형 허브이고, 신원 영역 전체에는 공통 상위 문서가 없다.
- **EU 매핑의 기본형**: 요건 비교 → 동등성 평가 → 인정 결정 → 공시·목록 등재 → 감독 유지의 5단계다.
  - 매핑 단위는 조문이 아니다. **"수준(LoA·적격)으로 표현된 요건 묶음 + 이를 보증하는 평가·감독 체계 + 공시 수단"**이 단위다.
  - 판정 기준은 문구가 일치하는지가 아니라 **결과가 동등한지**다.
- **실제 작동 중인 기술 매핑 선례**: EU **AdES LOTL**이다. 우크라이나·몰도바의 신뢰목록을 서비스 유형·상태·인증서 내용·보정자(qualifier)의 4축 대응표로 EU 의미에 옮긴다. 우크라이나 "적격 CA"는 EU에서 "비적격 PKC"로 **낮춰** 대응된다. 인정 수준은 eIDAS 제25·27조 AdES 수준이고, 제14조의 적격 동등 인정이 아니다.
- **한국의 과제**: 분산형이므로 제도별로 EU 대응물과 인정 경로를 따로 설계해야 한다. 가장 현실적인 출발점은 **전자서명·e시일**이다. 기계가독형 국가 신뢰목록(KR-TL)을 공시하는 것이 eIDAS 제14조의 전제 조건이자 AdES LOTL 등재의 전제 조건이다.

## 2. 구성요소 배치 구조

E1 목적·원칙 / E2 거버넌스 주체 / E3 역할 / E4 규칙 / E5 보증수준 / E6 적합성평가·인정 / E7 감독·집행 / E8 신뢰공시

### 2.0 분류 기준

구조 분류는 **E1~E8이 어떻게 연결되어 있는가**를 본다. E1~E8을 모두 갖췄는지는 따지지 않는다. 그것은 0번 문서 1.6의 판정(신뢰 프레임워크 / 부분적 / 구성요소)이 따로 본다. 두 축은 서로 독립이다. 허브형이어도 적용 범위가 좁으면 "부분적"일 수 있다(예: 벨기에).

**용어**

- **허브(메인 문서)**: 다음 네 요건을 **모두** 충족하는 단일 문서(법률·규정·협약·개요서)다.
  - H1 해당 신뢰 영역의 **공통 목적·범위**를 선언한다.
  - H2 **거버넌스 주체**를 지정한다. 규칙의 제정·개정 권한과 책임을 가진 주체다.
  - H3 자신에게 없는 E4~E8 요소를 하위 문서에 **위임 조항이나 명시적 참조**로 연결한다. 하위 문서는 허브에서 권한이나 효력을 얻는다.
  - H4 하위 문서가 허브의 **용어 정의**를 공유한다.
- **신뢰 영역**: 전자서명·신뢰서비스, 신원확인·인증 등 분류 대상 범위다. 영역을 먼저 정하고 판정한다.

**판정 순서**

| 단계 | 질문 | 답 → 분류 |
|---|---|---|
| Q1 | 대상 신뢰 영역 전체를 덮는, H1~H4를 모두 충족하는 허브가 있는가? | 없음 → **분산형** / 있음 → Q2 |
| Q2 | 허브가 직접 규율하는 대상은 무엇인가? | 개별 사업자·서비스(역할 수행자) → **허브형**, Q3으로 / 다른 프레임워크·기관(국가·분야별 프레임워크) → **메타 허브** |
| Q3 | 허브는 무엇으로 참여자를 구속하며, 누가 소유하는가? | 국가 입법(법률·하위법령)으로 구속 → **허브형(법률)** / 공공기관이 소유하고 참여자와의 **계약**으로 구속 → **허브형(계약)** / **비정부 단체**가 소유하고 자발적 인증계약으로 구속 → **허브형(민간)** |

**유형별 기준**

| 유형 | 필수 조건 | 판별 증거 | 해당 |
|---|---|---|---|
| **허브형(법률)** | H1~H4 충족 + 사업자·서비스 규율 + 허브가 법률·규정 | 허브 조문에 하위 규칙·인정·공시를 위임하는 조항이 있다 | 영국(DUA Act s.28·29·32·50 → TF·보충코드·등록부·신뢰표시), 뉴질랜드(Act s.18 → Rules), 호주(Act s.28·99·168 → 인정 Rules·데이터 표준), EU eIDAS(규정 → 시행규칙 → ETSI 표준), 핀란드(법 617/2009 → Traficom M72B), 이탈리아(CAD 제64조 → DPCM → AgID 규정), 태국(ETA → 왕령 → 고시 → ETS 11), 우루과이(Decreto 70/018 → Política v1.0) |
| **허브형(계약)** | H1~H4 충족 + 사업자·서비스 규율 + 허브가 **공공 소유 문서**이고 구속력이 계약에서 나옴 | 참여자 계약·라이선스 계약이 허브를 부속서나 준거 규범으로 편입한다. 법률의 인정 조항이 없거나 미시행이다 | 네덜란드(BZK 소유 Afsprakenstelsel + 참여자 계약, Wdo 인정조항 미시행), 스웨덴(Digg 신뢰 프레임워크 = 라이선스 계약 부속서 2) |
| **허브형(민간)** | H1~H4 충족 + 사업자·서비스 규율 + 허브 소유자가 **비정부 단체** | 인증계약·상표사용계약으로만 구속한다. 정부는 참여자나 수용자일 뿐 소유자가 아니다 | 캐나다 DIACC PCTF(Overview → 구성요소 → 적합성 기준 → 인증 프로그램), 미국 Kantara |
| **메타 허브** | H1~H4 충족 + 허브가 사업자·서비스가 아니라 **다른 프레임워크를 규율** | 허브 자체에 사업자 대상 E5·E6·E8이 없다. 하위 프레임워크에 정렬 의무·권고를 둔다 | EIF(IEA 제6조 → EIF → NIF·분야별 프레임워크 정렬, RC5.1) |
| **분산형** | 대상 영역 전체를 덮는 허브가 **없음** | 요소가 서로 다른 법·부처에 있고, 서로 위임·참조하지 않으며, 공통 목적 조항·단일 거버넌스 주체가 없다 | 한국, 독일(BSI TR·PAuswG·EUDI 시행법안), 베트남(Decree 23·69가 제34·36조로만 연결), 인도(CCA·eSign·Aadhaar) |

**경계 사례 처리**

- **부문 허브**: 영역 일부에만 허브가 있으면 영역 전체는 분산형으로 분류하고, 부문 허브를 따로 표기한다.
  - 예: 한국 전자서명 영역은 전자서명법 → 시행령 → 운영기준 고시로 H1~H4를 충족한다. 그러나 신원확인 영역(본인확인기관·모바일 신분증)과 연결되지 않는다. 따라서 "분산형(전자서명 부문 허브)"이다.
  - 브라질의 PKI 영역, 베트남의 신뢰서비스 축도 같은 방식으로 처리한다.
- **일부만 참조하는 경우**: 요소 사이에 참조가 있어도 H1·H2(공통 목적·단일 거버넌스)가 없으면 분산형이다.
  - 예: 독일은 EUDI 시행법안이 BSI 인증을 참조하지만, BSI TR·PAuswG·법안을 묶는 공통 목적 조항과 단일 주체가 없다. 게다가 법안은 아직 시행 전이다.
- **법률과 계약의 혼합**: 허브의 구속력이 실제로 어디서 나오는지로 판정한다. 법률 조항이 있어도 미시행이면 계약형이다(네덜란드).
- **공공 수용 정책**: 정부가 민간 허브를 수용하는 정책(캐나다 TBS Directive 제4.1.7조)은 허브가 아니다. 이 경우 허브는 민간 PCTF이고, 연방 정책은 **수용자**로 기록한다.

**캐나다 DIACC PCTF — 민간 허브형(개요 → 구성요소 → 적합성 기준 → 인증 프로그램)**
- 구조: E1·E2는 Overview와 DIACC 위원회, E3·E4는 구성요소별 적합성 기준, E5는 구성요소 수준과 AMM, E6은 인증 프로그램(CP-02/03/05), E7은 인증계약, E8은 Trusted List가 맡는다.
- 연방 공공부문은 **준허브형**이다. TBS Directive 제4.1.7조가 "승인된 신뢰 프레임워크"를 수용하게 하고, 그 아래 Standard와 PSP가 있다. 수용은 수용서(Letter of Acceptance)로 한다.

**EIF — 메타 허브형**
- 구조: 상호운용성법(IEA) 제6조 → EIF(원칙·계층·권고) → 국가 상호운용성 프레임워크(NIF)·분야별 프레임워크 → 솔루션.
- 거버넌스는 IE 위원회가 맡는다. NIF는 RC5.1에 따라 EIF와 정렬하고, 솔루션은 "Interoperable Europe solution"으로 공시한다.
- E5·E6이 없으므로 신뢰 프레임워크를 **묶는 틀**이지 그 자체는 아니다.

**그 밖의 허브형**
- 법령형: 태국(ETA → 왕령 → 고시 → ETS 11), 이탈리아(CAD 제64조 → DPCM → AgID 규정 → Convenzione), 핀란드(법 617/2009 → M72B), 우루과이(Decreto 70/018 → Política v1.0)
- 계약형: 네덜란드 eTD AS1.24e, 스웨덴 Digg 프레임워크(라이선스 계약 부속서)

### 2.2 분산형 사례

**한국**

| 요소 | 담는 문서 | 메인과의 연결 |

**그 밖의 분산형**
- 독일: BSI TR·PAuswG·EUDI 시행법안, 기관 5곳
- 베트남: 신뢰서비스 축과 신원 축이 Decree 23 제34·36조로만 연결
- 인도: CCA·eSign·Aadhaar
- 브라질: PKI 영역만 완비

### 2.3 구조가 매핑에 주는 의미

- **허브형 ↔ 허브형**: 프레임워크 대 프레임워크로 매핑한다. 거버넌스 주체가 하나라 창구도 하나다(예: 스웨덴 신뢰 프레임워크 레벨 3·4 → eIDAS substantial·high).
- **분산형**: 제도마다 EU 대응물과 인정 경로가 다르다. 요소별로 매핑한 뒤 이를 묶을 주체가 필요하다.

**EIF·IEA의 위치**
- IEA 평가(M2)는 두 체계의 **동등성을 판정하는 절차가 아니다**. 자기 체계의 새 요건이 국경 간 상호운용에 주는 영향을 보는 사전 영향평가다.
- 다만 매핑 단위(구속 요건), 차원(법·조직·의미·기술·거버넌스), 판정 표현(IOPA Statement), 공개 방식(기계가독 보고서)은 **매핑 결과를 기록하는 서식**으로 재사용할 수 있다.
- 동등성 판정 자체는 eID 동료평가, 제14조, PCTF 평가·수용(M8)이 맡는다.

## 6. 권고 경로

1. **기록 서식**: 요소별 매핑 결과를 IEA·IOPA 서식(요건 → 차원별 영향 → 판정 → 남은 장벽)으로 기록한다.
2. **전자서명·e시일(단기)**: TS 119 612 비EU 규칙에 맞춘 KR-TL을 공시한다. 이어서 KR 서비스 유형·상태·인증서 내용을 EU로 옮기는 **MRA 대응표 초안**을 만들어 AdES LOTL 수준(제25·27조)을 목표로 한다. KR-DSS는 같은 대응표로 검증한다.
3. **전자서명·e시일(장기)**: 법적 효력 차등(적격 상당 등급), 국가인정기구 기반 평가기관 인정, 외국 서비스 동등성 판정 조항을 정비해 **제14조**(이행법률 또는 협정)를 목표로 한다. 경로는 EU–일본처럼 **협력각서 → 기술 실증(목록 교차 참조) → 동등성 평가 → 협정**이다.
4. **신원·지갑**: 우선 일·EU 실증 방식(기술 우선, TS 119 602 교차 참조)을 따른다. EU에 제3국 지갑 인정 근거가 없다는 점을 전제로 둔다.
5. **구조 전환(중장기)**: E5(공통 보증수준)와 E2(허브 문서·단일 거버넌스)를 새로 만들어 분산형을 허브형으로 전환해야 프레임워크 대 프레임워크 매핑이 가능하다.

## 7. 확인하지 못한 사항

- 제14조 이행법률·협정 체결 여부. 우크라이나·몰도바의 법적 인정 문서(AdES LOTL 등재 외). 집행위 국제 호환성 파일럿(`https://eidas.ec.europa.eu/efda/intl-pilot/`) 내용.
- 동료평가 결정 대체 규정(CIR 2025/1568)의 정확한 명칭·내용(ARF 참고문헌표 기준).
- 스웨덴 "LoA Mapping" 별첨 본문(공개 페이지에 없음). 동료평가 대응 문서 서식.
- ETSI TS 119 602·119 605 원문, eIDAS SAML LoA·속성 URI 원문.
- OIX Digital ID DNA·Guide 원문(403), OECD 권고 원문의 국경 간 조항, ENISA 보고서 본문.
- 영국·뉴질랜드·호주와 eIDAS·NIST 간 공식 대조표, 영국·스위스의 EU 인정 현황.
- 한국 전자서명법의 외국 전자서명 상호인정 조문 현행 번호.
