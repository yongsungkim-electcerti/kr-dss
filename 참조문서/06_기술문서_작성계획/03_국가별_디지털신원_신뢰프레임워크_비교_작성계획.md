# 작성계획 — 3. 국가별 디지털 신원 신뢰 프레임워크 비교

작성일: 2026-09-29. [기술문서 작성 목록](기술문서_작성목록.md)의 3번 문서(A. 법·제도 계층)의 작성계획이다.

## 1. 문서 개요

| 항목 | 내용 |
|---|---|
| 문서명 | 국가별 디지털 신원 신뢰 프레임워크 비교 |
| 위치 | A. 법·제도 계층(EIF 법률적 상호운용성). 0번 기준 문서의 공통 구성요소를 비교 기준으로 받아 쓴다 |
| 비교 대상 | 영국 DIATF(DVS Trust Framework 1.0), 뉴질랜드 DISTF, 캐나다 PCTF, 일본 Trusted Web·VC/DIW 거버넌스 |
| 비교 축 | ① 역할 모델 ② 인정(인증)체계 ③ 감독 구조. 보조 축으로 법적 근거, 보증수준, 신뢰표시·등록부를 둔다 |
| 목적 | 국가별로 "누가 무엇을 인정하고, 누가 감독하며, 인정 결과를 어떻게 공시하는가"를 한 틀로 비교해 국내 인정사업자 제도와 KR-TL 설계에 쓸 시사점을 도출한다 |
| 분량(목표) | 본문 25~35쪽, 비교표 5~7개, 구조도 4~5개 |

### 작성 원칙

- 네 나라의 **성숙도가 다르다**. 영국·뉴질랜드는 법률에 근거한 시행 제도, 캐나다는 민관 협의체(DIACC)의 자율 프레임워크, 일본은 정책 방향·검토 보고서 단계다. 비교표에 성숙도 열을 두고, 계획·초안을 시행 제도와 같은 급으로 서술하지 않는다.
- 일본 VC·DIW 보고서의 별지 3은 준수 의무가 아닌 **검토사항 초안**이다([통합 원문요약](../03_원문요약/통합_원문요약.md) 4.4절). 일본 부분은 "제도"가 아니라 "설계 논점"으로 다룬다.
- 보증수준은 이 문서에서 이름과 구조만 비교한다. 등급 대응(매핑)은 4번 문서(IAL/AAL/FAL)로 넘긴다.
- 인증기관(CAB) 요건 세부는 5번 문서(적합성 평가), 신뢰 레지스트리 운영 절차는 6번 문서로 넘긴다. 이 문서는 구조 비교에 집중한다.

## 2. 목차(안)

### 1장. 서론
- 1.1 작성 배경 — 0번 문서가 도출한 신뢰 프레임워크 공통 구성요소, 국내 전자서명 인정제도와의 관계
- 1.2 비교 대상 선정 이유 — eIDAS(1번 문서)와 다른 방식: 법률 근거형(영국·뉴질랜드), 민관 협의형(캐나다), 정책 검토형(일본)
- 1.3 비교 틀 — 역할 · 인정체계 · 감독 구조 + 보조 축, 성숙도 표기 방법

### 2장. 영국 — UK DIATF / DVS Trust Framework 1.0
- 2.1 연혁: beta 0.3(2023) → gamma 0.4 → 1.0, Data (Use and Access) Act 2025에 따른 법정 제도화
- 2.2 역할 모델: identity / attribute / holder / orchestration / component service provider
- 2.3 인정체계: UKAS 인정 CAB에 의한 인증, 인증 스킴(CAB 요건 v1.15), gamma 0.4 인증의 경과 규칙
- 2.4 감독 구조: DSIT·OfDIA, DVS 등록부(register), 신뢰표시(trust mark)
- 2.5 보증수준과 데이터: GPG45 연계, GPG45 데이터 스키마(선택 적용)
- 2.6 GOV.UK Wallet과 민간 DVS의 관계

### 3장. 뉴질랜드 — DISTF
- 3.1 법적 구조: DISTF Act 2023 → Regulations 2024 → Rules 2024 → 2026-1 개정(2026-06 통합본)
- 3.2 역할 모델: 5개 서비스 유형(information · binding · authentication · credential · facilitation)
- 3.3 인정체계: 제공자·서비스 인정(accreditation), 인정표시, 독립 평가
- 3.4 감독 구조: Trust Framework Board와 Trust Framework Authority(GDDA/DIA 이관 포함)
- 3.5 규칙 구성: Part 2 서비스 → 2A 신원보증 → 3 권한 → 4 프라이버시 → 5 보안·위험 → 6 정보·데이터 관리
- 3.6 2026-1 개정의 변경점과 자격증명 수용(인정 서비스의 자격증명과 다른 출처 자격증명의 구분)

### 4장. 캐나다 — DIACC PCTF
- 4.1 성격: 민관 협의체가 만든 자율 프레임워크, 공공(PCTF 공공부문 프로파일)과 민간의 관계
- 4.2 구성요소 체계: 구성요소별 Final Recommendation 구조
- 4.3 역할 모델: Digital Wallet 구성요소의 Wallet Provider 역할, 자격증명 저장·관리·제시 요건
- 4.4 신뢰 레지스트리: 참여자 등록·검증·상태관리(Trust Registries 개요 V1.0)
- 4.5 인정체계: DIACC 인증 프로그램(Voilà Verified)과 신뢰표시 — **원문 확보 후 서술**(5장 참조)
- 4.6 감독 구조: 법정 감독기관이 없음, 협의체 거버넌스의 한계와 장점

### 5장. 일본 — Trusted Web과 VC·DIW 거버넌스
- 5.1 Trusted Web 구상: 신뢰 앵커 문제, 검증 가능성 확대 원칙(KISA Trusted Web 보고서 경유)
- 5.2 DIW 자문기구 보고서(FY2024): 지갑의 이점·활용 유형, 보안·프라이버시 위험, 거버넌스 쟁점, 발급자 거버넌스를 논의에서 제외한 범위
- 5.3 VC·DIW 거버넌스 보고서(2026-04): 속성증명 과제, 발급과 수용을 함께 설계, 서명 검증과 발급기관 정당성의 분리
- 5.4 별지 3·4: 검토사항 목록안(사용 사례·보증수준·기술 구성·생애주기·거버넌스), 기술 WG 논의
- 5.5 실행 사례와의 연결: 마이넘버카드 스마트폰 탑재, 국가자격 디지털화(세부는 19번 문서로)

### 6장. 비교 분석
- 6.1 역할 모델 비교표 — 각국 역할을 공통 역할(발급자·보유자/지갑·검증자·신원확인·중개·신뢰정보 제공자)에 대응
- 6.2 인정체계 비교표 — 인정 주체, 평가 주체(CAB·독립평가자·자체평가), 인정 대상(제공자/서비스), 유효기간·재평가
- 6.3 감독 구조 비교표 — 법적 근거, 감독기관, 등록부·신뢰표시, 제재·정지·해지 수단
- 6.4 보조 비교 — 보증수준 명칭·단계, 프라이버시 규칙, 국경 간 수용 조항
- 6.5 성숙도와 방향성 — 시행 / 협의체 권고 / 정책 검토 단계 표기, eIDAS(1번 문서)와의 위치 비교

### 7장. 국내 시사점
- 7.1 국내 제도 대응: 전자서명법상 인정제도(인정기관·평가기관·인정사업자)와 각국 역할·인정·감독 구조의 대응
- 7.2 공백: 속성·자격증명 서비스, 지갑 제공자, 중개(오케스트레이션) 역할의 부재 여부 — 2번 문서의 법적 공백과 교차 확인
- 7.3 KR-TL 설계 입력: 등록부·신뢰표시 공시 항목, 서비스 유형 코드, 상태·이력 → 15번 문서로 연결
- 7.4 후속 문서 연결: 4번(보증수준), 5번(적합성 평가), 6번(신뢰 레지스트리), 20번(상호인정 로드맵)

## 6. 완료 기준

- 네 나라 모두 역할 · 인정체계 · 감독 구조의 세 칸이 원문 인용으로 채워져 있다. 채울 수 없는 칸은 "원문 미확보" 또는 "해당 제도 없음"으로 구분해 표기한다.
- 시행 제도, 협의체 권고, 정책 검토 단계가 비교표에서 구분된다.
- 7장에 KR-TL(15번)과 적합성 평가(5번)로 넘길 입력 항목이 목록으로 정리되어 있다.
- 4·5·6번 문서와 범위가 겹치는 내용은 요약과 링크로만 처리한다.
