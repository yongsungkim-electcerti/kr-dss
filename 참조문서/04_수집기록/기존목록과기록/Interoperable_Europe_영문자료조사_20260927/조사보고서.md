# Interoperable Europe 상호운용성 참고자료 조사

조사 기준일: 2026-09-27

상호연동을 개별 시스템의 연결뿐 아니라 법적·조직적·의미적·기술적 상호운용성으로 넓혀 조사했다. 전자서명과 신뢰체계 연구에 직접 필요한 자료 외에 평가, 공통 데이터 모델, 참조 아키텍처, 적합성 시험, 운영과 재사용 자료를 포함했다.

## 1. 저장한 결과와 확인 범위

| 구분 | 결과 | 해석 |
|---|---:|---|
| 사이트맵 | 15개 사이트맵, 6,012개 URL | 탐색 후보 전체 목록. 전문을 읽은 문서 수가 아님 |
| 접근 시도 | 392개 URL | 포털과 연결된 SEMIC·ITB 기술 문서 포함 |
| HTTP 200 응답 | 261개 URL | 로그인·목록·중복 경로도 있어 독립된 문서 수와 다름 |
| 접근 실패 | 131개 URL | HTTP 429 등. 오류를 접근결과 파일에 보존 |
| 참고자료 목록 | 261개 항목 | 본문 확인 자료와 상위 목록에서 확인한 명세를 포함 |
| 한국어 설명을 붙인 핵심 자료 | 63개 항목 | 개별 명세·지침뿐 아니라 탐색용 자료실도 포함 |
| 첨부 원문 링크 | 389개 URL | 중복 URL 제거. 영어 외 언어 및 전문 미검토 자료 포함 |
| 자료실 개별 문서 후보 | 290개 URL | 카드의 제목·게시/수정일·링크 확보. 개별 본문 확인과 구별 |
| 목록 내 직접 참조 | 924개 방향 관계 | 한 페이지가 다른 자료를 링크하는 관계 |

웹사이트 전체를 정독한 전수 조사로 볼 수는 없다. 상위 메뉴를 기준으로 범위를 펼치고, 사이트맵을 확보한 뒤 연구 관련 페이지와 기술 문서로 내려갔다. 접근 제한이 발생한 뒤 포털에 대한 추가 요청을 중단했다. 연결된 다른 공식 기술 문서 사이트는 별도로 확인했다. 검색 결과의 모든 페이지, 로그인 후 자료, 모든 첨부 파일의 전문을 확인하지는 않았다.

날짜는 발행·게시·수정·버전 날짜를 구별했다. 자료실에 표시된 개별 카드 날짜는 `자료실_개별문서_후보.csv`에 저장했다. 날짜가 없는 소개 페이지에 사이트맵의 lastmod나 조사일을 발행일로 넣지 않았다. 버전 번호나 연도판은 확인한 경로의 표시이며, 항상 최신판이라는 뜻은 아니다.

## 2. 사이트 메뉴별 조사 지도

포털의 공통 내비게이션은 다음 다섯 영역으로 나뉜다. 메뉴 링크는 `사이트_메뉴.csv`에 보존했다. [포털 홈페이지](https://interoperable-europe.ec.europa.eu/)

| 상위 메뉴 | 하위 메뉴 | 이번 연구에서의 역할 |
|---|---|---|
| Policy | News, Events, Interoperable Europe Act, AI in the public sector, Digital Ready Policy Making, FAQs | 제도·정책과 개정 동향 파악 |
| Solutions | Interoperable Europe Solutions, EU Interoperability Solutions Catalogue, EU Open Source Solutions Catalogue, Guidelines on Sharing Interoperability Solutions, EUPL | 재사용 가능한 명세·소프트웨어·라이선스 탐색 |
| Support Centre | Portal support, SEMIC, OSOR, EIF, Monitoring, Public Sector Tech Watch, GovTech, Architecture solutions, Regulatory sandboxes, Forum | 프레임워크·의미 모델·아키텍처·운영 사례 |
| Governance | Board, Community, National competent authorities, Assessments, Funding Opportunities, Landscape of EU digital regulations | 책임 체계·평가·의사결정·법령 관계 |
| Academy | Learning paths, Courses, Policy briefs, Curriculum, Seasonal school 2026 | 도구 적용 교육과 정책 설명 자료 |

사이트맵에는 과거 프로젝트, 소프트웨어 이슈와 토론도 많이 포함된다. URL 수가 많은 컬렉션을 최신 정책의 중요도 순위로 해석해서는 안 된다. 최신 소개 페이지, 버전별 원문, 과거 연도판을 함께 남겨 비교할 수 있도록 했다.

## 4. 조사에서 확인한 연결 관계

### 평가 지침 → 도구 → 공통 어휘 → 사례

Assessment Toolbox는 평가 지침의 실행을 지원하며 온라인 도구, 보고서 저장소, 공통 어휘와 API를 연결한다. 평가 문서를 만드는 일과 결과 데이터를 교환하는 일을 함께 설계할 수 있다는 점에서 유용하다. [Assessment Toolbox](https://interoperable-europe.ec.europa.eu/collection/assessments/assessment-toolbox)

평가 저장소 첫 화면에서 **eIDAS Implementing Acts Batch 6** 항목과 **2026-06-23 게시일**을 확인했다. 개별 보고서의 분석 내용은 아직 검토하지 않았다. 전자신원 분야의 실무 사례로 우선 후속 확인할 가치가 있다. [저장소](https://interoperable-europe.ec.europa.eu/collection/assessments/report/repository) · [개별 보고서 링크](https://interoperable-europe.ec.europa.eu/collection/assessments/report/2175)

### 공통 의미 모델 → 메시지 구조 → 데이터 검증

SEMIC 목록은 공통 어휘와 응용 프로파일을 제공하고 검증 도구도 연결한다. 자연인·법인·공공기관의 식별 정보, 판단 기준과 증빙, 서비스 목록, 데이터 카탈로그를 같은 모델 하나로 처리하기보다 각 명세의 범위를 확인해 조합해야 한다. 국내 신뢰정보에 적용하는 방법은 별도 매핑 작업이 필요하다. [SEMIC Specifications](https://interoperable-europe.ec.europa.eu/collection/semic-support-centre/specifications)

Core Person·Business 등에서 표시된 Recommendation과 Core Public Event의 Candidate Recommendation은 같은 상태가 아니다. 목록에는 원문의 상태와 날짜를 함께 보존했다. [Core Person](https://semiceu.github.io/Core-Person-Vocabulary/releases/2.1.2/) · [Core Public Event](https://semiceu.github.io/Core-Public-Event-Vocabulary/releases/1.1.1/)

### EIF → EIRA → ELIS

EIRA는 EIF의 상호운용성 관점을 구성요소와 설계 관점으로 구체화한다. ELIS는 그 구성요소와 구현에 활용할 표준·명세를 연결한다. 상위 아키텍처 소개 페이지와 개별 솔루션 페이지의 버전 표시가 일치하지 않는 경우가 있어, 실제 인용·적용 시 선택한 버전의 원문을 고정해야 한다. 조사 시 EIRA 개별 소개 페이지는 7.0.0, ELIS는 7.0.0과 2026-04-30 날짜를 표시했다. [EIRA](https://interoperable-europe.ec.europa.eu/collection/interoperability-architecture-solutions/solution/eira/welcome) · [ELIS](https://interoperable-europe.ec.europa.eu/collection/common-assessment-method-standards-and-specifications-camss/solution/elis/welcome)

### 검증 규칙 → 적합성 시험 → 운영 결과

ITB는 개별 데이터 검증과 여러 단계를 거치는 시스템 적합성 시험을 구별한다. GITB TDL, 서비스 API, 검증기와 적합성 결과 화면의 기술 문서를 함께 확보했다. 이를 국내 시험체계에 활용하려면 국내 규격의 요구사항, 오류·예외 처리, 시험 판정과 증빙 보존 규칙을 먼저 정의해야 한다. 이 활용 방향은 본 조사의 제안이다. [ITB FAQ](https://interoperable-europe.ec.europa.eu/collection/interoperability-test-bed-repository/solution/interoperability-test-bed/faq) · [GITB 서비스 API](https://www.itb.ec.europa.eu/docs/services/latest/)

## 5. 국내 산출물과 참고자료의 대응 — 연구 활용 제안

아래 대응은 EU 문서가 국내 도입을 요구한다는 뜻이 아니라, 기존 국내 산출물을 구체화하기 위한 연구자의 제안이다.

| 국내 산출물 | 먼저 참고할 자료 | 산출물에 반영할 항목 |
|---|---|---|
| 서비스별 상호운용성 검토서 | EIF, 평가 지침, Toolbox, IOPA | 대상 서비스, 기관·사용자, 계층별 제약, 영향, 대안, 증빙, 판정 기록 |
| 기관 간 책임·데이터 협약 | Digital-ready Policymaking, 평가 지침의 거버넌스 장, 솔루션 공유 지침 | 결정권자, 데이터 제공·이용 책임, 변경 통지, 장애·분쟁 처리, 운영 종료 |
| 공통 용어와 상태 코드 | Core Person·Business·CPOV, CCCEV, SEMIC Style Guide | 용어 정의, 식별자, 코드 소유자, 버전, 증빙과 상태의 구분; 전자서명 상태 코드는 관련 검증 규격을 별도 확인 |
| 재사용 가능한 신뢰검증 구성요소 | EIRA, ELIS, CAMSS, RP 2026, OSOR | 구성요소 책임, 인터페이스, 적용 표준, 의존성, 변경·배포·유지보수 정책 |
| 공동 적합성 시험세트 | ITB, GITB TDL, 검증·메시징 API, XML/RDF/JSON 검증 가이드 | 정상·오류·경계 사례, 시험 입력, 예상 결과, 기관 간 메시지 순서, 재현 가능한 실행 증빙 |

## 7. 후속 확인이 필요한 자료

1. eIDAS 평가 보고서의 개별 본문과 첨부: 법적·조직적·의미적·기술적 영향이 실제로 어떻게 작성됐는지 확인한다.
2. Board 의제·회의록과 EIF 개정 관련 원문: 기존에 보유한 2025년 Blueprint 초안과 현재 정책 결정 자료를 구별한다.
3. 국가별 factsheet의 첨부와 원문 발행연도: 서로 다른 기준연도의 국가를 단순 비교하지 않도록 한다.
