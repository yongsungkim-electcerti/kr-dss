배경 — 설치형 보안 SW 철폐
금융당국은 설치형 보안 소프트웨어의 단계적 철폐를 추진 중이다.
기존 방식 — 설치형
• 사용자 단말에 별도 보안 프로그램 설치 요구
• 클라이언트 배포·업데이트·호환성 부담
• OS·브라우저 변화마다 재대응
• 검증 시스템은 단일 경로만 지원
Web A Sign — 무설치
• 브라우저 표준 API(WebAuthn)만으로 서명
• 클라이언트 추가 실행코드 없음
• OS·브라우저 내장 규격 활용
• 단일 검증 시스템에서 다중 유형 처리
WebAuthn은 사용자 인증(로그인·본인확인) 규격으로, 전자서명과 직접 결합하는 방법론은 정의되어 있지 않다. Web A Sign이 결합 방법론을 정의한다.

서명자

검증 경로
kr-dss-core가 Tester → 공동인증CA → KISA Root CA 경로를 신뢰 앵커까지 검증한다.
알고리즘: SHA256withECDSA / secp256r1. WebAuthn 자격증명 개인키는 인증기(브라우저/플랫폼)에 보관되고, 서버에는 공개키·인증서가 저장된다.
