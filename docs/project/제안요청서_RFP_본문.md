## Ⅱ. 제안요청 사항

### 추진 배경
- 전자서명법 개정 이후 다양한 전자서명 인증서가 도입되었으나, 활용이 대부분 단순 본인인증 용도에 편중
  - 전자서명(단순 로그인이 아닌, 전자문서(PDF, HWP 등) 자체에 서명 데이터를 결합하여 문서의 무결성·부인방지 기능을 제공하는 서비스: 전자계약, 증명서 발급 등) 활성화를 위해 다양한 서비스 이용환경(문서편집기, 문서 뷰어, 브라우저, 기안기, 서명앱 등)에서 상호호환 가능한 표준 전자서명 및 그 이용 기반 마련
- 인정제도를 운영 중이나 시스템적 연동 기능 부재(인정기관은 목록 홈페이지 게시, 사업자는 인증마크 부착에 그침)로 기술적 신뢰 검증 불가
  - 전자서명인증서비스 이용자가 신뢰성을 시스템적으로 검증할 수 있는 체계 마련

### 제안요청 내용
1. **국내 전자문서 서명 규격 표준(안) 설계 및 프로토타입 개발**
   - (현황 분석) 공공·금융·의료 등 분야별 전자서명 적용 현황 조사, 전자문서 규격·서명 데이터 저장 구조·패키징 방식 비교 분석
   - (표준 프로파일 설계) 서명 생성·패키징·검증 처리 규격 등 정의
   - (표준 모듈) 최소 기능 요구사항 도출 및 SDK 형태 프로토타입 구현
     - 생성: 원본 데이터 추출 + 인증서 결합 → 표준 규격 서명 생성 → 문서 주입
     - 추출: 뷰어에서 문서 열람 시 표준 프로파일 위치에서 서명 데이터 분리·추출
     - 검증: 서명 + 인증서 검증(인정사업자 발급 여부, 유효기간, 정책 등)
2. **신뢰검증체계(안) 설계 및 프로토타입 개발**
   - (신뢰목록 관리) 인정사업자 인증서 자동 수집, 유효성 주기적 동기화 관리 프로세스 설계
   - (한국형 신뢰목록) 국내 인정제도·이용환경 반영, 국제 표준(EU TL 등) 호환 가능한 규격 제시
   - (검증 모듈) 추출한 서명 데이터를 신뢰목록과 대조하여 인증서 신뢰성·문서 무결성 판별 검증 기능 프로토타입 구현
3. **프로토타입 실증(PoC) 및 시나리오 검증**
   - (End-to-End 실증) 표준 모듈로 서명 생성·패키징 → 서명 추출·신뢰목록 검증 전 과정 실증
   - (예외 처리) 오프라인 환경, 미등록 사업자 인증서 처리 등 예외 케이스 검증 정책 검토
   - 실증 연구 범위(발주기관과 협의 조정): 표준 전자서명 규격(PDF, HWP 등), 모듈 프로토타입(생성·추출, 신뢰목록 연동 등)
