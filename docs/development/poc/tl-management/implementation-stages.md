## 설계 계약 및 범위

- 기존 관리 대시보드·사업자 화면 유지. 신규 이용사 화면은 `/tl-poc.html`로 연결한다.
- TL 발행과 이용사 채택은 별도다. 서버에 사전 구성한 TL 앵커만 신뢰하며 업로드 TL의 인증서를 앵커로 승격하지 않는다.
- TL 적용은 서버가 서명·체인·현재 만료·순번을 검사한 후 수행한다. 원문 해시로 고정하고 실패 시 기존본을 유지한다.
- 실증 포맷은 PDF, 정책은 고정 PoC 정책. 폐지·신뢰 시각 증거는 미검증 표시한다. 시험 평가시각과 현재 TL 수신시각을 구분한다.
- 원문·실행 결과는 main 비관리 영역을 설정으로 지정한다. 개인키를 신규 API로 받거나 결과에 저장하지 않는다.
- 입력 제한: TL 5 MiB, PDF 25 MiB, 인증서 묶음 1 MiB. 단일 로컬 PoC이며 공개 서비스 배포를 포함하지 않는다.
- 중간 상태를 실증할 때 상태 변경마다 TL을 발행한다. 기존 발행 이력 모델 자체는 이번 차수에 변경하지 않는다.
- 단계별 결과: 무결성 / 인증 경로 / TL 신뢰 / 서비스 상태 / 미검증 항목. 미등재와 깨진 체인을 구분하며 정지 CA를 상위 Root로 우회하지 않는다.
- 비교 키: 문서 해시·평가시각·정책 버전·검증 엔진 버전. 다르면 TL 단독 효과 판정 불가.

## 보안·시험

TL 위조·앵커 바꿔치기 → 별도 서버 앵커 및 서명/PKIX 검사. 회귀·충돌 → 순번/해시 비교. 실행 중 교체 → 불변 스냅숏. 결과 혼동 → 실행 ID·조건 고정 및 불변 파일 저장. XML 외부 접근 차단, 크기 제한, 서버 생성 파일명 사용.

시험 및 증거는 차수별로 아래에 추가한다. 코드 존재만으로 통과를 기록하지 않는다.

### 1차 시험

`gradlew.bat :poc:poc-relying-party:test --tests '*tlpoc.TlAcceptanceTest'` 성공. 정상 적용·동일본 재적용·회귀·동일번호 충돌·만료·비신뢰·변조 거부·기존본 유지·스냅숏 고정·재시작 복원·만료 경계 확인. 초회 시험은 구형 상태 URI를 사용한 시험 자료 오류로 실패했고 PoC URI로 정정 후 재실행 통과.

### 2차 구체화

단일 PDF 서명(전체 파일 ByteRange, detached CMS)을 지원한다. 기존 PDFBox·BouncyCastle 고정 버전으로 무결성을 직접 검사하고 Java PKIX로 TL 신뢰점 경로를 검사한다. 기존 DSS 종합 결과를 서명 무결성으로 오인하지 않도록 실증 전용 경로를 분리한다. 다중 서명·증분 변경·폐지·시각 증거는 이번 정책에서 지원하지 않는다.

## 차수 내 병렬 작업 경계

1차: 수신·적용 서비스 / 검증 진입부 / 적용 화면 / 실패 시험. 2차: PDF 무결성 / 경로·상태 / 결과 화면 / 대조 시험. 3차: 저장소 / 비교 로직 / 비교 화면 / 통합 시험. 공통 응답 모델은 한 담당자가 관리하고 같은 파일을 동시 편집하지 않는다. 이번 실행은 단일 에이전트가 차수 순서대로 수행했다.

## 확인 범위와 남은 검증

핵심 경로 개발 완료와 전체 요구 10개·시험 후보 25개의 승인/충족은 다르다. 메모리·시간 공격의 부하 시험, 30초 취소 경계, 모든 실패 복구 조합, 원본 시나리오의 정식 인수 승인은 별도 미검증이다. FUN-023 증거 묶음 다운로드·FUN-024 재실행 버튼은 이번 1~3차 대상이 아니다. 현재 실행 폴더는 재현 자료로 보존한다.
