# Windows 로컬 배포 패키지 준비

2026-10-28 사용자 위임 범위: 1. 대상 확인, 2. 패키지 구성, 3. 기존 프로젝트 PoC 프로세스 종료. 배포본 실행·기능 검증은 사용자가 수행한다. 관리 시스템 매뉴얼과 API 연계 매뉴얼은 그 이후 작성한다.

## 구성 결정

- 산출 위치: `outputs/TrustList-PoC-Windows-20261028/` 및 같은 이름의 ZIP. 배포 JAR·시험키·ZIP은 Git 비관리이며 재생성 스크립트는 Git 관리한다.
- 설계·엑셀·개발 문서: 기존 `docs/`에서 관리한다. `outputs/`는 실행용 배포물 전용이다.
- 실행 모듈: 관리 서버 `poc-kisa-tl`, 검증 작업대 `poc-relying-party`의 Spring Boot 실행 JAR. 의존 라이브러리는 JAR 내부에 포함한다. 외부 사업자·RSSP·SAM·HSM 서비스는 이번 파일 기반 PoC 실행 대상에서 제외한다.
- 환경: Windows, Java 21, PowerShell 5.1 이상. Java는 별도 설치하며 Gradle·소스는 수신자에게 필요하지 않다.
- 기본 포트: 관리 18081, 검증 18082. loopback만 바인딩한다. 기존 8081 Python 서버는 다른 프로젝트이므로 종료하지 않는다.
- 데이터와 로그: 패키지 내부 data/logs/run. 사용자 추가 요청에 따라 main 초안 r15의 사업자 4개·서비스 10개와 공개 인증서를 배포 초기 revision 1로 포함한다. 과거 이력·발행본·개인키·로그는 포함하지 않는다.
- 시험 자료: 전용 PKI로 새 TL 2개·PDF·CA 인증서·TL 앵커·관리 발행용 서명키를 생성한다. 시연 키임을 명시하며 운영에 사용하지 않는다. 사용자의 기존 키를 읽거나 복사하지 않는다. 검증 JAR의 기존 PoC 리소스도 데모용이며 제품용 인증·권한 기능으로 취급하지 않는다.

## 실행 스크립트 계약

시작 전 Java 버전·포트·파일을 확인한다. 경로는 스크립트 위치를 기준으로 계산한다. 백그라운드 프로세스의 PID와 임의 토큰을 저장하고 종료 시 Java 실행 파일·토큰·JAR 경로를 대조한다. 포트만으로 다른 프로세스를 종료하지 않는다. 기동 확인은 각 모듈의 실제 API 응답 구조로 한다. 일부 서비스 기동 실패 시 이번 실행에서 시작한 프로세스만 종료한다.

`Start-Poc.cmd` / `Stop-Poc.cmd` / `Status-Poc.cmd` 및 대응 PowerShell 파일을 제공한다. 상세 매뉴얼 대신 실행에 필요한 최소 안내만 README.txt에 포함한다. 패키지 실행·재시작·복구 시험은 사용자 실행 대기 상태다.

## 재생성

```powershell
./scripts/distribution/Build-TlPocDistribution.ps1
```

새 출력 폴더에서 빌드와 시험 자료 생성 후 패키징하며 기존 패키지를 덮어쓰지 않는다. `package-manifest.json`에 소스 커밋·수정 여부·의존 JAR 목록·파일 해시·미실행 상태를 기록한다. SHA256SUMS.txt와 ZIP 해시도 제공한다.

이번 작업의 완료 기준은 실행 JAR 구성, PowerShell 구문 검사, 패키지/ZIP 파일 일치 및 원치 않는 개발 경로·실행자료 미포함 확인, 기존 프로젝트 PoC 프로세스 종료다. 이를 배포본 기능 검증 통과로 보고하지 않는다.

## 준비 결과

- 실행 JAR 2개 빌드 및 전용 시험 자료 생성 완료. 배포 폴더 21개 파일과 ZIP 내용 일치, manifest 등록 19개 파일 해시 일치 확인.
- 포함 PowerShell 4개 구문 검사 통과. Java 서버 기동 및 배포본 기능 시험은 수행하지 않았다.
- ZIP 크기 85,109,300 bytes. SHA-256: `65f5d787d399b5c77ad34b843c95f6c6b4d1c95f8cf3ef9b830f04a702035010`.
- 시험 평가시각: `2026-10-27T00:00:00Z`. 시험 TL NextUpdate: `2027-04-25T17:00:14.789597Z`.
- 기존 프로젝트 PoC 서버 4개(8082, 18081, 18082, 18083)를 경로·Application 클래스로 식별 후 종료. 종료 후 해당 작업공간의 PoC 프로세스 0개 확인. 다른 프로젝트 Python 서버는 유지.
- 현재 PC의 기본 Java는 17이다. 사용자 실행 전 Java 21을 JAVA_HOME 또는 config.json의 javaHome으로 지정해야 한다. 배포 패키지에는 개발 PC의 절대 JDK 경로를 넣지 않는다.
- 배포본 사용자 실행 결과 확인 후 관리 시스템 매뉴얼 및 API 연계 매뉴얼을 작성한다.

기본 검증 서버 index.html에 TrustList 검증 작업대 카드 링크를 추가하고 배포 JAR/ZIP에 반영했다. 현재 PC의 Java 설정과 사용자 data는 유지하며 ZIP에는 사용자 실행 데이터를 넣지 않았다. 실행 중 서버 반영에는 재시작이 필요하다.

사용자 추가 요청 반영: 현재 실행 중인 배포 관리 서버의 빈 초안을 main _backup/2026-10-28-distribution-before-seed에 보존한 뒤 관리 API로 사업자 4개·서비스 10개를 등록했다. 이름·유형·인증서 SHA-256이 main 원본과 일치함을 확인했다. ZIP은 같은 내용을 신규 초기 r1로 포함하며, 현재 실행본은 등록 결과 r15다. 등록 자료와 signed.pdf의 시험 CA는 서로 다르므로 관련 안내를 README에 명시했다.
