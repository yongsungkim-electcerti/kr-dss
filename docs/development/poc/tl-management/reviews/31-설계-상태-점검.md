# 31. TL 관리 PoC 설계 상태 점검

후속 갱신(2026-10-09): 아래 표는 상세 보완 전 점검 기록이다. 이후 사용자 요청으로 [PoC 적용 기준](../../../../design/poc/tl-management/concept-v02-application.md), [프로파일 v1](../../../../design/poc/tl-management/profile-poc-v1.md), [발행·복구 상세](../../../../design/poc/tl-management/issuance-recovery.md)를 작성했다. 신뢰점 레벨·임시 URI·실패 복구는 이 문서들로 구체화했다. 공식 URI 공표, 전체 XSD·소비자 호환성, 실제 장애 복구 시험은 완료되지 않았다.

점검일: 2026-10-09. 이번 작업은 개념 설계 보관·영향 검토·인계 문서 정리이며 제품 코드 변경은 없다. 수정 개발은 다음 세션에서 진행한다.

## 현재 판정

**개념 설계 검토와 개발 범위 정리는 완료했다. 상세 구현 설계는 일부 보완이 필요하며, 실제 관리 기능 구현은 후속 작업이다.** 문서가 있다는 사실을 기능 개발 완료로 판단하지 않는다.

| 영역 | 설계 상태 | 다음 세션 작업 |
|---|---|---|
| PoC 범위·책임 | 확정 | TL 관리에 집중. HSM·별도 WEB·권한·감사 제외, 심사는 메뉴만 제공 |
| 개정 개념 설계 v02 | 수집·검토 완료 | 전체 운영 설계와 PoC 예외 적용표를 연결 |
| 공통 이력·버전 모델 26 | 상세안 작성 완료, 구현 전 | 형식 버전/순번, current/history, 다중 인증서·서비스 식별자 구현 |
| 키 파일·체인 설계 27 | 상세안 작성 완료, 실제 키 생성 전 | TL 체인과 사업자 체인을 분리하여 생성·검증 |
| 초안·스냅숏·발행본 저장 | 기본 구조 확정, 실패 복구 계약 보완 필요 | 요청 중복·동시 발행·서명 후 저장 실패·재기동 처리 명시 |
| IF-07 계약 28 | 상세안 작성 완료, 관리 WAS 제공 구현 전 | 불변 XML·해시·ETag/304와 제공본 선택 연결 |
| 오류 TL 제공 | 기존 사용자 결정으로 확정 | 개념 설계의 정상 게시 정책과 다른 시험 예외임을 명시 |
| 상태 URI·KR 확장 | 의미와 보존 원칙 정의, 구체 매핑 보완 필요 | 임시 PoC 값과 공표 값을 구별하고 미지원 상태 자동 치환 제거 |
| 신뢰점 레벨 | 본문·그림 표현 정합성 검토 필요 | CA 레벨과 OCSP/TSA의 등재·연결 정책을 구별 |
| 관리 화면 | 과거 화면안·시연 API 존재, 실데이터 연결 전 | 발행 성공·현재 제공본·사전 검사·외부 검증 결과 구분 |
| 상세 시나리오·시험 시계·표본 | 기존 결정에 따라 유보 | 별지 기대 결과를 시험 성적으로 사용하지 않음 |
| 자동 재발행 | 이번 범위의 완료 기준 미확정 | 기한 표시·수동 재발행과 무인 스케줄러를 구별 |

## 적용 우선순위

1. [사용자 확정 PoC 범위](../../../../design/poc/tl-management/scope.md).
2. [기존 구현 차이 검토 25](25-PoC-구현-차이-검토.md)의 사용자 결정 D-01~06.
3. 공통 모델 26·키 파일 27·IF-07 계약 28과 현재 저장·발행 설계.
4. [개정안 영향 검토 30](30-수정-개념설계-v02-영향검토.md)의 보완 제안. 제안과 미결 사항을 자동으로 확정 범위에 편입하지 않는다.

개정 원문은 전체 목표 시스템을 설명한다. 본문에 HSM·심사·별도 WEB·권한 관리가 존재한다는 이유로 PoC 범위를 확대하지 않는다. 원격 개념 문서와 기존 상세 설계는 이번에 수정하지 않았으므로, 영향 검토서의 조치가 이미 반영되었다고 가정하지 않는다.

## 다음 세션 시작점

1. 개정안의 PoC 적용표와 의미 오류 제공 예외를 상세 문서에 반영한다.
2. 구현할 필드의 URI·확장·신뢰점 레벨 매핑과 발행 실패 복구 계약을 정리한다. 정책 결정을 요구하는 불명확한 부분은 임의로 확정하지 않는다.
3. 공통 모델과 XML 변환부터 시작해 관리 API·영속 저장 → 실제 서명·발행 → 불변 보관·IF-07 → 관리 화면 순으로 구현한다.
4. 버전/순번 왕복, 상태 경계, 키 갱신/교체, 실패 시 성공 표시 금지, 오류본 제공과 동일본 재전송을 확인한다.

보관된 개정안은 표 23개·삽입 그림 13개를 포함한다. HTML·그림의 SHA-256과 로컬 참조 링크를 확인했다. 최신 이용 시나리오 별지·draw.io 원본까지 새로 취득한 것은 아니다.

커밋 전 `gradlew.bat build` 통과: 163개 작업 중 1개 실행, 162개 최신 상태. 기존 결과를 재사용한 빌드이며 새로운 PoC 기능 시험을 수행한 것은 아니다. 제품 코드 변경 없이 문서와 원문 보관 자료만 커밋한다.
