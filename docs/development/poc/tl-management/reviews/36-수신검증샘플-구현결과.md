# 36. TL 수신 검증 샘플(PDF 뷰어·이용기관) 구현 결과

작성일: 2026-10-09. 브랜치 `feat/claude-tl-admin`. 사용자 지시: PDF 뷰어가 IF-07로 TL을 받아 검증하는 샘플 코드를 만든다. HTTP GET으로 받고, 실제 PDF 검증은 하지 않으며 TL 관련 검증 단계만 수행한다.

## 결과물

- `src/poc/tl-viewer-sample/` — 빌드 없는 정적 샘플. `krtl-verifier.js`(재사용 검증 모듈), `index.html`(화면), `README.md`(실행·단계·사유 코드·한계).
- 브라우저 DOMParser·WebCrypto만 사용한다. DER/X.509 최소 해석, exclusive C14N, ECDSA/RSA 검증을 직접 구현했다.

단계별 확인 내용과 사유 코드는 샘플 README에 정리했다. 신뢰앵커는 사전 설정한 KISA TL RootCA(T-00)이며 서버에서 받지 않는다. 수용본과 거부본을 분리하고, 조건부 GET은 수용본 ETag로만 보낸다.

## 발행 서명 수정 (TS 119 612 Annex B.1.0)

샘플 작성 중 기존 발행 서명이 Annex B.1.0을 따르지 않음을 확인했다. DSS 기본값이 `URI=""`와 XPath Filter 2.0 transform을 썼다. 표준은 다음을 요구한다.

- TL 루트를 가리키는 Reference
- Transform은 enveloped-signature, exc-c14n 두 개만
- CanonicalizationMethod는 exc-c14n

`KrTrustListXmlSigner`를 `URI="#kr-tl"`, enveloped-signature → exc-c14n, SignedInfo·SignedProperties exc-c14n으로 바꿨다. 자체 확인(`check`)도 이 구조를 검사하도록 바꿨다. 이 수정 이전 서명 발행본은 샘플에서 `SIGNATURE_INVALID`로 거부된다. 실제 runtime에는 그런 발행본이 없다. 시험 저장소에서만 생겼다.

## 검증

- `gradlew.bat build` 통과. kr-tl-builder 서명 시험에 Annex B 구조 확인 1건을 추가했다.
- 실제 PoC 키(T-02 서명, T-00 앵커)로 TL 관리 PoC(:18081)와 샘플(jwebserver :18095, 다른 origin)을 띄워 Chrome에서 확인했다.

| 제공본 | 기대 | 결과 |
|---|---|---|
| 수정 전 서명(filter2) 순번 2 | 거부 | SIGNATURE_INVALID (Reference 구조) |
| 수정 후 BASELINE 순번 3 (최초) | 수용 | 9단계 통과, 보유본 대비 ‘최초 수신 비교 불가’ 표시 |
| 같은 제공본 재조회 | 304 | 보유본 재검증 후 유지 |
| TRIAL 순번 1 | 거부 | SEQUENCE_ROLLBACK, 보유본 3 유지 |
| TRIAL 순번 3 다른 내용 | 거부 | SEQUENCE_CONFLICT |
| TRIAL 발행 시각 미래 | 거부 | ISSUE_TIME_IN_FUTURE |
| 보유본 발행 이전으로 소급 정지 | 거부 | RETROACTIVE_STATUS_CHANGE |
| NextUpdate 경과 | 거부 | TL_EXPIRED (+ 소급) |
| BASELINE 순번 4 (상태 변경, 이력 1) | 수용 | 순번 3→4, 이력 1구간 |
| 서비스 조회 JA-01, 변경 전 시각 | 인정(이력 구간) | 인정 10-01부터 변경 효력 시각까지 |
| 서비스 조회 UN-01 | 미등재 | TL 미등재 |

참조 다이제스트 일치로 브라우저 exclusive C14N이 Java(DSS) 정규화와 같은 바이트를 만든다는 것을 확인했다. `.sha2` 대조와 CORS(다른 origin, If-None-Match preflight)도 동작했다.

## 한계

- 데모용 최소 PKIX다. 폐기 확인, 이름 제약, 정책 처리가 없다.
- XSD 전체 검증이 없다.
- 실제 PDF 뷰어 제품과 KR-DSS SDK(Java) 수신 모듈 연동은 하지 않았다. 이 샘플은 같은 단계를 SDK·뷰어에 옮길 때의 기준 구현이다.
- 첫 Chrome 탭이 응답하지 않거나 그룹에서 빠지는 확장 측 문제가 있어 새 탭에서 확인했다. 기능 결과는 DOM 값으로 확인했다.
