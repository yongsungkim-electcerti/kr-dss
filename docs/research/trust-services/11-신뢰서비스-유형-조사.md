# 11. 신뢰서비스 유형 조사 — EU 서비스 유형과 국내 신뢰서비스

> 자료 분류: 기존 상세 설계·검토 자료. 현재 PoC 구현 범위는 [확정 범위](../../design/poc/tl-management/scope.md)를 우선한다. 고정 시나리오·HSM·별도 WEB 등은 현재 필수 개발로 간주하지 않는다.

> [10 TL 구조](../../design/common/kr-tl/10-TL-구조.md) §3.4 서비스 유형(N-05)의 근거 자료다.
> EU 쪽은 ETSI TS 119 612 v2.4.1 §5.5.1(저장소 참조문서 원문), 국내 쪽은 법령과 운영 기관 공개 자료를 기준으로 정리했다. 조사일: 2026-10-05.

## 1. EU 서비스 유형 (TS 119 612 §5.5.1)

EU TL은 서비스 유형 URI(`http://uri.etsi.org/TrstSvc/Svctype/…`)로 서비스의 **기능**과 **적격(Q) 여부**를 함께 나타낸다. 적격 서비스는 eIDAS가 정한 요건을 갖춘 서비스이며, `/Q` 또는 `/QC`가 붙는다.

### 1.1 기능별 정리

| 기능 그룹 | 유형 URI (`Svctype/` 이하) | 내용 |
|---|---|---|
| **인증서 발급** | `CA/QC` · `CA/PKC` | 적격 / 비적격 인증서 발급 |
| | `NationalRootCA-QC` | 국가 루트 CA |
| | `CA/PKC/CertsforOtherTypesOfTS` | 다른 신뢰서비스용 인증서 발급 |
| **인증서 상태** | `Certstatus/OCSP` (`/QC`) · `Certstatus/CRL` (`/QC`) | OCSP 응답, 폐지 목록 |
| **시점 확인** | `TSA` · `TSA/QTST` | 비적격 / 적격 타임스탬프 |
| | `TSA/TSS-QC` · `TSA/TSS-AdESQCandQES` | 인증서·서명 관련 타임스탬프 |
| **전자 배달 (EDS)** | `EDS` · `EDS/Q` | 전자 등기 배달 (적격은 송·수신 사실과 시각에 법적 추정) |
| | `EDS/REM` · `EDS/REM/Q` | 전자 등기 메일 |
| **보존 · 보관** | `PSES` · `PSES/Q` | 전자서명·인장의 장기 보존 (서명 유효성을 장기간 유지) |
| | `PKCPreservation` | 인증서 보존 |
| | `ElectronicArchiving` · `ElectronicArchiving/Q` | 전자 문서 보관 (eIDAS 2.0) |
| | `Archiv` | 국가 정의 보관 서비스 |
| **검증** | `QESValidation/Q` | 적격 전자서명·인장 검증 |
| | `AdESValidation` | 고급 전자서명·인장 검증 |
| | `PKCValidation` · `TSTValidation` | 인증서 검증 · 타임스탬프 검증 |
| | `EDSValidation` · `EAAValidation` | 배달 증거 검증 · 속성 증명 검증 |
| **서명 생성** | `AdESGeneration` | 고급 전자서명 생성 |
| | `RemoteSigCDManagement` (`/Q`) · `RemoteSealCDManagement` (`/Q`) | 원격 서명·인장 생성 장치 관리 (원격서명) |
| **속성 증명 (EAA)** | `EAA` · `EAA/Q` · `EAA/Pub-EAA` | 전자 속성 증명 발급 (비적격 / 적격 / 공공기관 원천 정보 기반) |
| **전자 원장** | `Ledgers` · `Ledgers/Q` | 전자 원장 기록 (eIDAS 2.0) |
| **국가 정의** | `RA` · `ACA` · `SignaturePolicyAuthority` · `IdV` · `KEscrow` · `PPwd` · `TLIssuer` · `unspecified` | 등록기관, 속성 인증기관, 서명정책 기관, **신원 확인**, 키 위탁, 비밀번호 기반, TL 발행자 등 |

### 1.2 특징

- 적격 여부를 서비스 유형에 넣는다 (`/Q`). 그래서 같은 기능도 유형이 둘로 나뉜다.
- eIDAS 2.0에서 EAA, 전자 보관, 전자 원장이 새 신뢰서비스로 추가되었다.
- 국가가 따로 정의한 서비스(`IdV` 등)도 TL에 실을 수 있다.

## 2. 국내 신뢰서비스 현황

국내 신뢰서비스는 **근거 법과 지정·인정 주체가 서비스마다 다르다.**

| 분야 | 서비스 | 근거 법 | 지정·인정 | 주요 기능 |
|---|---|---|---|---|
| 전자서명 인증 | 인정 전자서명인증사업자 (공동인증 · 간편인증 등) | 전자서명법 §8·§9 | 인정기관 KISA (평가기관: TTA · 금융보안원 · 회계법인) | 인증서 발급, 상태 확인, 시점 확인 |
| 행정 전자서명 | 행정전자서명 인증 (GPKI) | 전자정부법 | 행정안전부 | 행정기관 인증서 |
| 시점 확인 · 진본 확인 | 전자문서진본확인센터 (GTSA) | 전자정부법 | 행정안전부 | 타임스탬프 발급, 진본성 검증, 장기 검증 |
| 본인 확인 | 본인확인기관 | 정보통신망법 §23조의2·3 | 방송통신위원회 지정 | 주민번호 대체 수단으로 본인 확인 |
| 전자문서 보관 · 증명 | 공인전자문서센터 | 전자문서법 §31조의2 | 과학기술정보통신부 지정 | 보관 기간 중 내용 불변 추정, 보관·송수신 사실 증명서 발급 |
| 전자문서 유통 | 공인전자문서중계자 (공인전자주소) | 전자문서법 §31조의18 | 과학기술정보통신부 지정 | 송·수신 중계, 유통증명서 |
| 전자화 | 전자화작업장 | 전자문서법 | 정부 지정 | 종이문서를 전자화문서로 변환 |
| 전자증명서 | 행정기관 전자증명서 · 전자문서지갑 | 전자정부법 | 행정안전부 | 증명서 전자 발급, 진본 검증 |
| 모바일 신분증 | 모바일 신분증 | 전자정부법 등 | 행정안전부 | 신원 정보의 디지털 제시·검증 |

## 3. EU 유형과 국내 서비스 대응

KR-TL 유형 이름은 국내 명칭에 맞춘다 (S-01). 전체 코드 목록은 [10 TL 구조](../../design/common/kr-tl/10-TL-구조.md) §3.4.

| EU 기능 그룹 | 국내 대응 | 근거·주체 | KR-TL 유형 | 구분 |
|---|---|---|---|---|
| 인증서 발급 | 인정 전자서명인증사업자 CA | 전자서명법 · KISA | 인증서 발급 (`CA`) | 1차 |
| 인증서 상태 | 인증사업자 OCSP · CRL | 전자서명법 · KISA | 인증서 상태 확인 (`OCSP`) · 폐지 목록 (`CRL`) | 1차 · 정의 |
| 시점 확인 | 인증사업자 시점확인 | 전자서명법 · KISA | 시점확인 (`TSA`) | 1차 |
| 서명 생성 (원격) | 원격서명 | 전자서명법 · KISA | 원격서명 (`RemoteSign`) | 예약 |
| 신원 확인 (IdV) | 본인확인기관 | 정보통신망법 · 방통위 | 본인확인 (`IdCheck`) | 예약 |
| 보존 · 보관 | 공인전자문서센터 | 전자문서법 · 과기정통부 | 전자문서 보관 (`DocArchive`) | 예약 |
| 전자 배달 (EDS) | 공인전자문서중계자 | 전자문서법 · 과기정통부 | 전자문서 중계 (`DocRelay`) | 예약 |
| (해당 없음) | 전자화작업장 | 전자문서법 | 전자화 (`Digitization`) | 예약 |
| 검증 | 전자문서진본확인센터 (GTSA) | 전자정부법 · 행안부 | 진본확인 (`DocVerify`) | 예약 |
| 속성 증명 (EAA) | 전자증명서 | 전자정부법 · 행안부 | 전자증명서 (`eCert`) | 예약 |
| 속성 증명 (EAA) | 모바일 신분증 | 전자정부법 등 · 행안부 | 모바일 신분증 (`MobileID`) | 예약 |
| 전자 원장 | 해당 없음 | — | — | 범위 밖 |
| TL 발행자 | KISA | — | 발행 정보의 운영자 | — |

## 4. KR-TL에 주는 시사점

1. **1차 범위는 전자서명법 인정 서비스(CA · OCSP · TSA)로 한정한다.** 인정 주체가 KISA이므로 KR-TL 운영자와 같다.
2. **다른 신뢰서비스는 근거 법과 주체가 다르다.** 보관·중계(과기정통부 지정), 본인확인(방통위 지정), 전자증명서·GTSA(행안부)는 **KR-TL 구조에 포함할 수 있는 예약 유형**으로만 정의한다. PoC에서는 실행하지 않는다.
3. **국내는 적격 / 비적격 구분이 없다.** 인정 여부를 상태로 나타내고, 서비스 유형은 기능만 나타낸다 (10 §3.4).
4. **EU 2.0의 확장 방향(EAA · 보관 · 원장)과 국내 전자증명서 · 공인전자문서 제도가 겹친다.** 국제 연동 시 대응 관계를 설명할 수 있도록 대응표를 유지한다.

## 5. 결정 사항 (2026-10-05)

| ID | 항목 | 결정 |
|---|---|---|
| S-01 | 예약 유형의 이름과 범위 | **국내 유형에 최대한 맞춘다** — 원격서명, 본인확인, 전자문서 보관, 전자문서 중계, 전자화, 진본확인, 전자증명서, 모바일 신분증 |
| S-02 | 본인확인 표현 위치 | **서비스 유형으로 표현** (`IdCheck`). 신뢰 분야에서는 뺀다 |
| S-03 | 타 기관 서비스 등재 | 절차는 지금 정하지 않는다. **"KR-TL 구조에 포함할 수 있다"는 개념으로만** 정리하고, PoC에서 등재·실행하지 않는다 |
