## Part 1 · KpqC-HSM 소개 (7페이지)

**핵심 메시지**: "양자내성 **서명**(ML-DSA) + 양자내성 **키교환**(ML-KEM) + **FIPS 140-3 Level 3** — 셋을 따로가 아니라 **한 대(KpqCHSM)로 통합**"

| # | 페이지 | 핵심 내용 | 근거 |
|---|---|---|---|
| P1-1 | 표지·한 줄 정의 | "FIPS 140-3 + 양자내성암호(서명·키교환)를 한 장비로" | p01 |
| P1-2 | 왜 지금인가 | ① 규정: 평가기준 해설서 6.5/6.9/7.1 → FIPS 140-2 만료 **2026.9.21**(Historical), 검증 평균 542일 ② 정책: 범국가 PQC 전환('35), 시범전환 5대(통신·금융·교통·국방·우주)에 전자서명 포함 | p03 |
| P1-3 | 문제 — 따로 가면 이중·삼중 도입 | 전자서명은 HSM 내부에서 발생 → 알고리즘 교체 = HSM 교체. 140-3 따로 + PQC 따로 = 장비·검증·도입 2회 + 운영중단 2회. 외산 140-3 HSM은 ML-* 위주 → 국산 KpqC 못 씀(주권·선택권 제약) | p04·p05·p06 |
| P1-4 | 해법 — 3중 통합을 1대로 | **KpqCHSM = PCIe(FIPS 140-3 즉시) + HW-TEE(PQC 펌웨어 업그레이드, 장비교체 X)**. 단계 분리가 핵심 → "PQC 표준 미확정" 반론 무력화 | p05·p08 |
| P1-5 | 구성도 | CA → PKCS#11 분기 → PCIe(ML-KEM/ML-DSA·RSA/ECC, FIPS 140-3 L3) / HW-TEE(KpqC Library). 플랫폼=KTNF(국산). 요소별 역할표 | p09 |
| P1-6 | 사업자에게의 의미 | 도입 **1회**로 140-3+양자내성 통합, **내년(2027) 상반기** 완료. 외산 종속 대신 국산 KpqC 선택권 | p04·p10 |
| P1-7 | Takeaway (홍보 3줄) | ① "9월에 140-3만 급히 끝내지 말고 양자내성까지 한 번에" ② "KpqCHSM 1대로 이중 전환비용 제거" ③ "국산 KpqC로 암호 주권 확보" | p10·p11 |

> ⚠ 방향·검수 필요 표기: 제품 세부 사양(ML-KEM-768/1024, ML-DSA-65/87, KTNF +0.5개월 등)은 **실제 사양 검수 필요** → "예시/방향"으로 표기. 유예는 **인정심사위 검토 대상(제안)**임을 명시.

## Part 2 · Web A Sign 소개 (7페이지)

**핵심 메시지**: "**금융 설치형 보안 SW 철폐**에 대한 답 — 설치 프로그램 없이 **브라우저(WebAuthn)만으로** 전자문서에 서명을 결속하고 검증한다"

| # | 페이지 | 핵심 내용 | 근거 |
|---|---|---|---|
| P2-1 | 표지·한 줄 정의 | "설치 SW 없이 브라우저만으로 전자문서에 서명 — Web A Sign" | 명세서 §효과① |
| P2-2 | 왜 지금인가 | **금융당국의 설치형 보안 SW 단계적 철폐** = 사업자 당면 대응 이슈. 기존 전자서명은 단말에 별도 보안프로그램 설치 요구 → 웹 표준(WebAuthn)만으로 대체 필요 | 명세서 배경 |
| P2-3 | 핵심 아이디어 — 3요소 결속 | 전자문서·서명시각·서명자 인증서를 **단일 WebAuthn Challenge에 암호학적 결속**(Signature Binding). `Challenge = SHA-256(DER(SignedAttrs))` → 문서 전용성 확보, 재사용·문서대체 공격 원천 차단 | 명세서 §1, 설계서 §3 |
| P2-4 | 어떻게 동작하나 | 등록(패스키/CA 발급 인증서) → 서명(브라우저 `credentials.get`, 어서션이 곧 전자서명) → 검증(challenge 재계산 + COSE 실검증). HSM 미사용(Mode 1) | 설계서 §2·§5 |
| P2-5 | 무엇이 새로운가 | 정책 기반 **검증 라우터**: 인증서 정책 OID로 WebAuthn/HSM/표준서명 **단일 시스템 분기**. 판정 3분류(TOTAL_PASSED / INDETERMINATE / TOTAL_FAILED). 암호 민첩성·컨테이너 독립성 | 명세서 §효과②③④⑤ |
| P2-6 | 실증 현황 | PoC에서 등록→서명→검증 **E2E 동작 확인**(판정 `TOTAL_PASSED`, path=WEBAUTHN). 정식 CMS 컨테이너 승격 완료 | 진행상태.md, HANDOFF |
| P2-7 | Takeaway (홍보 3줄) | ① "설치형 보안 SW 없이 브라우저만으로 전자서명" ② "문서·시각·서명자 3요소 결속으로 위·변조·재사용 차단" ③ "이미 E2E로 동작 확인" | 명세서 효과 |

> ⚠ 표기: Web A Sign은 **PoC 실증 단계**(상용/표준 확정 아님). Mode 1(WebAuthn 로컬) 중심 소개, SM3 등 일부는 예약/미구현으로 표기.

### 코드로 확정한 사실 (표현 확정 근거)
- **poc-tsp-sim(:8082) 실시간 호출 여부 = 호출 안 함.**
  `WebAuthnDemoCa`(poc-relying-party)가 `classpath:pki/joint-ca.p12`를 **인프로세스 로드** →
  `CertificateAuthority.issue(publicKey, "KR-DSS WebAuthn Signer", …, POLICY_WEBAUTHN, 365d)`로 Tester 인증서 직접 발급.
  Mode1 경로(`rp/local/*`)에 RestTemplate/WebClient/:8082 호출 없음(오직 allowed-origins `:8080`).
  poc-tsp-sim은 **별도 사본 joint-ca.p12를 로드하는 보조(설명용) 서비스**(OCSP/RA 시연용) — 핵심 경로 아님.
- **실제 인증서 체인** (`joint-ca.p12`, storepass `changeit`, keytool 확인):
  - KISA Root CA — Subject `CN=New-KISA RootCA, O=KISA, C=KR` · Issuer **Self(자가서명)** · SHA256withECDSA/secp256r1 · ~2046
  - 사업자 CA — Subject `CN=공동인증CA, O=KISA, C=KR` · Issuer `CN=New-KISA RootCA` · ~2036
  - Tester — Subject `CN=KR-DSS WebAuthn Signer` · Issuer `CN=공동인증CA` · Policy `POLICY_WEBAUTHN` · 365일 (런타임 발급)
- **개인키 표기**: WebAuthn 표준상 자격증명 개인키는 인증기(브라우저/플랫폼) 보관, 서버에는 공개키·인증서 저장.
  "개인키가 서버에 절대 저장되지 않는다" 식 단정 표현은 사용하지 않음(참조 §7 지침).
- **내일 시연 제외 범위**(회색/향후 확장): KR-TL 운영 · 폐지/복원 · Multi-RA · HSM Attestation · LT/LTA · 6종 포맷.
