1. 문제와 목표

사용자는 전자서명이 포함된 문서를 열어도 서명의 암호학적 유효성, 문서 변조 여부, 인증서비스의 KR-TL 등록 상태를 구분하기 어렵습니다. 본 PoC는 이 판정을 이해하기 쉬운 사용자 경험으로 제공하는 것을 목표로 합니다.

사용자 가치

  • 문서 변경 여부를 즉시 확인
  • 서명과 인증서비스 신뢰를 분리 이해
  • 문제 발생 시 다음 조치 확인

사업 가치

  • KR-AdES 표준 적용성 검증
  • 웨일–SDK 연동 타당성 확보
  • 상용화 제약과 확장 범위 식별

비목표

  • 네이버의 검증 알고리즘 자체 개발
  • 1단계에서 모든 문서 포맷 지원
  • KR-TL 미등록을 위조로 단정

2. 사용자와 핵심 시나리오

사용자필요성공 결과
일반 사용자받은 계약서가 서명 후 변경되지 않았는지 확인종합 판정과 쉬운 설명을 확인한다.
업무 담당자서명자·인증서·정책의 근거 확인세부 판정과 결과코드, 보고서를 확인한다.
실증 운영자오류를 재현하고 연동 품질 측정환경·시각·요청 ID·SDK 결과코드를 확보한다.

3. 책임과 범위

주체책임
네이버웨일의 문서 선택·권한 동의·SDK 연동 지점·결과 UI·실증 환경
일렉서티검증 SDK·판정 로직·결과 스키마·샘플 문서·기술지원
KISAKR-TL 데이터·배포 및 갱신 정책·신뢰목록 운영 기준

4. 성공 지표와 출시 기준

  • 정상·변조·KR-TL 미등록·오프라인·서명 없음 시나리오의 기대 결과가 100% 재현된다.
  • 문서 무결성, 서명, 인증서, 인증서 경로, KR-TL, 정책 판정이 독립적으로 표시된다.
  • 원문 외부 전송과 민감정보 로그 기록 없이 동작한다.
  • 검증 실패가 문서 열람 실패 또는 브라우저 보안 경고로 오인되지 않는다.

기능명세

네이버 구현·협조 범위를 시험 가능한 요구사항과 수용 기준으로 정의합니다.

STEP 3SDK 검증

STEP 4종합 결과

유효·경고·검증 불가 상태를 확인한다.

STEP 5상세·다음 조치

근거, 결과코드와 보고서를 확인한다.
