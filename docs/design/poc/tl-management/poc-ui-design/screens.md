# 화면설계 — 4개 작업 화면

사용자는 로컬 실증 담당자이다. 기존 관리 현황판·사업자 화면은 시연용으로 유지한다. 실제 검증 작업대(tl-poc.html)는 TL 적용·서명 검증·결과 비교의 세 탭으로 구성하며, 아래 네 화면은 전체 설계 분류다. 인증 경로·적용 TL·분리 판정이 시각적 중심이다.

## 공통 동작

- 미실행은 회색, 판단 보류는 황색, 확인된 실패는 적색, 개별 통과는 녹색과 문구를 함께 쓴다. 색만으로 구분하지 않는다.
- 버튼 처리 중 중복 클릭을 막고 처리 단계를 표시한다. 오류는 입력 옆 설명과 화면 내 요약에 함께 표시한다. 오류 시 이전 적용 TL·결과를 무단 삭제하지 않는다.
- 입력 변경 후 과거 결과는 과거 run으로 남기며 현재 입력의 결과인 것처럼 표시하지 않는다.
- 키보드 탭 이동·명시적 label·focus 표시, 1280px 작업 화면과 좁은 화면의 세로 재배치를 제공한다. 긴 해시·표는 자체 스크롤 영역을 둔다.
- 시안의 모든 값은 예시이며 실제 인증서 읽기·TL 서명·검증·내보내기를 하지 않는다. 시안에서 보기 선택을 바꾸는 동작은 시험 실행이 아니다.

## 시각 기준

도메인: 신뢰앵커, TL 발행본, 인증 경로, 상태 구간, 검증 근거, 실행 비교. 서류 흰색·잉크 남색·파일함 회색·보류 황색·성공 녹색·오류 적색을 의미에 따라 사용한다. 관리 현황판은 기존 화면에서 시연하며 실제 검증 결과와 구분한다. 통합 통과 배지는 사용하지 않는다. 서명 무결성과 TL 신뢰를 나란히 보여주는 분리 판정 패널을 중심 패턴으로 사용한다.

본문 맑은 고딕 14px, 제목 24px, 보조 12px. 간격 4px 기준, 패널 여백 20px, 컨트롤 40px, 모서리 6px, 흰색/연회색 배경과 얇은 경계선. 모션 없이 상태·차이 표시에 집중한다.

## v0.4 실제 작업대 반영

UI-02: 파일 선택 → 내용 확인·검사 → 변경 요약과 기존/후보 구조 나란히 확인 → 별도 적용. 현재 사용 TL을 독립 표시한다. 운영기관·사업자·서비스·상태·효력시각을 우선하고 인증서 지문·해시는 접힌 기술정보에 둔다. 실제 이력이 없으면 이력 없음을 표시한다. 필드 버튼은 해당 XML 요소를 열고 다운로드는 원문을 유지한다.

UI-04: 조건 일치 여부와 결과 비교 아래에 두 실행의 저장 TL 내용 차이와 구조를 표시한다. 서비스 식별자가 없고 공개키가 달라지면 추가/삭제로 표시될 수 있음을 안내한다.
