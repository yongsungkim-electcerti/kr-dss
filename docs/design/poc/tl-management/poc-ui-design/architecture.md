# PoC 구성·신뢰 경계

로컬 단일 사용자 환경을 설계 가정으로 둔다. 브라우저의 네 화면은 로컬 처리 모듈을 사용한다. 기능 설계는 기존 서버·검증 모듈 재사용을 전제로 하며 신규 외부 서비스·사업자 서버·운영 인증 체계를 추가하지 않는다. 외부 노출을 허용하는 설계가 아니며 노출 변경 시 신뢰 경계를 다시 검토한다.

흐름: 시험 파일 → TB-001 파싱 → 서비스 초안 → TB-003 파일키 서명 → TL 후보 → TB-002 서명·체인·최신성 검사 → 적용 TL·색인 → TB-003 실제 검증 → TB-004 결과 보존·비교·내보내기.

| ID | 자산 | 종류 | 보호 속성 | 위치 |
|---|---|---|---|---|
| AST-001 | 시험용 서명키·암호 | 비밀 | 기밀성 | main runtime |
| AST-002 | 사전 신뢰앵커·채택 TL·색인 | 신뢰정보 | 무결성 | 서버 설정·검증기 |
| AST-003 | 인증서·서명 표본 | 입력 | 무결성, 기밀성 | main runtime |
| AST-004 | 실행 결과·재현 조건 | 증거 | 무결성 | main results |

| ID | 경계 | 안쪽 | 바깥쪽 | 진입점 |
|---|---|---|---|---|
| TB-001 | 파일 입력 경계 | 파일 처리 모듈 | 선택 파일·사용자 경로 | 인증서·TL·서명 입력 |
| TB-002 | TL 신뢰 채택 경계 | 검증된 TL·색인 | 미검증 TL 후보 | 검사·채택 |
| TB-003 | 키·실행 프로세스 경계 | 서명·검증 처리 모듈 | 브라우저 UI | 서명 별칭·실행 명령 |
| TB-004 | 결과 비교·내보내기 경계 | 보존된 실제 결과 | 조회·예상값·재실행 요청 | 비교·내보내기 |

공격자 모델: 사용자가 악성 파일·변조 TL·동일 이름의 다른 키 인증서 또는 잘못된 재현 조건을 선택할 수 있다. 로컬 OS 관리자 권한 탈취에 대한 방어는 PoC 범위 밖이며 이를 보안 검증 완료로 주장하지 않는다.
