# TL 구조 설명·변경 비교 — 변경 정의 v0.4

사용자 승인에 따른 변경. 기존 요구사항 10개를 유지하고 POC-03(수용 과정), POC-07(전후 비교), POC-10(근거 표시)의 인수 조건을 구체화한다. 이 문서의 변경 정의가 기존 ‘검사 후 즉시 적용’ 구현 설명보다 우선한다.

| 대상 | 변경 정의 | 확인 조건 |
|---|---|---|
| POC-03 | 파일 선택 → 내용 확인·서버 검사 → 변경 비교 → 별도 적용 | 검사 요청만으로 적용본이 변경되지 않는다. 적용 시 후보와 비교 기준을 재확인한다. |
| POC-07 | 실제 실행 결과뿐 아니라 그 실행에 사용한 두 TL의 의미상 변경을 보여준다 | 현재 적용본 대신 실행별 저장 TL을 사용하며 상태·인증서·서비스 변경을 구분한다. |
| POC-10 | TL 목록·사업자·서비스·상태 이력·인증서 정보를 한글 설명과 원문 근거로 제공한다 | 해시는 접힌 기술 상세에 두고 운영기관·순번·시각·변경 요약을 우선한다. |

| 기능 | 변경 또는 추가 |
|---|---|
| FUN-009 | 새 XML 파일을 후보로 입력. 파일 선택이 바뀌면 이전 검사·적용 버튼을 무효화한다. |
| FUN-010 | 서버 검사 결과와 구조 미리보기를 함께 반환. 거부된 파일은 ‘신뢰 미확인/채택 불가’로 표시한다. |
| FUN-011 | 검사한 후보 ID로만 별도 적용. 후보가 교체되었거나 적용 기준 TL이 바뀌면 재검사 요구. 적용 직전 유효성 재검사. |
| FUN-025 | TL 읽기 화면: 목록 운영기관 → 사업자 → 서비스, TL 서명자와 별도 신뢰앵커, 인증서 주체·발급자·유효기간, 상태 이력 표시. |
| FUN-026 | 기존/후보 및 실행별 TL 비교: 추가·삭제·상태·효력시각·인증서 갱신·공개키 변경·이력 변경 구분. 동일 이름만으로 같은 서비스로 묶지 않는다. |
| FUN-027 | 필드 설명과 XML 요소 연결, 정렬 원문 보기와 원문 다운로드. 화면 정렬은 표시용이며 원문 바이트는 변경하지 않는다. |

## 데이터·보안 계약

- 구조 표시는 파싱된 내용이며 신뢰 판정을 대신하지 않는다. 거부 후보에도 신뢰 미확인·채택 불가 경고를 유지한다.
- 후보는 서버 메모리에 최신 한 건만 보관(5 MiB 상한). 후보 ID와 검사 당시 적용 해시를 묶는다. 재시작·새 후보 검사 후에는 재검사한다.
- XML은 외부 엔티티·DTD 접근을 차단하고 HTML로 삽입하지 않는다. 사용자 문자열은 escape/textContent로 표시한다.
- 서비스 비교는 사업자 ID와 서비스 ID를 우선 사용한다. ID가 없으면 공개키 기반으로 매칭하며 키 변경 시 추가/삭제로 보일 수 있음을 안내한다. 중복 ID는 모호함으로 표시하고 확정 매칭하지 않는다.
- 현재 상태와 과거 이력은 실제 XML에 있는 구간만 표시한다. TL에 포함되지 않은 중간 CA나 과거 이력을 추정하여 그리지 않는다.
- 원문 다운로드는 attachment/application/octet-stream으로 반환한다. 경로는 서버가 선택하며 사용자가 로컬 경로를 지정할 수 없다.

- TC-109: 상태 변경·동일키 인증서 갱신·공개키 변경·추가/삭제·이력 없음·중복 ID 비교.
- TC-110: 실제 브라우저에서 구조·설명·차이·원문 확인, 저장 실행의 TL 비교 및 원문 바이트 동일성.
