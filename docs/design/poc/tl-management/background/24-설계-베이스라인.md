# 24. 설계 베이스라인 v1.0 (초안) (D11)

> 자료 분류: 기존 상세 설계·검토 자료. 현재 PoC 구현 범위는 [확정 범위](../scope.md)를 우선한다. 고정 시나리오·HSM·별도 WEB 등은 현재 필수 개발로 간주하지 않는다.

> 1차 설계 검토([16](../../../../development/poc/tl-management/reviews/16-설계-보완사항-조치목록.md)) §5 우선 작업 6 — D11.
> **완료 기준:** 생략 범위가 관련 문서에 반영되고, 핵심 결정 · 미결 사항 · 후속 과제 · 기준 문서가 구분된다.
> 상태: **초안 v1.0 (2026-10-05)**. 2차 검토 후 확정 · 태그(`krtl-design-v1.0`)를 붙인다.

## 2. 확정 결정

| 영역 | 결정 |
|---|---|
| 증명 명제 | 체인 고정, TL 등재 · 상태 · 보유 버전에 따라 같은 서명의 판정이 바뀐다 (23 §1) |
| 범위 조정 | 관리자 인증 · 역할 · 승인 분리 · 감사 제외. 시연자 1명 |
| 구성 | 인증사업자 ─ 신뢰체계 관리 시스템(KISA · 신뢰앵커: 관리 폐쇄망 + 배포) ─ 이용환경. IF-01~09 |
| 신뢰앵커 | KISA TL RootCA 하나. TL 서명 체계는 전자서명 체계와 분리 |
| 인증체계 | 사업자 4개 (JA · JB = KISA RootCA 하위 레벨 1, SA = 자체 Root 레벨 0 · Root만 등재, SB = 레벨 1). 한 체인에 신뢰점 하나. 폴더 구조 사용 |
| TL 형식 | ETSI TS 119 612 v2.4.1 기반 XML + XAdES 단일. TSL 유형 KRlist, URI `urn:kr:krtl:`, 가상 OID `2.999.1`, 국내 표기 한글 |
| 상태 · 이력 | 인정 · 정지 · 철회 (· 국가 지정 정의만), EU 대응. 이력 삭제 없음, 소급 금지. 새 키 = 새 서비스 |
| 버전 | EU 규칙 고정 — 일련번호 역행 불가, 기한 지난 TL 버림. PoC 값: NextUpdate +7일, 긴급 1시간, 이용환경 풀 10분, 사업자 제출 30일 |
| 판정 | 서명에 기록된 서명 시각(KST, `+09:00`), TSA 미사용. 경계 = 새 상태. 최초 인정 전 · 서명 시각 없음 = 보류. 사유 코드 9종 (18 §1) |
| 흐름 | 입력 → 확정 → 발행 → 게시 → 수신 → 적용. 단일 발행 · 수동 재시도. 서명 성공 시 번호 확정. `ALREADY_PUBLISHED` · `CONFLICT` 구분 |
| 배포 | 서명된 TL 하나만 반출 (매니페스트 · 제출서 서명 없음). 이용환경은 풀 방식 |
| 시험 | 체인 3종, 표본 9개, TL #1~#5, 실행 R1~R6, 시드 · 체크포인트 초기화 |
| 브라우저 | 웨일은 **크롬 확장으로 우선 대체**. 확장은 TL 활용만 하고 **PDF 서명 값 검증은 웨일의 역할**로 하지 않음 |
