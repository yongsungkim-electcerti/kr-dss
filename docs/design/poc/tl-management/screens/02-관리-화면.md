# 02. 관리 화면 설계

> 자료 분류: 기존 상세 설계·검토 자료. 현재 PoC 구현 범위는 [확정 범위](../scope.md)를 우선한다. 고정 시나리오·HSM·별도 WEB 등은 현재 필수 개발로 간주하지 않는다.

> 관리 콘솔(IF-02 관리 조작)의 화면 구성.
> **1차 설계 검토 반영 (2026-10-05):** 관리 화면은 **시험 조건을 입력하고 TL을 발행하는 도구**다. 로그인 · 역할 · 승인자 분리 · 감사 기능은 PoC 핵심 범위에서 뺀다. 시연자 한 명이 입력 → 확정 → 발행 → 결과 비교까지 조작한다.
> 현재 `poc-kisa-tl` 화면(대시보드·사업자 상세·등록 대기·배포 파이프라인)을 출발점으로 삼는다.

## 1. 사용자

| 사용자 | 하는 일 |
|---|---|
| **시연자** (관리자) | 신뢰정보 입력, 제출 건 확정, 상태 변경, TL 발행, 결과 비교 |

- 로그인 없이 쓴다. 관리자 인증 생략은 **TL 서명 · 인증서 · 사업자 연계 인증을 생략한다는 뜻이 아니다.**
- 실제 운영의 역할 분리(운영자 · 심사자 · 승인자 · 감사자)와 감사 기록은 후속 범위로 둔다.

## 2. 화면 목록

| ID | 화면 | 다루는 데이터 | 주요 기능 | 관련 시나리오 |
|---|---|---|---|---|
| **M-01** | 대시보드 | D-02, D-06 | 현재 TL 버전 · 다음 발행 예정, 상태별 서비스 수, 확정 대기 건수 | 전체 |
| **M-02** | 사업자 · 서비스 | D-01~04 | 사업자 목록 · 상세, 서비스별 상태 이력 타임라인, 서비스 인증서 | SC-01 |
| **M-03** | 상태 변경 | D-02, D-03 | 정지 · 철회 · 복원 입력: **효력 시각(KST)**, 사유 → 즉시 발행 여부 | SC-03~05 |
| **M-04** | 제출 확정 | D-05 | 제출 건 목록, 변경 전 / 후 비교, 확정 · 반려(사유) | SC-01, 12 |
| **M-05** | TL 발행 | D-06, D-07 | 확정된 입력으로 TL 발행 → **직전 버전과 차이** 표시 → 서명 → 반출 → 게시 확인, 실패 표시 · 재발행 | 전체 |
| **M-06** | 배포 현황 | D-07, 게시 결과 | 버전별 게시 이력, 게시 성공 · 실패, 현재 배포 버전 | SC-06 |
| **M-07** | 수신 현황 (배포 시스템 화면) | D-09 | 이용기관 · 브라우저별 마지막 수신 버전 · 시각 | SC-06 |
| **M-08** | **결과 비교** | D-06, D-11 | 변경 조건 · 변경 전후 신뢰 경로 · 이용환경 결과를 나란히 표시 ([18](../../../common/kr-tl/18-신뢰경로-판정표.md) §6) | SC-01, 03~06 |
| **M-09** | KISA 인증체계 (조회) | D-08 | KISA TL RootCA · KISA TL CA · TL 서명 인증서 현황 | — |

## 3. 핵심 화면 개요

### M-03 상태 변경

```
┌ 서비스: 가상공동인증A CA (현재: 인정, 2026-11-02T10:00:00+09:00부터) ─┐
│ 변경할 상태   ( ) 정지   ( ) 철회   ( ) 인정 (복원)                    │
│ 효력 시각     [2026-11-03T10:00:00+09:00]   ※ 발행 시각 이전은 입력 불가 │
│ 사유          [키 유출 의심 신고]                                       │
│ 발행 방식     (●) 즉시 발행   ( ) 다음 정기 발행에 포함                 │
│                                                       [입력 확정]      │
└────────────────────────────────────────────────────────────────────────┘
```

- 효력 시각은 상태 이력(D-03)에 그대로 남고 TL에 실린다. 이용환경의 시점별 판정은 이 값으로 이뤄진다.
- **효력 시각 소급은 금지한다** (EU 기준, [10](../../../common/kr-tl/10-TL-구조.md) §7.2).

### M-05 TL 발행

```
[1 입력 확정] ─ [2 차이 확인] ─ [3 서명] ─ [4 반출] ─ [5 게시 확인]

TL #3 (직전 #2 대비)
  ~ 가상공동인증A CA   인정 → 정지 (2026-11-03T10:00:00+09:00)
  다음 발행 예정: 2026-11-10T10:00:00+09:00
                                                   [발행]
```

- 확정된 입력만 발행 대상이다. 확정 뒤 입력은 다음 TL로 간다.
- 서명 · 반출 실패는 단계에 표시하고 시연자가 다시 발행한다.

### M-08 결과 비교

[18 신뢰 경로 판정표](../../../common/kr-tl/18-신뢰경로-판정표.md) §6의 세 영역(변경 조건 · 변경 전후 신뢰 경로 · 이용환경 결과)을 한 화면에 둔다.

## 4. 화면에서 드러난 기능 세부 사항

| # | 세부 기능 | 근거 |
|---|---|---|
| F-01 | 상태 변경에 효력 시각 · 사유를 함께 저장 | M-03 |
| F-02 | TL의 직전 버전 대비 차이 계산 | M-05 |
| F-03 | 발행 단계 표시 (확정 · 서명 · 반출 · 게시)와 실패 시 재발행 | M-05 |
| F-05 | 즉시 발행 (정기 주기와 별개) | M-03 |
| F-06 | 이용환경별 마지막 수신 버전 | M-07 |
| F-08 | 서비스 디지털 ID — **같은 공개키**의 인증서만 여러 장 보관 (키가 바뀌면 새 서비스, 12 §2.3) | M-02 |
| F-09 | 시험 실행 ID 단위 기록: 변경 내용 · 발행 TL 버전 · 이용환경 결과 | M-08 |

- 기존 F-04(생성자 ≠ 승인자)와 F-07(감사 기록 해시 연결)은 PoC 핵심 범위에서 뺀다.
