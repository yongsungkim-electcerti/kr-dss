# TrustList 개념증명 — 요구사항 검토 초안

기준일: 2026-10-27. 현재 검토 대상은 **TL을 실제 검증에 사용하는 개념증명 요구사항 10개와 산출물 4종**이다. 사업자 연계는 제외하고 인증서 파일·최소 신뢰정보 입력으로 실증한다.

## 검토 순서

1. [PoC 요구사항·범위](poc-requirements.md): 현재 검토할 초안.
2. [엑셀 검토본](../../../../outputs/tl-poc-20261027/TrustList_개념증명_요구사항_v0.3.xlsx): 영역·요구사항·설명·산출물·참고의 5열, 산출물 및 실증범위 시트.
3. [공식 근거와 적용 구분](sources.md), [Dev-Pulse 지침 보완안](dev-pulse-guidance-changes.md).
4. [기능목록·화면설계](poc-ui-design/README.md): v0.3 요구사항에 연결한 기능 24개·화면 4개, 엑셀과 클릭형 시안. D1의 설계 부속이며 검토 초안이다.

사용자가 제공한 시나리오 2개는 비공식 예상 사례이며 정식 시나리오·인수 기준으로 승계하지 않는다. 현재 요구를 실제 실행한 결과는 아직 없다.

## 이전 상세안 — 현재 PoC의 의무 목록이 아님

엑셀 검토본: [요구사항 70개·도출 산출물 24종](../../../../outputs/tl-requirements-20261026/신뢰체계_요구사항_및_산출물정의_v0.2.xlsx). 산출물별 필수 내용·검수 기준·작성 상태를 포함한다. 엑셀 수정 의견은 검토 후 아래 원본에 반영한다.

1. [요구사항 정의서](requirements.md): 범위·개별 요구·인수 기준. 수정 요청은 ID로 지정한다.
2. [공식 근거와 적용 구분](sources.md): 원문·판본·조항·국내 적용·PoC 예외.
3. [미결정 사항](open-questions.md): 요구사항 확정 전에 필요한 결정.
4. [시험 명세](test-spec.md): 요구별 검증 입력·기대 결과. 모든 시험은 미실행.
5. [추적표](traceability.md): Dev-Pulse가 생성하는 요구→설계→시험 연결.
