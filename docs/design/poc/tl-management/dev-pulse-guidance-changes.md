# Dev-Pulse 요구사항 정의 지침 보완안

상태: 사용자 검토용 제안. 원본 `F:/custom-skills/Dev-Pulse`는 수정하지 않았다. 이 문서의 채택 후 스킬 수정·자체 평가를 별도 수행한다.

## 목표 수준

### 2026-10-27 추가: PoC의 규모와 목적을 먼저 정한다

- 제품 개발과 개념증명을 구분한다. 이번 목표는 TL 관리 업무 완성이 아니라 TL을 실제 검증에 사용하는 흐름의 입증이다.
- PoC는 입력·처리·관찰 결과를 설명하는 실증 단위로 요구를 묶는다. 세부 필드·HTTP 조건마다 독립 요구와 제출 문서를 만들지 않는다.
- 사업자 연계·심사는 인증서 파일과 최소 입력으로 대체한다. 사용자 범위에 없는 HSM·권한·감사·고가용성·성능 목표를 필수로 추가하지 않는다.
- 산출물은 요구사항·실증계획서, 실행 패키지, 시험 데이터 세트, 실증 결과서 4종으로 통합한다. 설계·실행 안내·로그는 필요한 묶음의 일부로 관리한다.
- 비공식 예상 시나리오에서 후보를 추리되 정식 절차·인수 기준·통과 증거로 승계하지 않는다.
- TL 채택, TL 기반 신뢰 판단, 실제 서명값 검증 결과를 구분한다. 검증 미실행을 통과로 표시하지 않는 원칙은 유지한다.

아래 상세 추적 수준은 제품화·운영 확장 또는 필요한 부분의 상세화에 적용하며, 모든 항목을 PoC의 문서 의무로 적용하지 않는다.

한 요구에 하나의 의무를 적고, 원문·판본·조항→적용 해석→인수 기준→설계·시험→실행 증거를 추적한다. 표준 요구·사업 요구·사용자 결정·프로젝트 선택·신규 제안을 구분한다. 요구 확정·구현 상태·시험 판정은 독립된 상태다.

## 이번 문서에서 먼저 적용한 규칙

- 새 ID는 기존 기준 문서를 대신하는 검토 초안으로 만들고 자동 확정하지 않았다.
- 표준 원문은 main 비관리 자료실, 출처·해시·요구사항은 Git 관리 대상 문서로 분리했다.
- 국내 제도 HTML의 탐색 페이지와 실제 조문 확보를 구분했다.
- 표준이 정하지 않은 raw 해시 표현·state.json·TRIAL은 프로젝트 선택으로 표시했다.
- 미결정 수치를 임의로 넣지 않고 보류 요구와 OQ로 남겼다.
- 전체 시험은 미실행으로 두었으며 기존 빌드 성공을 개별 요구사항 충족으로 승계하지 않았다.

## 변경 순서 제안

우선 요구사항·출처 템플릿과 사람 검토 체크리스트를 보완하고, 적용 대상별 상태/판정 규칙을 확정한 뒤 검사기를 변경한다. 기존 프로젝트가 새 필드 없이 모두 실패하지 않도록 구형 문서 호환·마이그레이션 규칙도 함께 정한다.
