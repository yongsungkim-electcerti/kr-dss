# TL 생성·발행·제공

2026-10-09 보완: [개정안 PoC 적용표](concept-v02-application.md), [프로파일 v1](profile-poc-v1.md), [발행·복구 상세](issuance-recovery.md)를 함께 적용한다. 아래 절차의 확정·실패·재시도 기준은 발행·복구 상세가 정의한다.

1. 초안을 읽고 정상 권장 순번·시각을 표시한다. 사용자가 의미 오류 값을 입력할 수 있다.
2. 후보 스냅숏을 고정하고 XML을 편성한다.
3. 사전 검사 결과를 안내하고 키 파일로 서명한다. 의미 오류와 키 읽기·서명 실패를 구별한다.
4. 생성된 암호 서명을 확인하고 XML·메타데이터를 issuanceId별로 저장한다. 저장 실패는 생성 성공이 아니다.
5. 관리자가 제공본을 선택한다. 최대 순번을 자동 선택하지 않는다.
6. WAS가 저장된 바이트를 IF-07로 제공한다. GET에서 재서명·재직렬화하지 않는다.

정상 서비스 이력을 전진시키는 BASELINE과 기준 이력을 유지하는 TRIAL을 관리 메타데이터에서 구분한다. 의미 오류가 있으면 TRIAL로 생성한다. 두 종류 모두 선택·제공할 수 있으며 외부 수용 판정은 소비자의 책임이다. 정상 권장 순번은 마지막 확정 BASELINE+1이다. TRIAL 최대 순번·현재 제공 순번으로 권장값을 바꾸지 않는다.

서명 후에도 저장 또는 상태 확정에 실패하면 생성 성공이 아니다. 발행본 파일과 다음 초안 revision을 준비한 뒤 state.json의 발행 확정 목록·요청 매핑·정상 기준을 한 번에 교체한다. 동일 requestId 재전송은 저장된 결과를 반환하며, 같은 순번으로 새 내용을 생성하려면 새 requestId를 사용한다.

개념 설계 v02 §4.4.1의 낮은 순번·동일 순번 충돌 게시 거부는 목표 운영 정책이다. 이 PoC는 수신 검증 시험을 위해 해당 의미 오류를 제공하는 예외를 유지한다. 별도 WEB·게시 심사 단계는 추가하지 않는다.

순번·시각의 의미 오류는 관리 화면에서 발행·제공 가능해야 한다. 생성 성공은 외부 검증 모듈의 수용을 뜻하지 않는다. 보관본은 덮어쓰지 않으며 재제공은 같은 바이트를 사용한다.

[IF-07](interfaces/28-IF07-TL-조회-API.md): `/tl/kr-tl.xml`, `/tl/kr-tl.sha2`, XML 해시 기반 ETag/304. 별도 WEB 서버는 구성하지 않는다.
