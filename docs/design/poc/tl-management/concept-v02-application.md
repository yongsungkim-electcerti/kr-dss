# 개정 개념 설계 v02의 PoC 적용 기준

작성일: 2026-10-09. 사용자 요청에 따른 상세 설계 보완이다. 제품 구현·시험 완료를 뜻하지 않는다.

## 적용 원칙

[개정 원문](sources/2026-10-08-concept-v02/README.md)은 목표 운영 시스템을 설명하고, [scope](scope.md)는 이번 PoC의 구현 경계를 정한다. 원문을 수정하거나 기존 사용자 결정을 변경하지 않는다.

| 개념 설계 | PoC 적용 | 책임 |
|---|---|---|
| 사업자·서비스·인증서·상태 이력 관리 | 실제 입력·저장·복원 | 관리 기능 |
| 접수·심사·보완·반려 | 메뉴와 범위 안내만 제공 | 관리 화면 |
| TL XML 구성·서명 | 실제 XML 생성과 파일 키 서명 | 공통 builder + 발행 기능 |
| HSM | 파일 개인키로 대체 | PoC 서명 어댑터 |
| 서명본 보관 | issuanceId별 불변 파일 | 발행 저장소 |
| WAS→WEB 게시 | 단일 WAS가 선택한 파일 제공 | 제공 기능 |
| 낮은 순번·동일 순번 충돌 게시 거부 | 정상 기준으로 경고하되 시험 발행·제공 허용 | 관리자는 생성·제공, 외부 검증기는 채택 판단 |
| 인증·권한·감사 | 제외 | 추가 개발하지 않음 |
| NextUpdate까지 갱신 | 기한 표시와 수동 재발행 제공 | 관리 기능 |
| 브라우저·이용기관 검증 | 필요한 XML·체인·프로파일 인계 | 외부 검증기 |

자동 스케줄러, 별도 WEB, 외부 검증 결과 수집 API는 추가하지 않는다. 기능 상태와 실패 복구를 위한 내부 저장 메타데이터는 감사 기능과 구별한다.

## 정상 권장값과 시험 발행

모든 발행은 같은 XML 생성·서명·불변 저장 절차를 사용한다. 입력을 정상값으로 몰래 교정하지 않는다. 사용자에게 권장 순번·시각을 제시하고 변경값과 진단을 표시한다.

- 지원 자료형으로 표현 가능한 순번·시각의 의미 오류는 경고다. 생성·제공을 막지 않는다.
- 잘못된 날짜 문자열, 필수 디지털 ID 누락, 미지원 상태 입력처럼 모델 자체를 구성할 수 없는 값은 입력 오류다.
- 키 읽기·서명·서명 자체 확인·저장 실패는 처리 실패다. 생성 성공으로 표시하지 않는다.
- 서명 훼손이나 XML 스키마 파괴는 별도 오류 생성 기능이며 이번 범위에 추가하지 않는다.
- 소비자는 생성기의 사전 검사 결과와 무관하게 서명·체인·시각·이력을 검증한다.

발행 메타데이터의 purpose는 정상 기준 이력을 전진시키는 BASELINE과 기준 이력을 건드리지 않는 TRIAL로 구별한다. 의미 오류가 있으면 TRIAL로 저장한다. 정상 자료도 시험 목적으로 TRIAL로 저장할 수 있다. 이 구분은 내부 관리 값이며 XML의 새로운 신뢰 판정 필드가 아니다. 추가 승인 단계나 로그인은 없다.

BASELINE은 이력·순번 제안의 기준일 뿐 외부 검증기의 채택을 보장하지 않는다. 제공본은 BASELINE/TRIAL과 무관하게 관리자가 선택한다. 큰 순번 TRIAL을 만들거나 예전 발행본을 제공해도 다음 정상 권장 순번과 정상 서비스 이력을 바꾸지 않는다.

## 화면 표시 계약

| 표시 | 자료와 의미 |
|---|---|
| 편집 중 | draftRevision과 저장 여부 |
| 사전 검사 | 순번·시각·이력의 진단 코드와 대상 필드 |
| 생성 성공 | 확정된 issuanceId, 입력 순번, 시각, 최종 XML 해시 |
| 자체 서명 확인 | 실제 암호 서명 검사 결과. 전체 TL 유효 판정과 구별 |
| 현재 제공본 | publicationRevision과 선택 issuanceId |
| 기한 알림 | 저장된 NextUpdate, TL 서명 인증서·서비스 인증서의 만료 |
| 외부 검증 결과 | 결과를 확보하지 않은 경우 ‘미확인’. 성공으로 추정하지 않음 |

신청 처리 상태를 서비스 인정 상태로 저장하지 않는다. 비구현 메뉴에는 ‘PoC 범위 제외’를 표시한다. 숫자·최근 활동·배포 완료 문구는 실제 저장 상태에서만 산출한다.

## 선택한 구조와 한계

단일 WAS 안에 관리·발행·제공 책임을 분리한다. 공통 모델과 builder는 PoC 컨트롤러나 이용기관 모듈을 역참조하지 않는다. 발행 저장소만 불변 발행본을 만들며 제공 기능은 읽기만 수행한다.

별도 DB·메시지 브로커·다중 WAS는 이번 구조에서 채택하지 않는다. 파일 기반 단일 작성자는 복구 경로가 작다는 장점이 있지만, 동시 발행 처리량과 다중 프로세스 운영을 제한한다. 실패 복구 근거는 [저장·발행 트랜잭션](issuance-recovery.md)의 개발 검증 항목으로 확보한다.

상세 설계와 구현 책임은 TL 관리 PoC 개발 담당, 공통 프로파일 해석과 외부 채택 검증은 각 소비자 개발 담당에 있다. 외부 소비자가 임시 프로파일을 지원하는지 확인하기 전에는 상호운용 완료로 표시하지 않는다.
