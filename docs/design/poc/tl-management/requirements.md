# 신뢰체계 관리시스템 요구사항 정의서 — 검토 초안 v0.1

> 2026-10-27: 이 70개 목록은 이전 상세 검토안이다. 현재 PoC 검토 기준은 [TrustList 개념증명 요구사항 10개](poc-requirements.md)이며, 아래 항목을 PoC 필수 구현 범위로 자동 승계하지 않는다.

작성일: 2026-10-26. 사용자 검토용 재구성 초안이다. 기존 결정의 출처는 보존하되 이번 ID·인수 기준·분해 단위는 아직 확정하지 않았다. 기능 구현 여부나 시험 통과를 뜻하지 않는다.

## 목적과 범위

사업자·신뢰서비스·디지털 ID·인정 이력을 관리하고, TL을 구성·서명·보관·제공하여 외부 소비자가 시점별 신뢰 판단에 사용할 수 있게 한다. 관리 시스템의 생성·제공 성공은 외부 소비자의 신뢰 수용이나 PDF 서명 유효성을 보증하지 않는다.

- **공통**: 목표 운영과 현재 PoC에 공통으로 요구하는 의미·계약. 운영에서 동일 구현 방식을 강제하지 않는다.
- **PoC**: 단일 WAS·파일 키·파일 저장 및 의미 오류 시험 제공이라는 기존 사용자 범위. 운영 안전정책으로 일반화하지 않는다.
- **외부 소비자**: 인터페이스 인수에 필요한 외부 책임. 관리 시스템 단독 개발 완료 항목에 합산하지 않는다.
- **운영 보류 / 정책 보류 / 적합성 보류**: 요구 후보는 보존하되 결정 전 PoC 개발량·통과 분모에 넣지 않는다.
- **보안 제안**: 기존 확정 사항이 아닌 새 제안. 사용자 검토 전 의무화하지 않는다.

현재 PoC는 인증·권한·감사, 실제 HSM, 별도 WEB, 신청·심사 업무 처리를 제외한다. 신청 관련 메뉴는 범위 안내만 제공한다. 상세 실증 시나리오·시험 시계·표본은 별도 결정한다. 외부 소비자의 PDF 무결성·OCSP·TSA 검증은 해당 소비자 책임이다.

## 읽는 방법

출처의 STD/CTX는 [공식 근거 목록](sources.md), POL/BIZ/LEG는 같은 문서의 결정·기존 설계 출처를 따른다. 표준의 규범 요구, 참고 부속서, 국내 적용 선택, PoC 예외를 혼동하지 않는다. `필수`는 해당 적용 범위가 채택된 경우의 중요도이며, `보류`를 자동 활성화하지 않는다.

표의 설명은 준수할 요구, 인수 기준은 관찰할 결과다. 시험 입력은 [시험 명세](test-spec.md)에 분리했다. 설계는 [설계 연결](detailed-design.md)의 초안이며 구현 위치·보안 통제는 후속 단계에서 검증하여 연결한다.
