# 20. 시험 데이터와 비교 화면 명세 (검토 우선 작업 4)

> 자료 분류: 기존 상세 설계·검토 자료. 현재 PoC 구현 범위는 [확정 범위](../scope.md)를 우선한다. 고정 시나리오·HSM·별도 WEB 등은 현재 필수 개발로 간주하지 않는다.

> 1차 설계 검토([16](../../../../development/poc/tl-management/reviews/16-설계-보완사항-조치목록.md)) §5 우선 작업 4 — D4 · D7 · D9.
> **완료 기준:** 표본 · 체인 · 시각 · 정책 · 초기 TL · 기대 경로 · 판정 · 사유를 고정해 비교할 수 있다.
> **PoC 구현:** 웨일은 **크롬 확장**으로 우선 대체한다 ([21](../../../../guides/poc/tl-management/21-시연-운영-절차.md) · [22](../../../../development/poc/tl-management/planning/22-구현-작업-계획.md) W-10). 이 문서의 "웨일"은 브라우저 이용환경을 뜻한다.
> 판정 규칙과 판정표는 [18](../../../common/kr-tl/18-신뢰경로-판정표.md), 조작 흐름은 [19](../publication/19-변경-발행-수신-흐름.md).

## 2. 기대 결과

### 2.1 주 시연 — 가입자 U (C-JA)

[18 판정표](../../../common/kr-tl/18-신뢰경로-판정표.md) §5 그대로다. S0~S4 · SB × TL #1~#5.

### 2.2 추가 표본

| 표본 \ TL | #1 | #2 | #3 | #4 | #5 |
|---|---|---|---|---|---|
| `sig-W-S2` (JB, 대조군) | 통과 | 통과 | **통과** | 통과 | 통과 |
| `sig-V-S2` (SA, 레벨 0) | 통과 · 신뢰점 SA-00 | 통과 | 통과 | 통과 | 통과 |
| `sig-U-NT` (서명 시각 없음) | 보류 · `NOT_IN_TL` | 보류 · `NO_SIGNING_TIME` | 보류 · `NO_SIGNING_TIME` | 보류 · `NO_SIGNING_TIME` | 보류 · `NO_SIGNING_TIME` |

- 대조군 W는 TL #3에서도 통과한다 → **정지는 JA만의 일**이다 (레벨 1의 사업자별 정지).
- V는 신뢰점이 SA RootCA(레벨 0)로 표시된다. SA CA는 TL에 없어도 Root까지 체인으로 통과한다.

### 2.3 경로 표시 기대값

| 결과 | 비교 화면의 경로 표시 |
|---|---|
| 통과 | 인증서 체인 + TL 신뢰점 연결(초록) + 서명 시각의 상태 "인정" |
| 실패 · 정지/철회 | TL 신뢰점 연결(주황/빨강) + 서명 시각의 상태 + 끊긴 지점 = 상태 |
| 보류 · `NOT_IN_TL` | 인증서 체인만 있고 TL 연결 없음 — 끊긴 지점 = TL 신뢰점 |
| 보류 · 그 밖 | 끊긴 지점 = 시각(최초 인정 전 / 서명 시각 없음) 또는 TL(유효한 TL 없음) |

## 3. 시험 실행 순서

| 실행 | 시작 상태 | 조작 (19 흐름) | 확인 | 시나리오 |
|---|---|---|---|---|
| **R1** | 이용기관 · 웨일 모두 TL #1 | 표본 전체 검증 | §2 #1 열 | SC-01 |
| **R2** | — | JA 등재 확정 → TL #2 발행 · 게시 → 이용기관 · 웨일 "지금 확인" → 표본 전체 검증 | #2 열, U-S1이 보류 → 통과 | SC-01 · 06 |
| **R3** | — | JA 정지 확정 → TL #3 발행 · 게시 → **이용기관만** 수신 → U-S2 검증 (이용기관 · 웨일) → 웨일 수신 → 다시 검증 | 이용기관 실패 / 웨일 통과 → 둘 다 실패 | SC-03 · 06 |
| **R4** | — | JA 복원 확정 → TL #4 → 양쪽 수신 → 표본 검증 | #4 열, U-S3 통과 · U-S2 실패 유지 | SC-04 |
| **R5** | — | JA 철회 확정 → TL #5 → 양쪽 수신 → 표본 검증 | #5 열, U-S4 철회 실패 · U-S1 · S3 통과 | SC-05 |
| **R6** (보조) | 양쪽 TL #5 | 위조 TL #6 게시 시도 / TL #2 재게시 / 시험 시계를 NextUpdate 이후로 | 거부 · #5 유지 / 거부 / `NO_VALID_TL` | SC-08 |

- 각 실행은 **시험 실행 ID**(예: `R3-2026-11-03`)로 묶어 기록한다: 변경 내용 · 효력 시각 → 발행 TL → 이용환경별 사용 TL → 표본별 신뢰점 · 판정 · 사유 ([18](../../../common/kr-tl/18-신뢰경로-판정표.md) §8).
- R1~R5를 이어서 하면 18 판정표의 모든 칸을 채운다.

## 4. 초기화 (재시연)

| 대상 | 초기 상태 | 방법 |
|---|---|---|
| 인증서 (`pki/`) | §1.1 체인 고정 | 한 번 만들어 두고 다시 만들지 않음 (구축 명세 14 §5) |
| 서명 표본 | §1.3 파일 9개 | 한 번 만들어 두고 재사용 |
| 등재 정보 (`krtl/registry/`) | TL #1 상태 (JA 없음, JB · SA · SB 인정) | 시드 폴더로 덮어쓰기 |
| 발행본 (`krtl/published/`) | #1만 존재 | #2 이후 삭제 |
| 배포 WAS | 최신 = #1 | 게시 이력 초기화 |
| 이용환경 보유본 | #1 | `cache/`를 #1로 되돌림 |
| 시험 기록 | 비움 | 삭제 |

- 시드(seed) 데이터: `krtl-seed/registry/`, `krtl-seed/published/1/kr-tl.xml`, `krtl-client-seed/cache/`. 운영 절차 상세(D8)는 이 표를 바탕으로 쓴다.

### 5.1 화면 구성

```
┌─ 변경 조건 ───────────────────────────────────────────────────────────────┐
│ 시험 실행 R3 · 대상: 가상공동인증A CA (JA-01) · 레벨 1                       │
│ 변경: 인정 → 정지 · 효력 2026-11-03T10:00:00+09:00 · 발행 TL #3             │
├─ 변경 전후 신뢰 경로 ─────────────────────────────────────────────────────┤
│        TL #2 (웨일)                         TL #3 (이용기관)               │
│  KISA TL RootCA ─ TL #2 ─ JA-01 [인정]        KISA TL RootCA ─ TL #3 ─ JA-01 [정지 t2~] │
│  K-00 ─ JA-01 ─ U ─ S2 (11-03T15:00)          K-00 ─ JA-01 ─ U ─ S2 (11-03T15:00)       │
│              ✔ 경로 성립                                ✖ 끊긴 지점: 상태(정지)           │
├─ 이용환경 결과 ───────────────────────────────────────────────────────────┤
│ 이용환경   사용 TL   표본    서명 시각              정책     판정   사유                │
│ 웨일       #2        U-S2    2026-11-03T15:00+09:00  18 §1    통과   —                   │
│ 이용기관   #3        U-S2    2026-11-03T15:00+09:00  18 §1    실패   SERVICE_SUSPENDED_AT_TIME │
└──────────────────────────────────────────────────────────────────────────┘
```

### 5.2 항목과 데이터 출처

| 영역 | 항목 | 출처 |
|---|---|---|
| 변경 조건 | 시험 실행 ID, 대상 사업자 · 서비스 · 신뢰점 · 레벨, 변경 상태 · 효력 시각, 발행 TL 번호 | 관리 시스템 (확정 · 발행 기록) |
| 신뢰 경로 | 인증서 체인(고정), TL 번호, TL 신뢰점과 서명 시각의 상태, 경로 성립 여부 · 끊긴 지점 | 이용환경 검증 결과 (D-11) |
| 이용환경 결과 | 이용환경, 사용 TL 번호, 표본, 서명 시각, 정책, 판정, 사유 | 이용환경 검증 결과 (D-11) |

### 5.3 조작

| 조작 | 동작 |
|---|---|
| 시험 실행 선택 | R1~R6 중 선택 → 그 실행의 변경 조건 · 결과 표시 |
| 표본 선택 | 표본 하나를 골라 이용환경별 경로를 나란히 표시 |
| 판정표 보기 | 18 §5 형식(표본 × TL)으로 지금까지 결과를 채워 표시 — 기대값과 다르면 강조 |

- 비교 화면은 관리 콘솔에 둔다. 이용환경 결과는 각 이용환경이 남긴 검증 결과(D-11)를 모아서 보여 준다. 수집 방법은 PoC 구현 설계(D10)에서 정한다 (예: 시연용 결과 업로드).
