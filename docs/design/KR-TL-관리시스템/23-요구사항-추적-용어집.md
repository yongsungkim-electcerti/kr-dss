## 1. 증명 명제 (PoC)

> 인증서 체인은 그대로인데, **TL의 등재 · 상태와 이용환경이 가진 TL 버전**에 따라 같은 서명의 판정이 서명 시각 기준으로 달라진다. KISA가 발행한 TL이 국가 신뢰의 구심점으로서 이용환경까지 그대로 전달된다.

## 3. "자동 수집 · 주기적 동기화" 해석

| RFP 표현 | PoC 설계 | 남은 확인 |
|---|---|---|
| 인증서 자동 수집 | KISA가 사업자 시스템을 긁어 오지 않고, **사업자가 정해진 형식으로 제출**(IF-01)한다. 수집 자동화 = 제출 · 형식 확인의 시스템화. 등재는 KISA 확정 후 | KISA가 이 해석을 "자동 수집"으로 인정하는지 — **발주기관 확인 필요** |
| 유효성 주기적 동기화 | 사업자 정기 제출(PoC 30일) + TL 정기 발행(NextUpdate +7일) · 긴급 발행(1시간) + 이용환경 풀(10분) | 운영 주기 값은 향후 결정 |

- 관리자 인증 생략은 이 요구의 삭제나 충족을 뜻하지 않는다 (16 §5.1). 사업자 연계 인증(mTLS)과 TL 서명은 유지한다.

## 4. 용어집

| 용어 | 뜻 |
|---|---|
| **KR-TL** | KISA가 발행하는 한국형 신뢰목록. ETSI TS 119 612 기반 XML + XAdES |
| **인증사업자** | KISA 인정을 받은 전자서명인증사업자. PoC 가상 4개: 가상공동인증 A · B, 가상간편인증 A · B |
| **가입자** | 인증사업자에게 인증서를 받아 전자서명하는 주체 (U · V · W) |
| **이용기관 (이용자)** | 전자서명을 받아 검증하는 기관 · 시스템. 설계 문서의 "이용자"와 같다 |
| **브라우저** | 이용자가 서명을 확인하는 브라우저 이용환경 (웨일). PoC는 크롬 확장으로 대체 |
| **이용환경** | TL을 받아 판정에 쓰는 쪽 — 이용기관 시스템 · 브라우저 |
| **신뢰앵커** | 이용환경이 처음부터 믿는 단 하나의 인증서 = **KISA TL RootCA** |
| **국가 신뢰 구심점** | KISA가 인정 · 평가한 결과를 TL로 묶어 분절된 신뢰체계를 한 점에 모으는 구조 |
| **신뢰점** | TL에 등재되어 체인 검증이 멈추는 지점. **레벨 0** = 사업자 RootCA, **레벨 1** = 사업자 CA |
| **발급 관계 / TL 신뢰 관계** | 인증서가 누구에게서 발급됐는가 / 그 발급자가 TL에서 어떤 상태인가. 체인은 고정, TL이 바뀐다 |
| **서비스 · 디지털 ID** | TL 등재 단위(CA · OCSP · TSA …)와 그 식별 인증서 |
| **상태 · 효력 시각** | 인정 · 정지 · 철회 (· 국가 지정). 효력 시각부터 적용, 소급 금지, 이력은 지우지 않음 |
| **서명 시각** | 서명에 기록된 시각 (KST, ISO 8601 `+09:00`). PoC 판정 기준. TSA로 증명하지 않음 |
| **일련번호 · NextUpdate** | TL 버전 번호(역행 불가) · 다음 발행 예정 시각(지나면 그 TL은 버림) |
| **입력 · 확정 · 발행 · 게시 · 수신 · 적용** | 변경이 이용환경 판정까지 가는 6단계 (19) |
| **시험 실행 (R1~R6)** | 같은 표본을 TL 버전별로 검증해 비교하는 시연 단위 (20 · 21) |
| **시험 시계** | 시연 날짜를 쓰기 위한 기준 시각 주입 기능 (구현 방식 논의 후 결정) |
| **판정 · 사유 코드** | 통과(PASSED) · 실패(FAILED) · 보류(INDETERMINATE)와 18 §1 사유 코드 |
| **기존 서비스 채널** | 인증서 발급 · OCSP · 전자서명 제출처럼 KR-TL과 무관하게 이미 있는 연결 (IF 아님) |

## 5. 범위

### 5.1 PoC 핵심 범위

관리 콘솔의 입력 · 확정 · 발행 · 반출, 배포의 게시 · 제공, 이용환경의 수신 · 판정, 변경 전후 비교(M-08), 시험 데이터 · 초기화.

### 5.2 범위 밖 (후속)

| 구분 | 항목 |
|---|---|
| 관리 통제 | 관리자 인증 · 역할 · 승인 분리 · 감사 기록 무결성 (SC-11) |
| 인프라 | 실제 HSM · 폐쇄망 · VPN 구축, 이중화 · 성능 · 재해복구 |
| 운영 | 정기 발행 스케줄러, 운영 주기 · 목표 시간, 전체 이용기관 관리, 접속 통계 |
| 키 · 정책 | TL 서명키 교체 실행(SC-09), 전체 키 수명주기, 장기 검증 · PQC |
| 서명 증명 | TSA 타임스탬프 기반 서명 시각 증명 |
| 브라우저 | 웨일 탑재, 브라우저의 PDF 서명 값 검증 (웨일의 역할) |
| 규격 | 다국어 변환기 구현, Attestation · 장치 신뢰목록, JSON TL |
