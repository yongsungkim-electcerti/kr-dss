# 00. 신뢰체계 관리 시스템 개발(PoC) — 설계 진행 단계와 상태

## 현재 진행 상태 (2026-10-07)

**현재 단계: 기존 구현 검토 후 PoC 상세 설계 구체화.** 아래 ‘설계안 작성’은 문서 작성 상태이며 사용자 최종 확정·제품 구현·실행 검증 완료를 의미하지 않는다. 제품 코드와 키 파일은 변경하지 않았으며, 문서 부속 IF-08 Java 흐름 참조 샘플을 추가했다.

| 순서 | 단계 | 현재 상태 | 산출물·남은 작업 |
|---|---|---|---|
| 1 | 기존 구현과 최신 설계 비교 | 1차 검토 완료 | [25](25-PoC-구현-차이-검토.md): 구현 차이 16건, 제외·유보 구분 |
| 2 | PoC 범위 결정 | 사용자 결정 반영 완료 | 인증·감사 제외, 심사 메뉴만 제공, 키 파일 서명, IF-01~08, Spring Boot WAS |
| 3 | 이력·버전 모델 | 상세 설계안 작성 | [26](26-EU-기준-이력-버전-모델.md): EU 구조, 시점 이력, 순번·시각 오류 발행 허용 및 수신 검증 |
| 4 | 키 파일·인증체계 | 디렉터리 설계안 작성 | [27](27-PoC-키파일-디렉터리-설계.md): 가상 KISA·4개 사업자. 실제 키·인증서·체인 README 생성은 개발 시 수행 |
| 5 | IF-07 WAS 조회 연계 | Request/Response 설계안 작성 | [28](28-IF07-TL-조회-API.md): GET XML·해시, ETag/304, HTTP 오류와 TL 검증 오류 분리 |

| 8 | 최신 설계 간 정합성·구현 작업 분해 | 진행 필요 | 구 IF·HSM·WEB·심사·순번 폴더 등 이전 본문 정리, 변경 단위 확정 |
| 9 | PoC 시나리오 | 향후 결정 | 표본·시계·비교 화면·초기화·시연 순서. 기존 R1~R6은 참고 자료 |
| 10 | 신규 설계 구현·통합 검증 | 미착수 | 기존 PoC 코드 자산은 존재. 이번 상세 설계의 구현과 실행 증거는 아직 없음 |

다음 설계 대상은 **관리 화면과 관리 API**다. 발행 입력·오류값 조정·제공본 선택·검증 결과 표시를 구체화한 뒤 모듈별 구현 작업으로 나눈다. PoC 시나리오는 사용자 결정 전까지 확정하지 않는다.

세션 종료 후 다음 작업은 새 세션에서의 **개발 전 폴더 구조 정리**다. [30 인계](30-새세션-폴더정리-인계.md)를 우선 적용하며, 위 관리 화면 설계는 폴더 정리 후 이어간다. 기존 코드 빌드와 신규 기능의 실제 검증은 구별한다.

## 이전 설계 진행 이력 (2026-10-05)

아래 D0~D11 표는 이전 설계 초안의 작성 이력이다. 최신 상태와 구현 범위는 위 표 및 25~28을 우선 적용한다. 과거 ‘완료’ 표기를 신규 구현 완료로 해석하지 않는다.

> 이 워크트리(`KR-TL-관리-시스템-설계`)는 **설계 단계**를 맡는다. 설계를 아래 단계로 나눠 진행하고, 마지막 단계에서 설계 기준선(베이스라인)을 확정해 구현 단계로 넘긴다.
> 상태 범례: ✅ 완료 · 🟦 초안 있음(보완 필요) · ⬜ 미착수 · ⏸ 미결(논의 후 / 향후 / 구현 중 결정 — [24](24-설계-베이스라인.md) §3)
> **설계 초안 v1.0 완료 (2026-10-05):** 모든 단계의 초안을 작성했다. 미결 항목은 [24 설계 베이스라인](24-설계-베이스라인.md)에서 분류한다.
> 기준일: 2026-10-05
> **1차 설계 검토 반영:** [16 설계 검토](16-설계-보완사항-조치목록.md)의 범위 조정(관리자 인증 · 승인 분리 · 감사 제외, 변경 전후 신뢰 경로 비교 중심)과 단계별 검토 판단을 아래 표에 반영했다.

- 각 단계 완료 시 이 문서의 상태 표를 갱신한다.
