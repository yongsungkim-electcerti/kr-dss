# 01. 아키텍처 설계 브리프 — KR-TL 관리·배포 시스템 분리

|---|---|
| 결정 대상 | KR-TL 관리 시스템과 배포 시스템의 분리 구조, 망 구역, 시스템 간 채널 |
| 결정 책임자 | 사업 PM (KISA 협의 필요) — **미지정** |

## 2. 설계 동인

| 동인 | 출처 | 우선순위 | 근거 상태 |
|---|---|---|---|
| TL 서명키와 관리 데이터는 외부에서 접근할 수 없어야 한다 | 사용자 요구(폐쇄망·HSM) | 1 | 확정 |
| 관리 시스템과 배포 시스템은 **채널 1개만** 공유한다 | 사용자 요구 | 1 | 확정 |
| 외부 배포 채널(DMZ)과 관리자 내부 접근 채널은 서로 달라야 한다 | 사용자 요구 | 1 | 확정 |
| 인증사업자는 **기존 VPN 채널**로 관리 시스템에 연결한다 | 사용자 요구 | 1 | 확정 |
| 배포 시스템은 TL을 가져간 기관·에이전트의 통계를 수집해야 한다 (WEB-WAS 구조) | 사용자 요구 | 2 | 확정 |
| 통계관리 시스템은 폐쇄망 안에 둔다 | 사용자 요구 | 2 | 확정 |
| 인정사업자 인증서 자동 수집·주기적 동기화 | RFP 과업2 | 2 | 확정 |
| EU TL(ETSI TS 119 612)과 호환되는 규격 | RFP 과업2 | 2 | 확정 (`kr-tl-builder`에 XML·JWS 구현 있음) |
| 처리량·이용기관 수·보존기간 등 정량 요구 | — | — | **미확인** (§6) |

이해관계자: KISA(TL 운영 주체), 인정사업자(신뢰정보 제공), 이용기관·브라우저 에이전트·SDK(TL 소비), 보안 심사 담당.

## 3. 품질 시나리오

| ID | 자극 | 경계 | 요구 반응 | 측정·근거 |
|---|---|---|---|---|
| QS-1 무결성 | 공격자가 DMZ 배포 서버를 장악해 TL 파일을 바꿔치기 | 배포 시스템 | 이용기관이 서명 검증에서 위조 TL을 거부. 배포 시스템에는 서명키가 없음 | 배포망에 키 자료 0건, 변조 TL 검증 실패 시험 |
| QS-2 키 기밀성 | 관리 WAS 권한 탈취 | 관리 시스템 | 서명키는 HSM 밖으로 나가지 않음. 서명 요청은 승인 이력이 있어야 실행 | HSM 반출불가 속성, 승인 없는 서명 요청 거부 시험 |
| QS-3 망 경계 | 배포망에서 관리망으로 연결 시도 | 방화벽 | 차단. 연결은 항상 관리망에서 시작 | 방화벽 정책 점검: 배포→관리 허용 규칙 0건 |
| QS-4 배포 가용성 | 관리 시스템 장애·점검 | 배포 시스템 | 마지막으로 반출된 TL을 NextUpdate 시점까지 계속 배포 | 관리망 차단 상태에서 다운로드 정상 시험 |
| QS-5 긴급 반영 | 인정사업자 서비스 정지 결정 | 관리→배포 | 승인 후 **N시간** 안에 배포 시스템에 새 TL 게시 | N 값 **미정** (KISA 협의) |
| QS-6 추적성 | 감사 시점에 TL 변경 경위 요청 | 관리 시스템 | 누가·언제·무엇을 바꾸고 승인·서명했는지 위변조 없이 제시 | 해시체인 감사로그 검증 |
| QS-7 이용 관측 | 운영자가 "어느 기관이 최신 TL을 받았는가" 확인 | 통계관리 시스템 | 기관·에이전트별 최종 수신 버전·시각 조회 | 통계 화면, 집계 지연 시간(미정) |

우선순위 충돌: QS-3(관리망 발신 전용)과 QS-7(통계 신선도)은 서로 당긴다. 통계는 관리망이 주기적으로 가져오므로 실시간이 아니다 → 통계는 **준실시간(주기 집계)** 으로 수용한다.

## 4. 대안 비교

### 4.1 관리·배포 시스템 구조

| 대안 | 적합성 | 비용 | 장애·복구 | 근거 부족 |
|---|---|---|---|---|
| A. 단일 시스템(관리+배포 한 WAS, DMZ 노출) | 낮음 — 서명키·관리 DB가 외부 공격면에 노출 | 낮음 | 하나가 죽으면 둘 다 중단 | — |
| **B. 관리(폐쇄망) / 배포(DMZ+내부존) 분리, 단일 연계 채널** | 높음 — QS-1~4 충족 | 중간 (서버·방화벽 구역 추가) | 배포가 관리와 독립적으로 동작 | 망연계 솔루션 사용 여부 |
| C. B + 오프라인 반출(매체·망연계 장비만) | 매우 높음 — 온라인 경로 없음 | 높음, 긴급 반영(QS-5) 느림 | 통계 회수 경로가 수작업 | — |

→ **B 채택.** C는 QS-5(긴급 반영)와 QS-7(통계) 비용이 지나치게 크다. 단일 채널(CH-4)은 방화벽으로 통제한다(AD-8).

### 4.2 관리↔배포 채널 방향

| 대안 | 내용 | 판단 |
|---|---|---|
| **관리망 발신 전용 (pull/push 모두 관리망이 시작)** | 반출은 관리망이 push, 통계는 관리망이 pull | **채택.** 배포망이 장악돼도 관리망으로 들어오는 세션이 없음 |
| 양방향 세션 | 배포망이 통계를 관리망으로 push | 기각. 배포→관리 인바운드 규칙이 생겨 QS-3 위반 |

### 4.3 통계 수집 방식

| 대안 | 내용 | 판단 |
|---|---|---|
| WEB 접근로그만 수집 | 정적 파일 서빙 + 로그 파싱 | 기각. 기관 식별(API 키·인증서)과 응답 결과(304 등) 의미를 남기기 어려움 |
| WAS 경유 식별 + WEB이 저장소 파일 직접 전송 | WAS가 식별·기록 후 WEB 내부 리다이렉트 | 기각. DMZ WEB이 배포 내부존 저장소를 마운트해야 해서 DMZ→내부 파일 접근 경로가 생김 |
| **WAS가 식별·기록·전송, WEB은 리버스 프록시** | WEB은 TLS 종단·WAF·프록시만, 파일은 WAS가 저장소에서 읽어 응답 | **채택.** DMZ에는 WEB만 두고 데이터는 두지 않음. TL은 수 MB 이하라 WAS 부하가 작음. 대용량 모듈 배포(O-7)를 결정할 때 캐시 방식 재검토 |

## 5. 아키텍처 결정 (AD)

| ID | 결정 | 주요 이유 |
|---|---|---|
| AD-1 | **관리 시스템(폐쇄망)과 배포 시스템(DMZ·배포 내부존)을 물리적으로 분리**한다 | QS-1·2·3 |
| AD-2 | 두 시스템은 **연계 채널 CH-4 하나만** 공유하고, 세션은 **항상 관리망에서 시작**한다 (반출 push, 통계 pull) | QS-3 |
| AD-3 | **TL 서명은 관리망 HSM에서만** 한다. 배포 시스템은 서명된 배포 패키지를 보관·전송만 하며, 패키지 서명을 검증한 뒤 게시한다 | QS-1·2 |
| AD-4 | 배포 시스템은 **WEB(DMZ) – WAS·DB·저장소(배포 내부존)** 구조로 한다. **DMZ에는 WEB만** 두고(WAS·데이터 없음), WEB은 TLS 종단·WAF·리버스 프록시만 한다. 요청 식별·기록·파일 응답은 WAS가 한다 | QS-1·7, 사용자 확정 |
| AD-8 | **CH-4는 방화벽으로 통제**한다. 연계 서버 → 배포 WAS 연계 포트 1개만 허용하고, 배포측에서 시작하는 관리망 접속은 모두 차단한다. 망연계 장비는 쓰지 않는다 | 사용자 확정 |
| AD-5 | 통계는 **2단 구조**: 배포 WAS가 원시 이벤트 수집·1차 집계(단기 보관) → 관리망 **통계관리 시스템**이 주기적으로 회수해 장기 보관·분석 | QS-3·7 |
| AD-6 | **인증사업자 연계는 기존 VPN**으로 관리망의 사업자 연계 서버에 직접 연결한다. DMZ를 거치지 않는다 | 사용자 요구, 공격면 축소 |
| AD-7 | **관리자 접근 채널(CH-2)** 은 외부 배포 채널(CH-1)과 분리한다. 관리자 전용 단말 → 접근통제 게이트웨이(MFA) → 관리 콘솔 | 사용자 요구, QS-2 |

## 6. 경계와 런타임 형태

- **정책 권한**: TL 등재·상태 변경의 최종 권한은 관리 시스템(KISA 승인자)에만 있다. 배포 시스템은 판단하지 않는다.
- **데이터 원천(authority)**
  - 사업자·서비스·인증서·상태 이력, TL 버전, 감사로그 → **관리 DB**(원천)
  - 배포 패키지(서명된 TL·매니페스트·모듈) → 관리망에서 생성, 배포 저장소는 **사본**
  - 접속 원시 이벤트 → **배포 DB**(원천, 단기), 장기 통계 → **통계 DB**(파생)
- **배포 단위**: 관리 WAS, 사업자 연계 서버, 연계 서버(관리측), 통계관리 시스템, 배포 WEB, 배포 WAS. 관리 WAS 안의 기능(사업자 관리·심사·TL 생성)은 한 모듈러 모놀리스로 둔다 — 서비스 분리 근거가 아직 없다.
- **장애 동작**
  - 관리망 장애 → 배포는 마지막 TL로 계속 서비스 (QS-4)
  - 반출 중단·중복 → 패키지는 버전 번호와 해시로 멱등 처리. 같은 버전 재전송은 무시, 낮은 버전은 거부
  - 통계 회수 실패 → 배포 DB가 미회수 구간을 보관, 다음 주기에 이어서 회수(커서 기반)
  - HSM 장애 → 서명 불가, 새 TL 발행 중단. 기존 TL은 계속 배포. 이중화 여부 **미정**

## 7. 결정 사항과 미결 사항

**결정**: AD-1 ~ AD-8

**채택한 비용·위험**
- 서버·망 구역 증가(배포 내부존 추가)에 따른 구축·운영 비용
- 통계가 실시간이 아님 (회수 주기만큼 지연)
- 배포 패키지 서명 검증 로직을 배포 시스템에도 둬야 함

**미결 사항 (확인 필요)**

| # | 항목 | 영향 | 상태 |
|---|---|---|---|
| O-1 | 배포 WAS·DB 위치 | 방화벽 구역 수 | **결정** — DMZ에는 WEB만, WAS·DB·저장소는 배포 내부존 (AD-4) |
| O-2 | CH-4 구현 수단 | 반출 지연, 구축 비용 | **결정** — 방화벽 통제 (AD-8) |
| O-3 | 긴급 반영 목표 시간 N (QS-5), 정기 발행 주기(NextUpdate) | 운영 절차 | 보류 (운영 절차 단계) |
| O-4 | 이용기관 식별 방식: 익명 공개 다운로드 + 선택적 등록(API 키) vs 등록 필수 | 통계 정확도, 이용 편의 | 보류 (API 설계 단계) |
| O-5 | 통계 원시 이벤트 보존기간, IP 등 개인정보 처리(마스킹·해시) | 개인정보 영향 | 미정 |
| O-6 | HSM·관리 DB 이중화, DR 사이트 | 가용성 | 미정 |
| O-7 | 배포 모듈 범위: TL·서명 인증서 외에 SDK·브라우저 에이전트 배포 포함 여부 | 배포 저장소 용량, 패키지 구조 | 보류 |
