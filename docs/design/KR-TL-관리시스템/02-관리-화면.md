# 02. 관리 화면 설계

> 관리 콘솔(IF-03)의 화면 구성. 화면마다 **누가 쓰는가 · 어떤 데이터를 다루는가 · 어떤 시나리오에서 쓰는가**를 적는다.
> 현재 `poc-kisa-tl` 화면(대시보드·사업자 상세·등록 대기·배포 파이프라인·감사 로그)을 출발점으로 삼는다.

## 1. 역할

| 역할 | 하는 일 | 할 수 없는 일 |
|---|---|---|
| **운영자** | 사업자·서비스 정보 입력, 상태 변경 요청, TL 초안 생성 | 자기가 만든 초안 승인 |
| **심사자** | 제출 건·자동 수집 결과 심사(승인·반려) | TL 발행 승인 |
| **승인자** | TL 발행 승인 → 서명 실행 | 신뢰정보 직접 수정 |
| **감사자** | 감사 기록·통계 조회, 감사 기록 무결성 확인 | 모든 변경 |

PoC에서는 로그인 화면에서 역할을 골라 들어가도 된다. 다만 **"생성자 ≠ 승인자" 규칙은 실제로 동작**해야 한다(시나리오 SC-11).

## 2. 화면 목록

| ID | 화면 | 주 사용자 | 다루는 데이터 | 주요 기능 | 관련 시나리오 |
|---|---|---|---|---|---|
| **M-01** | 대시보드 | 전체 | D-02, D-06, D-09 | 현재 TL 버전·다음 발행 예정, 상태별 서비스 수, 심사 대기 건수, **최신 TL 미수신 이용자 수**, 최근 이벤트 | 전체 |
| **M-02** | 사업자·서비스 | 운영자 | D-01~04 | 사업자 목록·상세, 서비스별 상태 이력 타임라인, 서비스 인증서(신·구) | SC-01, 02 |
| **M-03** | 상태 변경 | 운영자 | D-02, D-03 | 정지·철회·복원 요청: **효력 시각**, 사유, 근거 입력 → 긴급 발행 여부 선택 | SC-03~05 |
| **M-04** | 제출·수집 심사 | 심사자 | D-05 | 제출 건·자동 수집 차이 목록, 변경 전/후 비교, 승인·반려(사유) | SC-01, 02, 12 |
| **M-05** | TL 발행 | 운영자·승인자 | D-06, D-07 | 초안 생성 → **직전 버전과 차이** 표시 → 승인 → 서명 → 반출, 진행 단계 표시 | 전체 |
| **M-06** | 배포 현황 | 운영자 | D-07, 배포 결과 | 버전별 배포 이력, 게시 성공·실패, 현재 배포 중 버전 | SC-06, 10 |
| **M-07** | 수신 현황 (통계) | 운영자·감사자 | D-09 | 이용자별 마지막 수신 버전·시각, **최신 버전 미수신 목록**, 클라이언트 유형·버전 분포 | SC-06, 07 |
| **M-08** | 감사 기록 | 감사자 | D-10 | 기간·대상별 조회, **감사 기록 무결성 확인**(해시 연결 검사) | SC-11 |
| **M-09** | 서명 인증서·설정 | 승인자 | D-08 | TL 서명 인증서 현황·만료일, 서명키 교체, 발행 주기 설정 | SC-09 |

## 3. 핵심 화면 개요

### M-03 상태 변경

```
┌ 서비스: ○○인증 CA-2 (현재: granted, 2026-01-01부터) ─────────────────┐
│ 변경할 상태   ( ) suspended 정지  ( ) withdrawn 철회  ( ) granted 복원 │
│ 효력 시각     [2026-11-10 09:00]   ※ 과거 시각 입력 시 경고            │
│ 사유          [키 유출 의심 신고 — 사업자 신고서 #S-0142]            │
│ 발행 방식     (●) 즉시 긴급 발행   ( ) 다음 정기 발행에 포함          │
│                                         [변경 요청] → 심사·승인 단계로 │
└──────────────────────────────────────────────────────────────────────┘
```

- 효력 시각이 상태 이력(D-03)에 그대로 남고 TL에 실린다. 이용자의 "시점별 판단"은 이 값으로 이뤄진다.
- **개념 — 효력 시각 소급**: 효력 시각을 과거로 잡으면 이미 검증을 통과한 서명의 판정이 바뀔 수 있다. 소급을 허용할지, 어디까지 허용할지는 **운영 정책으로 향후 결정**한다. 화면은 소급 여부를 표시하고 사유를 감사 기록에 남길 수 있게만 설계한다.

### M-05 TL 발행

```
[1 초안 생성] ─ [2 차이 확인] ─ [3 승인] ─ [4 서명] ─ [5 반출] ─ [6 게시 확인]

#43 초안 (직전 #42 대비)
  ~ ○○인증 CA-2   granted → suspended (2026-11-10 09:00)
  + △△인증 TSA-1  신규 등재 (granted)
  다음 발행 예정: 2026-11-11 09:00
작성: operator1   승인자: [approver1 ▼]   [승인 및 서명]
```

- 차이가 없으면 "내용 변경 없음, 주기 재발행"으로 표시한다(NextUpdate 갱신 목적).
- 6단계 "게시 확인"은 IF-09로 회수한 배포 결과를 보여 준다.

### M-07 수신 현황

```
현재 배포 버전 #43 (2026-11-10 09:12 게시)
이용자              유형        마지막 수신   시각               상태
A은행 전자계약      SDK 1.2     #43          11-10 09:15        최신
B보험 청약          SDK 1.1     #42          11-10 06:00        ⚠ 미수신
브라우저 에이전트    agent 0.9   #43 (312건)  —                  —
```

- 긴급 발행(SC-03) 뒤 "아직 정지 정보를 반영하지 못한 이용자"를 찾는 화면이다.
- 수신 기록은 회수 주기만큼 늦다(IF-09). 화면에 **마지막 회수 시각**을 함께 보여 준다.

## 4. 화면에서 드러난 기능 세부 사항

| # | 세부 기능 | 근거 | 현재 상태 |
|---|---|---|---|
| F-01 | 상태 변경에 **효력 시각·사유·근거 제출 건**을 함께 저장 | M-03 | 없음 (모델에 이력 없음) |
| F-02 | TL 초안의 **직전 버전 대비 차이** 계산 | M-05 | 없음 |
| F-03 | 발행 단계 상태 관리 (초안·승인·서명·반출·게시) | M-05 | 화면 목업만 |
| F-04 | 생성자 ≠ 승인자 검사 | M-05, SC-11 | 없음 |
| F-05 | 긴급 발행 (정기 주기와 별개로 즉시 발행) | M-03 | `POST /publish` 목업만 |
| F-06 | 이용자별 최종 수신 버전 계산, 미수신 목록 | M-07 | 없음 |
| F-07 | 감사 기록 해시 연결 검사 | M-08 | 화면 목업만 |
| F-08 | 서비스 인증서 복수 보관 (갱신 중 신·구 공존) | M-02, SC-02 | 모델이 1개만 보관 |
