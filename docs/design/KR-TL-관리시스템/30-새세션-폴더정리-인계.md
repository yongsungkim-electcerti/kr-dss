# 새 세션 인계 — 개발 전 폴더 구조 정리

이번 세션은 PoC 상세 설계와 IF-08 Java 참조 샘플을 main에 반영하고 종료한다. **현재 세션에서 새 브랜치를 만들거나 폴더 재배치를 진행하지 않는다.** 다음 작업은 새 세션에서 시작한다.

## 이번에 정리한 내용

- 25: 기존 구현 차이 16건, 사용자 PoC 범위 결정.
- 26: EU 기준 이력·버전 모델. 관리 화면은 순번·시각 오류 발행을 허용하고 검증 모듈에서 거부.
- 27: 가상 KISA 두 체계와 사업자 4곳의 키·인증서 폴더. 실제 키 생성과 체인 README 작성은 후속 개발.
- 28: IF-07 GET XML·해시, ETag/304, PDF 뷰어·이용기관의 수신 검증 계약.
- 29: IF-08 Java 6단계 흐름 샘플. 암호·신뢰 정책 인터페이스만 제공, 실제 모듈 미연결.

인증·감사는 제외하고 접수·심사·보완·반려는 메뉴만 제공한다. HSM은 키 파일로 대체한다. 최신 IF는 01~08이며 Spring Boot WAS만 구현한다. PoC 시나리오·표본·시계는 향후 결정한다.

## 정리 원칙

1. 설계·참조·소스·결과를 분리하고 최신 유효 자료만 현재 관리 대상으로 유지한다. 번호별 초안·중복본은 내용을 비교해 통합한다. 이름이 비슷하다는 이유로 삭제하지 않는다.
2. 백업은 **main 체크아웃 `F:/kr-dss-works/kr-dss/_backup/`에만** 보관한다. 작업 worktree의 임시 백업만 남긴 채 작업을 종료하지 않는다.
3. 백업 manifest에 원래 경로·보관 경로·사유·SHA-256을 기록한다. 복사 및 해시 대조가 끝난 뒤 기존 추적 파일을 정리한다. Git LFS 파일은 실제 원문 보존 여부를 확인한다.
4. `_backup/`, `runtime/`, `results/`는 Git 추적에서 제외한다. 이미 추적된 자료는 ignore 추가만으로 빠지지 않으므로 백업 확인 후 추적 해제를 함께 처리한다. 과거 Git 이력을 재작성하지 않는다.
5. 제품 소스는 src 아래로 옮기되 Gradle 논리 모듈 이름은 유지하는 안이다. settings의 projectDir 매핑, includeBuild, 스크립트·CI·문서 경로를 함께 점검한다. 다른 PoC 모듈도 임의 폐기하지 않는다.
6. Java 참조 샘플은 docs에서 examples로 이동하고 설명서는 guides 또는 설계 인터페이스 문서에서 연결한다.
7. 기존 output은 최종 산출물·실행 결과·키 자료·중복본으로 분류한다. 27의 예정 pki 경로도 runtime/pki로 정합성을 맞추되 실제 키 생성은 후속 개발로 남긴다.
8. 새 세션에서 실제 이동 대응표를 작성한 뒤 재배치하고 링크·빌드·샘플 실행을 검증한다. 별도 agent worktree와 중복 수정 여부를 먼저 확인한다.

현재 폴더 이동·백업 생성·키 파일 생성은 수행하지 않았다. 이 구조는 사용자에게 제시한 정리안이며, 새 세션에서 실제 파일 목록과 대조해 구체화한다.
