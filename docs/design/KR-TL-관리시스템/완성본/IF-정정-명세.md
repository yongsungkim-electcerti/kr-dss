## 인터페이스 목록

| 구분 | 명칭 | 연결 방향 | 주요 내용 |
|---|---|---|---|
| IF-01 | 신뢰정보 제공 | 인증사업자 → 사업자 연계 서버 | 인증사업자가 사업자·서비스 정보, 서비스 인증서, 상태 변경 정보를 제공한다. 사업자 연계 서버는 이를 접수한다. |
| IF-02 | TL 관리 | 관리 콘솔 → 신뢰정보 관리 서버 | 관리자가 제출 내용을 확인하고 등재 정보와 서비스 상태·이력을 관리한다. |
| IF-03 | 심사 요청 | 사업자 연계 서버 → 신뢰정보 관리 서버 | 접수한 신뢰정보와 확인 결과를 전달하여 심사를 요청한다. 확정된 정보를 TL 발행에 사용한다. |
| IF-04 | 발행 요청 | 신뢰정보 관리 서버 → TL 발행 서버 | 확정된 등재 정보와 상태 이력을 전달하고 TL 발행을 요청한다. |
| IF-05 | TL 서명 | TL 발행 서버 → HSM | TL 서명을 요청한다. HSM은 보관 중인 개인키로 서명하고 서명값을 반환한다. |
| IF-06 | TL 배포 | 배포 서비스(WAS) → 배포 서비스(WEB) | 발행 서버에서 전달받은 서명된 TL을 외부에서 조회할 수 있도록 제공한다. 그림의 IF-06 표시는 WAS와 WEB 사이에 있다. |
| IF-07 | TL 조회 | 문서검증 모듈·이용자 시스템 → 배포 서비스(WEB) | 검증에 사용할 TL을 조회하고 내려받는다. 각 검증 주체는 TL의 서명을 확인한 뒤 신뢰 검증에 사용한다. |
| IF-08 | 서명 검증 | 이용자 서비스 → 사용자 브라우저 / 사용자 → 이용자 서비스 | 이용자 서비스가 서명한 내용을 사용자가 브라우저에서 검증하거나, 사용자가 서명한 내용을 이용자 서비스에서 검증한다. |

## 서명 검증

서명 검증(IF-08)은 두 방향의 검증을 포함한다. 한쪽이 보낸 검증 결과를 다른 쪽이 표시하는 기능만을 뜻하지 않는다. 서명된 내용을 받은 주체가 직접 검증한다.

| 구분 | 서명 주체 | 전달 내용 | 검증 주체 | 검증 구성요소 |
|---|---|---|---|---|
| 브라우저 검증 | 이용자 서비스 | 이용자 서비스가 서명한 내용 | 사용자 | 브라우저의 문서검증 모듈 |
| 서비스 검증 | 사용자 | 사용자가 서명한 내용 | 이용자 서비스 | 이용자 시스템의 KR-DSS SDK |

사용자는 그림의 가입자 측 사람을, 이용자 서비스는 그림의 이용자 시스템을 가리킨다. 사용자는 가입자 소프트웨어인 서명 앱으로 서명할 수 있다. 두 검증 주체는 TL 조회(IF-07)로 받은 신뢰정보를 서명 검증(IF-08)에 사용한다. TL 조회는 검증 기준을 받는 연계이며, 서명 검증은 전달받은 서명 내용의 유효성과 신뢰 여부를 확인하는 기능이다.

## 명세 적용 범위

이번 정리는 그림에 표시된 인터페이스의 의미와 방향을 정한다. 요청·응답 메시지 형식, 검증 호출 방식, 상세 오류 코드 등 구현 계약은 별도로 구체화한다. 서명 검증(IF-08)의 개념과 기존 브라우저 PoC의 제한된 구현 범위는 구분해야 한다.

기존 문서의 전면 수정은 다음 세션에서 진행할 검토 사항이다. 특히 이전 명세의 TL 반출(IF-06), 서명 결과 제공(IF-08), 서명 결과 확인 요청(IF-09)을 새 명칭으로 일괄 치환하지 않는다. 실제 연결 구간과 기능이 달라졌는지 먼저 확인한다.
