# 09. 신뢰체계 설명 자료 — 목차

> 자료 분류: 기존 상세 설계·검토 자료. 현재 PoC 구현 범위는 [확정 범위](../../../docs/design/poc/tl-management/scope.md)를 우선한다. 고정 시나리오·HSM·별도 WEB 등은 현재 필수 개발로 간주하지 않는다.

> 문서명(안): **국가 전자서명 신뢰체계와 KR-TL**
> 독자: KISA 전문가
> 상태: **목차와 설명 흐름만 정리**한 단계. 본문은 아직 쓰지 않는다. 각 장의 `메모`에 본문에 넣을 내용을 모아 간다.

## 핵심 메시지 (기준 문안)

국내 전자서명 신뢰체계는 공동인증(KISA RootCA)과 간편인증(사업자별 RootCA)으로 나뉘어 있고, 서로 연결되어 있지 않다. 그래서 이용기관은 체계마다 신뢰를 따로 설정해야 하고, 사업자 상태가 바뀌어도 같은 기준으로 반영할 수 없다.

KR-TL은 KISA가 인정평가제도로 인정한 사업자의 인증서와 서비스 상태를 신뢰목록에 담아 서명·공표하는 방식으로 이 체계들을 하나로 묶는다. 신뢰의 기준점은 KISA TL RootCA다. 이용기관은 이 목록을 기준으로 모든 체계의 전자서명을 같은 방식으로 검증한다.

사업자의 기존 인증 체계는 그대로 두고 그 위에 국가 차원의 신뢰 기반을 더한다. EU 신뢰목록이나 ICAO PKD처럼 국가가 신뢰 기준을 공표하는 구조로, 국내 산업 활성화와 국제 상호연동에 대응한다.

### 5. 신뢰체계가 제공하는 기능

- 설명 의도: KR-TL이 이용기관과 사업자에게 무엇을 해 주는지 기능 단위로 정리한다.
- 기능 목록 (항목만):

| 기능 | 요지 |
|---|---|
| 5.1 통합 신뢰목록 공표 | 분절된 체계의 인증서·서비스를 하나의 목록으로 서명·공표 |
| 5.2 인정 상태 반영 | 인정평가 결과와 서비스 상태(정지·철회·복원)를 목록에 반영 |
| 5.3 시점 기반 판정 | 서비스 상태 이력으로 서명 시점의 유효성 판단 |
| 5.4 신뢰목록 동기화 | 이용기관이 최신 목록을 받아 같은 기준을 유지 |
| 5.5 무결성 보장 | 서명된 목록으로 위조·되돌리기 차단, 배포 경로와 무관한 신뢰 |
| 5.6 기준점 연속성 | 서명키를 교체해도 이용기관의 기준점은 유지 |
| 5.7 국제 연동 기반 | 국제 신뢰목록 형식과 맞춘 구조 |

- 그림: 기능과 신뢰 흐름 단계의 대응

## 작성 원칙

- 핵심만 쓴다. 독자가 전문가이므로 기초 설명과 비유는 넣지 않는다.
- 그림은 기존 도식(01 구성도, 07 인증체계, 08 신뢰 흐름)을 장에 맞게 줄여 쓴다.
- 운영 수치와 정책 값은 넣지 않는다.
- 대상 표기는 "이용기관"으로 통일한다. 브라우저는 PoC의 검증 매체로만 언급한다.
