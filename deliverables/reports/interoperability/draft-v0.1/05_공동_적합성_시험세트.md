# D05 공동 적합성 시험세트

버전: v0.1 · 작성일: 2026-09-27 · 상태: 기관 협의용 초안

본 문서는 KR-AdES·KR-TL·KR-DSS 연구를 위한 설계 제안이다. 실제 기관의 참여·책임 수락, 제품의 구현 지원, 국제 적합성 인증을 의미하지 않는다. ‘한다’는 문구는 초안에서 제안하는 규칙이며 승인 전 운영 의무로 적용하지 않는다.

## 1. 시험 목적·범위·현재 상태

D01의 R01~R12, D03 코드·집계, D04 C01~C09를 기관별 구현에서 같은 의미로 처리하는지 확인한다. 기술 사례 32개(T01~T32)와 운영·문서 검토 6개(J01~J06)를 정의한다. 현재 모든 사례는 NOT_RUN이며 합격·국제 인증 또는 상호인정 결과가 아니다.

이 문서는 실행 가능한 암호 벡터가 완성된 시험 도구가 아니라 공동 시험 명세 초안이다. 함께 제공하는 시험사례.json·CSV는 입력 변형과 기대 결과를 명시한 설계 자료다. 실제 서명·인증서·VC fixture 생성, 러너 연결과 실행은 후속 구현 범위다.

## 2. 시험 환경·기준 fixture

FX-SIG는 P-SIG 정상 서명문서, FX-ATTR는 P-ATTR 정상 지역 속성증명, FX-EMP는 P-EMP 정상 재직증명, FX-REQUEST는 요청 접수 오류 시험 기준이다. 기본 fixture는 승인된 합성 루트·발급자·권한·상태 서버·수신자 및 업무 수용정책을 사용한다. 실제 이용자나 운영 키를 사용하지 않는다.

fixture manifest에는 ID·버전, 생성 도구·버전·명령·난수 시드 처리 방식, 해시, 프로파일·정책·코드 버전, T0, 키·인증서·신뢰목록·상태 증거·권한 자료의 참조, 유효기간과 필요한 보유자 증명을 기록한다. 합성 비밀키는 시험용으로만 분리하고 결과 보고서에 넣지 않는다. 생성 뒤 고정된 fixture 해시로 배포하고 임의 재생성 결과를 같은 버전으로 쓰지 않는다.

T0는 fixture 생성 시 UTC의 고정 값으로 기록하고 모든 시험 시계를 이에 고정한다. 시험 전용 값은 신뢰목록 최대 나이 300초, 상태 증거 최대 나이 120초, 허용 시계 오차 30초다. 최신성 경계는 포함한다. 이 값은 운영 SLA·법적 유효기간이 아니며 O03에서 별도 정한다. 공급자가 선언한 유효기간도 동시에 충족해야 한다.

각 사례는 기본 fixture에서 지정한 한 요소만 바꾼다. 발급자 서명 이전에 바꿔야 하는 입력은 시험 키로 다시 서명하고, 변조 시험만 서명 뒤 바꾼다. 집계 단위시험은 검사 결과를 주입하고, 종단 간 시험은 실제 증거를 사용한다. 두 수준의 성공을 혼동하지 않는다.

## 3. 기대 결과 읽는 방법

정상 기준은 필수 검사 PASS이며 P-SIG의 holderBinding만 NOT_APPLICABLE이다. 아래 ‘검사 변경’ 외에는 기준을 유지한다. T22는 독립적인 검사 결과를 주입하는 집계 단위시험이며 통합 엔진의 조기 종료와 별도 기록한다. 오류 접수·실행 사례는 완료 checks를 반환하지 않는다.

기술·업무 결과, reasonCodes 집합, 정책·증거 참조를 비교한다. 코드 배열의 순서나 동적 reportId 값을 바이트 단위로 동일하다고 요구하지 않는다. 허용된 시간·식별자 차이를 제외한 의미는 일치해야 한다. 단순 HTTP 200 응답을 통과로 판정하지 않는다.

추가 확인: 정상 유효기간을 초과하지 않은 경계값임을 fixture에 명시.

## 5. 운영·문서·보안 검토

| 사례 | 요구 | 검토 주제 | 기대 증거 |
| --- | --- | --- | --- |
| J01 | R01,R08 | 서비스 목적·처리 근거·제공/위탁 분류 | 기관별 법무·개인정보 책임자의 검토 기록과 DT01~DT05 명세가 있고 빈 필수 항목이 없음 |
| J02 | R08 | 최소수집·로그 노출·보존·파기 | SVC-02가 불필요한 전체 주소를 요구하지 않으며 로그에 원문·토큰·비밀키가 없고 보존·파기 절차의 실행 증거가 있음 |
| J03 | R09,R12 | 사고·대체 경로·이의 처리 | 상태 서버 장애와 오발급 정정을 모의하여 담당·연락·보류 안내·대체 제출·재판정 이력이 남음 |

| J05 | R03,R08,R09 | 악성 입력·외부 접근·격리 | 외부 엔티티·내부망 URL·과대 입력을 제한하고 기관 간 자료가 노출되지 않음; 프로세스가 중단되지 않음 |

J05는 공개 원문·URL을 그대로 실행하거나 실제 내부망을 대상으로 시험하지 않고 격리된 모의 서버·합성 입력을 사용한다. J06의 구현 수, 역할 조합, 부하량·성능 목표는 O06에서 합의한다. 단일 구현의 단위시험만으로 상호운용성을 입증했다고 쓰지 않는다.

## 6. 절차·결과 기록·합격 기준

시험 주관기관이 프로파일·정책·fixture를 동결하고 각 기관이 실행 환경을 기록한다. 정상 사례 → 단일 오류 → 복합·경계값 → 장애·복구 → 공동 비교 순으로 실행한다. 차이가 발생하면 원문·정책·엔진·입력 해시와 최소 재현 자료를 모아 기준 해석 또는 구현 오류를 분류한다.

결과 기록 항목은 caseId, fixtureVersion/hash, 구현·엔진·정책 버전, 실행 시점, 기대/실제 결과, 보고서·증거 참조, PASS/FAIL/BLOCKED/NOT_RUN, 결함 ID·담당·재시험 결과다. 현재 파일에는 기대 결과만 있으며 실제 결과는 비워 둔다.

서비스별 필수 기술 시험과 관련 J 시험을 전부 충족하고 미해결 중대 결함이 없어야 해당 프로파일 통과를 제안할 수 있다. 미지원 프로파일은 제외 범위로 공개하며 다른 프로파일의 합격을 확대 적용하지 않는다. BLOCKED·NOT_RUN은 PASS로 집계하지 않는다. J01·J02의 승인 자료와 J06의 상호구현 증거가 없으면 운영 실증 진입을 승인하지 않는다.
